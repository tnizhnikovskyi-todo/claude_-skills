# ТЗ: Сервисные заявки (Odoo 19)

## 1. Общее

1.1. Компания оказывает сервисное обслуживание оборудования клиентов
(кофемашины, холодильные витрины). Сейчас заявки принимают по телефону и
ведут в Google-таблице. Нужно перенести учёт заявок в Odoo 19.

1.2. Пользователи: операторы колл-центра (4 человека), сервисные инженеры
(12 человек), руководитель сервиса (1), администратор Odoo (1).

1.3. Используемые модули Odoo: Контакты, Продажи, Склад, Обсуждения.
Модуль Field Service не используется и покупаться не будет.

## 2. Заявка

2.1. Новая модель «Сервисная заявка» с полями: номер (автонумерация
SR/ГГГГ/00001), клиент (контакт-компания), адрес объекта (контакт-адрес
клиента), оборудование (серийный номер, свободный текст), описание
проблемы, приоритет (обычный, срочный), ответственный инженер, плановая
дата визита, фактическая дата визита, затраченные запчасти (строки: товар,
количество), комментарий инженера.

2.2. Статусы заявки: «Новая» → «В работе» → «Выполнена». Других статусов
нет. Переход «Новая» → «В работе» при назначении инженера, «В работе» →
«Выполнена» кнопкой инженера после заполнения фактической даты визита.

2.3. Заявку создаёт оператор. Инженер не может создавать заявки.

2.4. Номер заявки не меняется после создания.

## 3. Сроки обработки

3.1. Срок реакции на заявку: 2 рабочих дня с момента создания. Рабочие
дни: пн–пт, по производственному календарю компании.

3.2. Для срочных заявок срок реакции: 4 рабочих часа (рабочее время 9:00–18:00).

3.3. Реакцией считается назначение инженера.

## 4. Права

4.1. Оператор видит все заявки, создаёт и редактирует их до статуса
«Выполнена».

4.2. Инженер видит только заявки, где он ответственный. Редактирует
фактическую дату визита, запчасти и комментарий.

4.3. Руководитель сервиса видит и редактирует всё.

4.4. Удалять заявки не может никто, включая администратора: заявки нужны
для гарантийных споров в течение 3 лет.

## 5. Запчасти

5.1. При переводе заявки в «Выполнена» по строкам запчастей создаётся
расход со склада «Сервисный» (перемещение в локацию списания).

5.2. Если запчастей на складе недостаточно, перевод в «Выполнена» не
блокируется, но руководитель получает уведомление.

## 6. Уведомления

6.1. Инженер получает уведомление в Обсуждениях при назначении на заявку.

6.2. Руководитель получает уведомление, если заявка не обработана в течение
48 часов с момента создания.

6.3. Клиент получает email при переводе заявки в «Выполнена» с перечнем
выполненных работ и запчастей.

## 7. Отчёты

7.1. Pivot-отчёт по заявкам: количество по инженерам, клиентам, месяцам.

7.2. Отчёт по просроченным заявкам (нарушен срок реакции из п. 3).

7.3. Отчёт по отклонённым заявкам с причиной отклонения, по месяцам.

7.4. Расход запчастей по клиентам за период.

## 8. Печатные формы

8.1. Акт выполненных работ (PDF) из заявки: реквизиты клиента, адрес
объекта, оборудование, работы, запчасти, подписи сторон.

## 9. Архив

9.1. Заявки в статусе «Выполнена» старше 1 года автоматически
архивируются (скрываются из списков, доступны через фильтр «Архив»).

9.2. Раз в год администратор удаляет архивные заявки старше 2 лет, чтобы
не раздувать базу.

## 10. Миграция

10.1. Перенос открытых заявок из Google-таблицы (около 150 строк) разовым
импортом CSV. Закрытые заявки не переносятся.

## 11. Обучение

11.1. Инструкция для операторов и инженеров (PDF, до 10 страниц) и одна
онлайн-сессия обучения на 2 часа.
