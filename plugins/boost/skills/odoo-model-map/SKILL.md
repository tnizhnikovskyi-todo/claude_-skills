# odoo-model-map

В Odoo связи живут в строках и XML, а не в Python-классах. Имя класса
произвольное (`class MileageKpi(models.Model): _inherit = ['td.vehicle']`),
поэтому поиск по `class` или по имени класса пропускает почти всё. Модель
это строка `'td.vehicle'`; ищи строку.

## 1. Область

- Найди все модули: Glob `**/__manifest__.py`. Прочитай манифесты целиком
  (они короткие): `depends` и `data`. Это границы скана.
- Запиши, что в область НЕ входит: ядро Odoo и enterprise, другие
  репозитории, данные в БД. Они пойдут в блок «Где не искал».

## 2. Карта до чтения методов

Сначала собери оглавление, потом читай конкретный код.

**Если есть Bash и python3** — запусти скрипт из папки этого скилла
(только stdlib, анализируемый код не импортирует и не исполняет):

```bash
python3 -I <папка скилла>/scripts/odoo_map.py <каталог аддонов> [--model X] [--field Y]
```

Он печатает модули, модели с ролью (определяет / расширяет / делегирует
через `_inherits` / миксин), поля-связи, `@api.depends`, `env['…']`, вью и
дерево их наследования, права, модели без строк доступа, `ir.rule`, пути
через модель из других моделей и (с `--field`) все упоминания поля.
Вывод скрипта — заготовка: перепроверь спорные строки Read'ом.

**Если Bash нет** — рецепты Grep из `references/grep-recipes.md`. Минимум
для вопроса о модели X:

1. Строка модели в кавычках по `*.py` и `*.xml`: `['"]X['"]` (точки
   экранируй). Это ловит `_name`, `_inherit` (строка и список), `_inherits`,
   comodel позиционно и `comodel_name=`, `env['X']`, `res_model`,
   `<field name="model">X</field>`, `<record model="X">`.
2. xml-id модели в правах и правилах: `model_X_с_подчёркиваниями`.
3. Для каждого вью X: кто на него ссылается через `inherit_id` (рекурсивно,
   наследник наследника тоже наследник).
4. Поля-связи на X (из п.1) → пути через них: `<поле>\.` в `related=`,
   `@api.depends`, доменах `ir.rule` и вью.
5. Вопрос о поле Y: `\bY\b` по `*.py`, `*.xml`, `*.csv`, `*.js`; затем
   разбери каждое попадание (см. п.3 ниже).

Покажи карту пользователю до ответа на вопрос:

```
Модули: td_fleet → td_fleet_service → td_fleet_report
| модель | роль | модуль | класс | файл:строка |
Вью: дерево inherit_id
Права / ir.rule: таблица
```

## 3. Ответ на вопрос

- **«Кто наследует X»** — три разные вещи, не смешивай: расширяют
  (`_inherit = 'X'` без нового `_name`), делегируют (`_inherits =
  {'X': 'x_id'}`: поля X видны в новой модели, в её вью и доменах),
  ссылаются (Many2one/One2many/Many2many на X, `env['X']`). Миксины
  (`_inherit = ['mail.thread']` у X) — отдельная строка.
- **«Где вью X»** — все `ir.ui.view` с `<field name="model">X</field>` плюс
  цепочка `inherit_id` до конца, плюс вью моделей с `_inherits` на X, где
  видны поля X. Укажи `действия` (`res_model`).
- **«Что сломается, если поменять поле Y»** — для каждого попадания реши:
  это Y модели X или одноимённое поле другой модели / часть другого слова
  (`odometer_at`, `td.odometer.export`)? Перечисли по категориям:
  определение; `@api.depends`/`constrains`/`onchange`; `related=`; домены
  (вью, `ir.rule`, `search()`, фильтры); `read`/`write`/словари;
  XML-вью и `xpath` в наследниках (сломанный `xpath` роняет установку
  модуля); вью `_inherits`-моделей; хранимые `related`/`compute` в других
  моделях (миграция данных).
- **«Какие права»** — строки `ir.model.access.csv` по группам (rwcd),
  `ir.rule` (глобальные пересекаются по AND, групповые объединяются по OR),
  модели без строк доступа (в Odoo 19 нужны и для `TransientModel`), для
  `_inherits` — права и правила родительской модели тоже действуют.
- Читай методы только после карты и только те, что нужны для ответа.

## 4. Не нашёл ≠ нет

Grep видит только то, что ты искал и где искал. Ответ «никто не наследует»,
«больше нигде не используется», «ничего не сломается» без оговорки —
ошибка. Всегда заканчивай блоком:

```
Где не искал: ядро Odoo 19 и enterprise (модели `res.partner`, `mail.thread`…),
другие репозитории/addons_path, данные БД (ir.filters, серверные действия,
автоматизации, Studio), JS/OWL и QWeb-отчёты (если не грепал), динамические
имена (env[var], getattr).
```

Если вопрос требует ядра (например, «кто ещё наследует `res.partner`»),
скажи, что нужно сканировать исходники Odoo 19 (`odoo/addons`, `addons`),
и не выдумывай список.
