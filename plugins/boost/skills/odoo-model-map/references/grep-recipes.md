# Grep-рецепты для карты Odoo

Шаблоны для инструмента Grep (ripgrep) или `rg` в Bash. Точку в имени
модели экранируй: `td\.vehicle`. Lookbehind не используй (в rg он только
с `-P`). Если попаданий много, сначала `output_mode: files_with_matches`
или `count`, потом `content` по нужным файлам.

## Модули

| Что | Как |
|---|---|
| Все модули | Glob `**/__manifest__.py` |
| Зависимости, файлы данных | Read манифеста (`depends`, `data`) |
| Кто зависит от модуля M | Grep `['"]M['"]` в `**/__manifest__.py` |

Порядок загрузки = порядок `depends`. Файл не из `data` не загружается
(вью или права «есть в репо», но не работают).

## Модели и наследование

| Что | Шаблон (glob) |
|---|---|
| Все определения | `_name\s*=\s*['"]` (`*.py`) |
| Всё о модели X одной строкой | `['"]X['"]` (`*.{py,xml}`) |
| Расширения X в одну строку | `_inherit\s*=.*['"]X['"]` (`*.py`) |
| Расширения X списком на несколько строк | `_inherit\s*=\s*\[[^\]]*['"]X['"]` + `multiline: true` |
| Делегирование | `_inherits\s*=` (`*.py`), затем Read словаря |
| Новая модель по прототипу X | `_name` ≠ `_inherit` в одном классе: копия полей, отдельная таблица |
| Абстрактные/миксины | `models\.AbstractModel` |
| Мастера | `models\.TransientModel` |

Классификация попаданий `['"]X['"]` в `*.py`:

- `_name = 'X'` — определение (один модуль).
- `_inherit = 'X'` / `['X', …]` без `_name` или с `_name = 'X'` —
  расширение той же модели.
- `_inherits = {'X': 'x_id'}` — делегирование: поля X доступны как свои.
- `fields.Many2one('X'`, `comodel_name='X'`, One2many/Many2many —
  ссылка.
- `env['X']`, `env["X"]` — использование в коде.
- `_name = 'Y'` + `_inherit = 'X'` — новая модель Y по прототипу X.

## Поля, related, depends

| Что | Шаблон |
|---|---|
| Поля-связи на X | `fields\.(Many2one|One2many|Many2many)\(\s*['"]X['"]` и `comodel_name\s*=\s*['"]X['"]` (`multiline: true`) |
| related через поле F (связь на X) | `related\s*=\s*['"][\w.]*\bF\.` |
| depends через F | `@api\.depends\(.*\bF\.` (и Read, если аргументы на нескольких строках) |
| Все упоминания поля Y | `\bY\b` (`*.{py,xml,csv,js}`) |

`\b` считает `_` частью слова: `\bodometer\b` не поймает `odometer_at`,
но поймает `td.odometer.export` и тексты — разбери вручную.

Где ещё живёт поле Y, кроме определения: `@api.depends`, `constrains`,
`onchange`, `related='….Y'`, домены (`[('Y', …)]` в Python, вью, `ir.rule`,
действиях), `read([...'Y'])`, `write({'Y': …})`, `mapped('Y')`,
`sorted(key=…)`, `_order`, `_rec_name`, `group_by` в context, XML
`<field name="Y">`, `xpath expr="//field[@name='Y']"`, `<field name="Y"
position=…>`, отчёты QWeb (`t-field="o.Y"`), JS.

## Вью и их наследование

| Что | Шаблон (`*.xml`) |
|---|---|
| Вью модели X | `<field name="model">X</field>` |
| Наследники вью V | `inherit_id"\s+ref="([\w]+\.)?V"` |
| QWeb-шаблоны-наследники | `<template[^>]*inherit_id=` |
| Действия на X | `<field name="res_model">X</field>` |
| Записи данных X | `<record[^>]*model="X"` |
| Кто ссылается на xml-id | `ref="([\w]+\.)?XMLID"` и `ref\(['"]([\w]+\.)?XMLID` |

Наследование вью рекурсивно: найдя наследника V1, ищи наследников V1.
Вне своего модуля xml-id пишется с префиксом `module.`; внутри модуля
может быть без него — ищи оба варианта (шаблон выше).

## Права и правила

| Что | Шаблон |
|---|---|
| Строки доступа на X | `model_X_с_подчёркиваниями\b` в `**/ir.model.access.csv` |
| Правила на X | `ref="([\w]+\.)?model_X_с_подчёркиваниями"` (`*.xml`) рядом с `model="ir.rule"` |
| Все правила | `model="ir.rule"` |
| Группы | `model="res.groups"`, `groups="` у вью/полей/меню |

Модели без строк доступа: список `_name` (кроме `AbstractModel`) минус
`model_…` из csv. `TransientModel` в Odoo 19 тоже нужны права.

`ir.rule` без `groups` — глобальное, глобальные пересекаются (AND).
Групповые правила одной модели объединяются (OR) для пользователя с
несколькими группами. Домены правил с путём (`vehicle_id.company_id`)
зависят от полей другой модели.

## Где этого не видно

- Ядро Odoo/enterprise и другие репозитории (не в области скана).
- Данные в БД: `ir.filters`, серверные действия, автоматизации, Studio,
  шаблоны писем, экспорт/импорт (имена полей строкой).
- Динамика: `env[model_name]`, `getattr(rec, name)`, `fields_get`.
