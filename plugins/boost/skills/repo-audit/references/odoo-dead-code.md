# Odoo: что выглядит мёртвым, но живое

Читать перед любой lean-находкой «удалить» в модуле Odoo. Пересказ идеи
`dead-code-methodology.md` из focuz-ai/odoo-spec-kit (MIT), источник —
`attribution.md`.

## Где Odoo вызывает код без импорта и без вызова по имени

Прежде чем назвать метод, поле, файл или модель неиспользуемыми, проверь
каждый пункт и назови, что проверил:

| Что | Где искать ссылку |
|---|---|
| Метод модели | `<button name="метод" type="object">` и `name="action_…"` в XML; `code` в `ir.cron`, `ir.actions.server`, `base.automation`; `_compute=`/`_inverse=`/`_search=`/`_constraints`; `@api.onchange`/`@api.constrains` |
| Метод с префиксом `_` | вызовы из родителя через `super()` в другом аддоне (это переопределение хука ORM: `_compute_display_name`, `_get_report_values`, `_prepare_invoice`…) |
| Python-файл | `__init__.py` пакета и подпакетов (не импортирован = действительно мёртв) |
| XML/CSV-файл | `__manifest__.py`: `data`, `demo`, `assets` — грузится без импорта |
| XML ID | `ref="…"`, `%(xml_id)d` в кнопках, `env.ref('…')`, меню, права, отчёты, шаблоны писем |
| Модель | `_inherit`/`_inherits` в этом и в других аддонах репозитория; `self.env['имя.модели']`; `comodel_name` у полей; `res_model` в action |
| Поле | виды (`field name=`), `related=`, `depends`, домены, отчёты QWeb, шаблоны писем, экспорт/импорт, `search_read` из JS или внешнего RPC |
| Функция-хук | `pre_init_hook`/`post_init_hook`/`uninstall_hook` в манифесте; `migrations/<версия>/pre-*.py`/`post-*.py` (вызываются по имени файла) |
| JS/OWL | `registry.category(…).add(…)`, `t-name` шаблона, `assets` манифеста |
| Только тесты/демо | используется в `tests/` или `demo/` — не мёртв, но может быть лишним: решает пользователь |

## Классы находки

- **Мёртв:** нет ни статических, ни динамических ссылок по таблице выше,
  и ты назвал, где искал. Можно предлагать удаление.
- **Подозрителен:** ссылок не нашёл, но есть путь, которого grep не видит
  (внешний RPC, другой репозиторий, данные в базе: `ir.actions.server`,
  `base.automation`, вид, созданный через интерфейс). Удаление не
  предлагать; фикс — «проверить на копии базы: `ir.model.fields`,
  `ir.ui.view`, `ir.actions.server`», группа «Можно потом».
- **Живой (ложное срабатывание):** нашлась ссылка — не находка.

## Поле «не существует»

Поле, которого нет в теле класса, может прийти через `_inherit` (в т.ч.
списком), `_inherits`, миксин (`mail.thread`, `mail.activity.mixin`,
`portal.mixin`, `utm.mixin`) или аддон из `depends`. Grep по классу этого
не покажет. Находку «поле не определено» пиши только с цитатой: где искал
(все родители из `_inherit`, аддоны из `depends`), и `файл:строка`
определения, если нашёл. Не можешь процитировать — «Подозрителен».
