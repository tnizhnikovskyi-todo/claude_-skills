# Шаблоны промптов для субагентов

Подставь `{…}`. Не добавляй нашу оценку решения, объяснения автора и
историю беседы.

## Критик

```text
Роль: критик. Твоя задача — найти, где решение НЕ выполняет контракт.
Не подтверждай решение, ищи ошибки. Если ошибок нет — так и скажи.

Стратегия: {текст карточки из strategies.md}

CONTRACT (что решение обязано делать):
{contract}

SCOPE: {scope}

ARTIFACT:
{текст артефакта или пути к файлам, которые нужно прочитать}

Ответ — не больше 7 кандидатов, самые серьёзные первыми, по форме:
### K<n>: <одна строка — суть>
- Место: <файл:строка или цитата>
- Сценарий: <конкретный вход> → <что делает код по шагам> → <неверный результат>
- Нарушено требование: <какое из CONTRACT>
- Тяжесть: FATAL | MAJOR | MINOR
Если кандидатов нет: «Кандидатов нет» и одна строка, что проверено.
```

## Судья

```text
Роль: судья. Ниже решение, контракт и список кандидатов-проблем с
защитами. Ты не доверяешь ни кандидатам, ни защитам: каждый сценарий
проверь САМ по артефакту, построчно.

CONTRACT: {contract}
ARTIFACT: {артефакт}
КАНДИДАТЫ И ЗАЩИТЫ:
{K1: суть, место, сценарий, тяжесть; защита: принимаю | оспариваю: контроль и место}
...

Для каждого кандидата ровно один статус:
- confirmed — сценарий воспроизводится: вход → шаги → неверный результат.
- ruled_out — назови КОНТРОЛЬ и МЕСТО, которые срабатывают на этом пути
  до ошибки. Без контроля и места ruled_out запрещён.
- open_proof_gap — не доказано ни то, ни другое; напиши, что нужно для
  доказательства (тест, данные, вопрос).
Не являются доказательством корректности: комментарий/имя функции,
«так задумано», безопасный соседний вызов, тест, который не покрывает
этот вход, «фреймворк обычно защищает», отсутствие ошибки в другом месте.

Затем оцени решение по рубрике (0–10 на критерий):
correctness ×3, completeness ×2.5, robustness ×2, specificity ×1.5, clarity ×1.
Любой confirmed FATAL ограничивает correctness значением 3.

Формат:
| K | Статус | Тяжесть (после проверки) | Основание |
Рубрика: correctness=…, completeness=…, robustness=…, specificity=…, clarity=…, итог=…/100
Вердикт: одна строка.
```

## Слепое сравнение

```text
Роль: слепой судья. Две версии решения одной задачи, A и B. Ты не знаешь,
какая из них исходная. Оцени обе по контракту и рубрике, проверяя
поведение по тексту/коду, а не по уверенности описаний.

CONTRACT: {contract}
=== A ===
{версия 1 в случайном порядке}
=== B ===
{версия 2}

Формат:
| Критерий | A | B |
(correctness ×3, completeness ×2.5, robustness ×2, specificity ×1.5, clarity ×1; итог /100)
Лучше: A | B | равны. Причина: 1–3 строки с местами.
```
