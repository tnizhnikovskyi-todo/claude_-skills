## Что делает

Тонкая обвязка (311 строк, из них 111 — README): регистрирует официальный
языковой сервер Odoo `odoo_ls_server` (Rust) как LSP-сервер Claude Code для
`.py`, `.xml`, `.csv` и даёт скилл `odoo-ls`, который говорит Claude брать
LSP-инструмент вместо grep: `goToDefinition` (в т.ч. в ядро Odoo), `hover`
(модель, кто наследует, сигнатура + docstring; в т.ч. на строке
`_inherit = "..."`), `documentSymbol`, `workspaceSymbol`; диагностики
`OLS0xxxx` приходят сами после правок. Вся «Odoo-логика» — в `odoo-ls`,
плагин её не добавляет.

Главная причина, ради которой плагин был сделан, — **уже не нужна**: в
`odoo-ls` до 1.6.0 сервер падал (`panic`, код 101), когда Claude Code
отказывал в `client/registerCapability`. Автор плагина отправил исправление
в апстрим, и оно вошло в **`odoo-ls` 1.6.1** (коммиты `df40068`, `e142515`;
changelog 1.6.1: «The server now accepts clients that do not use dynamic
registration, such as Claude Code»). Плагин же до сих пор собирает форк на
базе 1.6.0 и пишет, что `findReferences` ничего не возвращает — а в 1.6.1
GoToReference как раз чинили и ускоряли.

## Какую слабость Claude закрывает

1. **Факты версии Odoo из исходников, а не из памяти.** Диагностики
   `odoo-ls` проверяют код против реального `odoo_path`: поле нет в модели
   (`OLS03014`), поле в XML-вью/данных (`OLS05057`), поле в домене
   (`OLS03011`), неизвестная модель/xml-id/шаблон (`OLS03002`, `OLS05001`,
   `OLS05055`, `OLS05073`), модель или xml-id не из `depends`
   (`OLS03001`, `OLS03003`, `OLS03004`, `OLS03028`), inverse/comodel/related
   (`OLS03015`–`OLS03023`), компьют-метод (`OLS03019`). Это ровно класс
   ошибок из `synthesis.md` п. 3 (`partner_id.mobile` в 19.0), **но только
   если на диске исходники Odoo 19.0** и Python с её зависимостями.
2. **Строковые связи Odoo** (`_inherit`, xml-id, XML-вью), на которых
   споткнулись serena и graphify: `odoo-ls` понимает их как Odoo.

Чего не закрывает: синтаксические ловушки версии (`<tree>`→`<list>`,
`attrs=`, `type='json'`, `_sql_constraints`, `numbercall`…). Из 143 кодов
депрекаций всего 3 (`OLS03301`–`OLS03303`), ни одной про 17–19. Это
остаётся задачей линтера T2.

## Как устроен

| Файл | Что делает |
|---|---|
| `.claude-plugin/plugin.json` | манифест `odoo-lsp` 0.1.0, MIT |
| `.lsp.json` | сервер `odoo` → `${CLAUDE_PLUGIN_ROOT}/bin/odoo-ls --log-level info`, расширения `.py/.xml/.csv`, профиль `default`, `startupTimeout` 120 с |
| `bin/odoo-ls` | bash-обёртка: ищет `$ODOO_LS_SERVER` или `$ODOO_LS_HOME/server/target/release/odoo_ls_server` (по умолчанию `~/.local/share/odoo-ls`), раскрывает симлинк, `exec` |
| `scripts/install-odoo-ls.sh` | `git clone --branch claude-code-compat` форка `villelaitila/odoo-ls` (или `git pull --ff-only`), сабмодули, `cargo build --release`, симлинки `typeshed/`, `additional_stubs/` |
| `templates/odools.toml` | пример конфига: `odoo_path`, `python_path`, `addons_paths`, фильтр диагностик только по своему проекту |
| `skills/odoo-ls/SKILL.md` | 61 строка (~0.6k токенов): таблица «вопрос → LSP-операция», «диагностики — реальные сигналы», ограничения, troubleshooting |

**Что ставится на машину:** Rust-тулчейн (≥ 1.94), клон форка с
сабмодулями (typeshed), сборка release со всеми зависимостями Cargo (в т.ч.
git-зависимости `ruff`, `oxc`, `rust-analyzer` по тегам), бинарник и логи в
`~/.local/share/odoo-ls`. Плюс то, что нужно самому `odoo-ls`: исходники
Odoo нужной версии и venv с `requirements.txt` Odoo.

**Права, сеть, телеметрия.** Хуков нет, MCP нет, `permissions` не просит.
Сеть — только при установке (`git clone`, `cargo` тянет крейты). В
`Cargo.toml` `odoo-ls` 1.6.1 сетевых крейтов нет (ни `reqwest`, ни `hyper`,
ни `sentry`); `Command::new` в сервере: запуск `python_path -c` (печать
`sys.path` и версии), `--version` у инструментов, опционально `tsserver`
для JS. Телеметрии не нашли (grep по `server/src`, 2.3 МБ Rust целиком не
читали).

**Активность:** плагин — 1 коммит (2026-09-28), с тех пор не обновлялся и
отстал от апстрима. В маркетплейсе `softagram/claude-plugins-marketplace`
(`7ae49f2`, 2026-10-30) записи `odoo-lsp` **нет** — команда установки из
README не сработает. `odoo-ls` — официальный проект Odoo S.A., очень
активен (master 2026-10-30, релизы раз в 1–2 месяца).

**Версии Odoo:** в коде сервера ветвления по версиям от 15.0 до 20.0
(включая saas 18.1, 19.3, 19.4; например оператор домена `access` с 19.3 —
`OLS03025`). Минимальная поддерживаемая версия в документации не найдена —
**UNVERIFIED**; по коду 15.0+, Odoo 19 поддерживается.

## Облачная сессия

Практически нет. Нужно на каждом эфемерном старте (или через
setup-скрипт окружения): собрать Rust-сервер (минуты, сеть к crates.io и
GitHub), склонировать Odoo 19.0 (гигабайты, лимит диска сессии),
поставить venv с зависимостями Odoo (системные библиотеки для `psycopg2`,
`python-ldap`…). И главное — в этой облачной сессии LSP-инструмента
среди инструментов нет; появится ли он при включённом LSP-плагине, не
проверяли (запуск запрещён заданием). Rust 1.97 в контейнере есть, так что
**пакетный режим** `odoo_ls_server --parse -t <проект> -o out.json`
(`server/src/args.rs`, `cli_backend.rs`: пишет все `diagnostic`-события в
JSON) в облаке технически возможен без LSP-инструмента — это и есть
единственная интересная для нас идея.

Итог сравнения: по сути то же, что odoo-lens (LSP «как Odoo» с исходниками
на диске), но **сервер официальный, лицензия ясная**, а Odoo-логики у самого
плагина ноль. Дублирует навигацию `odoo-model-map` там, где есть исходники;
сверх нашего — проверка полей/моделей против реальной версии. Хуже нашего
— в облаке и без исходников. По `synthesis.md` п. 8 навигация по связям у
базовой модели уже на потолке (28.5/29 без MCP), так что LSP ради
навигации не окупится; ценна только **диагностика версии** как барьер.

## Риски и заметки

- **Конфликт с `pyright-lsp`** и другими LSP на `.py` (как у odoo-lens) —
  плагин об этом не пишет.
- Диагностики приходят после каждой правки автоматически: без
  `diagnostic_filters` из шаблона Claude получит шум из ядра Odoo и venv.
- Скилл велит «использовать LSP вместо grep» — при недоиндексированном
  сервере ответ «ничего не найдено» легко принять за отсутствие (№28).
- Детали проверки — `notes.md`.
