# odoo-lsp-claude: сводка для главной сессии

- **Что это:** `softagram/odoo-lsp-claude-code@721fc31` (MIT, сверено по
  `LICENSE`; 1 коммит, 2026-09-28) — тонкая обёртка: `.lsp.json` +
  bash-лаунчер + скрипт сборки + скилл (~0.6k токенов) вокруг официального
  `odoo-ls` (Rust, LGPL-3.0, Odoo S.A.). Своей Odoo-логики нет.
- **Устарел:** собирает форк ради фикса падения на Claude Code, но фикс
  автора уже в `odoo-ls` **1.6.1** (2026-10-19, changelog упоминает Claude
  Code). Записи в маркетплейсе softagram нет — установка из README не
  сработает.
- **Что даёт odoo-ls:** переход к определению в ядро, hover по `_inherit`,
  символы; 143 диагностики против реальных исходников Odoo: поле/модель/
  xml-id нет в версии, не из `depends`, inverse/comodel/related. Синтаксис
  17–19 (`<tree>`, `attrs`, `_sql_constraints`) НЕ ловит — 3 депрекации.
  Версии по коду 15.0–20.0 (минимум UNVERIFIED).
- **Облако — нет:** Rust-сборка, клон Odoo 19.0, venv с зависимостями Odoo,
  LSP-инструмента в сессии нет. Сеть только при установке, телеметрии нет.
- **Сравнение:** то же, что odoo-lens, но сервер официальный и лицензия ясная;
  навигация дублирует `odoo-model-map` и по пилоту не нужна (28.5/29 без
  инструментов); сверх нашего — только проверка полей против версии.
- **Оценка 9/18. Вердикт: отклонить плагин, взять идею:** пакетный
  `odoo_ls_server --parse` (JSON диагностик) как опциональный второй слой к
  T2 `odoo19-lint` — ловит «поле удалено в 19» без списка правил, если есть
  исходники 19.0. Сначала A/B с разрешением (открытые вопросы в `notes.md`).
- Для локальных машин, если попросят: свой `.lsp.json` (MIT, с атрибуцией)
  на официальный `odoo-ls` ≥ 1.6.1 без форка.
