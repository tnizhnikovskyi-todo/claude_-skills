## Что делает

Переносит кастомный модуль Odoo 14–19 на 20.0 в отдельное дерево, пофазно с
коммитами. Фазы: манифест → безопасный прогон официального `upgrade_code` →
сканер на 123 правила, с настоящими импортами `odoo.*` и JS под 20 →
ручные правки по областям (до 4 параллельных субагентов) → цикл «установка на
одноразовой базе `mig20_*` → смоук в headless Chrome → flow tour» до
`RESULT: CLEAN` → ревью → отчёт `MIGRATION_20.md` с разделом «Not migrated» и
доказательством, что исходник и ядро не тронуты.

## Какую слабость Claude закрывает

Ту самую, что у нас главная (`synthesis.md`, п. 3): модель пишет API прошлых
версий. Скилл запрещает писать API, xml-id, xpath и виджеты по памяти: всё
сверяется grep'ом по исходникам 20. «Готово» здесь значит, что модуль установился и
прошёл браузерный смоук, а не что код компилируется. Отдельно ловит **тихие**
поломки: `_sql_constraints` игнорируется, `t-esc` ничего не выводит, `name_get` не
вызывается, override со старой сигнатурой. И главное правило: «никогда не
комментировать код ради установки».

**Права и сеть.** Скрипты в сеть не ходят, телеметрии нет. `install_test.sh`
исполняет код модуля через `odoo-bin` (так задумано), `scan.py` импортирует
модули ядра и сторонние библиотеки, `xpath_check.py:30` делает `eval()`
манифеста. `install.sh` пишет в домашние каталоги 7 агентов и в проект
(`AGENTS.md`, `.cursor/`, `.github/prompts/`…). Хуков и MCP нет.
**Дефект:** `install_test.sh --db NAME` удаляет базу с любым переданным
именем; ограничение `mig20_*` прописано только в тексте. Подробно в `notes.md`.

**Требования:** локальный checkout Odoo 20, Python ≥ 3.12, PostgreSQL ≥ 16,
Chrome. В нашей облачной сессии ничего из этого нет.

## Проверка

Скрипты не запускали: в облаке нет Odoo 20, PostgreSQL и Chrome, а на чужой код
нужно разрешение. Проверили сами факты: 62 утверждения из таблиц сверены с
исходниками `odoo/odoo`, с `файл:строка` по каждому в `notes.md`.

| Что проверяли | Результат |
|---|---|
| Факты «что изменилось» (62, с упором на 18→19 и 19→20) | **0 неверных**, 49 полностью верны |
| Столбец «с какой версии» | **13 ошибок**: 12 раз «20», хотя изменилось в 19 или раньше, и 1 раз «18» вместо «19» |
| Требования Odoo 20 (Py 3.12+, PG 16+) | верно (`20.0:odoo/release.py:39–41`) |
| `ir.access` вместо `ir.model.access`/`ir.rule` в 20 | верно (`20.0:odoo/addons/base/models/ir_access.py:64`) |
| A/B «с ним / без него» | не делали (нужна Odoo 20 + разрешение) |

Для сравнения: mart337i — 9 ошибок из 19, dooservice — 0 из ~20 (`catalog/INDEX.md`).
Это лучший из разобранных справочников по 20.0. Типичный дефект — версия,
а не сам факт.

## Риски и заметки

- В облаке не работает: нужна локальная Odoo 20 + PG 16 + Chrome.
- `--db NAME` + `dropdb` — потенциальная потеря рабочей базы; перед любым
  локальным использованием нужна правка или запрет флага.
- В 20.0 ядро поставляется с Owl `3.0.0-alpha.50`, поэтому JS-раздел будет быстро устаревать.
- Таблицы удобны для 17→20, но столбцу «Since» верить нельзя. Для 18→19 часть
  ловушек спрятана в строках с пометкой «20».
- `odoo19-*` сравнивали по описаниям: `add_repo` на приватный маркетплейс отклонён.
