## Точность

Выборка из 62 утверждений с упором на 18→19 и 19→20, сверена с `odoo/odoo`
(`notes.md`, по строке на факт):

- **Факт верен: 62 из 62.** Неверных утверждений «это изменилось так» нет.
- **Версия неверна: 13.** 12 строк помечены «20», хотя изменение было в 19 или
  раньше (`_login`, `group_expand`, `odoo.registry`, `fields.datetime`, `models.NewId`,
  `readonly=1`, `post_send_callback`, `default_get`, `signup_url`,
  `base.default_user_group`, `'Product Unit'`, `<group>` в search). Ещё одна помечена
  «18» вместо «19» (`res.partner.title`) и противоречит строке 59 того же файла.

Причина видна из `lessons-learned.md`: автор мигрировал реальные модули 16→19,
17→20 и 18→20, а изменения записывал в версию цели. Для миграции на 20 это
безвредно, для таблицы «что изменилось в 19» — дефект.

## Что ценно

- Самый точный из разобранных справочников по 20.0 (ср. mart337i: 9 ошибок из 19).
- Конкретные «тихие» ловушки 20 с объяснением, как ломается: `ir.config_parameter`
  в шаблонах писем рушит установку с демо-данными; `copy()` копирует много записей
  сразу; `ir.attachment.datas` молча даёт пустой файл.
- Методика поиска новой ловушки: при ошибке `Field "x" does not exist` grep старого
  дерева по имени поля и нового по его `string`.
- `upgrade-code-tool.md`: проверенные ловушки официального `upgrade_code`, в
  документации Odoo их нет.
