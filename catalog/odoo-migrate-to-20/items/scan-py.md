# scan.py — сканер ломающих изменений 14→20

- **Файл:** `scripts/scan.py@a5507bf` (1447 строк, stdlib + запуск `$ODOO20_PYTHON`)
- **Лицензия:** MIT
- **Вердикт:** адаптировать идеи в T2 `boost:odoo19-lint`; сам скрипт не берём (цель 20, нужна локальная Odoo 20)

## Что делает

- 123 regex-правила в виде кортежей `(id, area, severity, kinds, where, regex,
  message, reference, auto)`. Распределение: python 44, backend-js 16, renames 14,
  views 12, website-sale 7, controllers 6, остальные мелкие. По серьёзности:
  57 BLOCKER, 20 SILENT, 30 RUNTIME, 16 WARN.
- Сверх regex: настоящий импорт каждого `odoo.*`-импорта под Python 20 (импорт в
  `try/except ImportError`, который на 20 падает, помечается SILENT), разрешение
  JS-импортов `@addon/...` до файла и экспорта, проверка туров по строгой схеме 20,
  сверка сигнатур override с ядром (индекс `def` по grep), проверка внешних xml-id,
  поиск секретов, `--fix-tesc` (механическая замена `t-esc` → `t-out`).
- Выход 1 при любом BLOCKER или SILENT.

## Что ценно для нас

1. **Класс SILENT.** В нашем T2 два уровня (ERROR/WARN). Ловушки «установится, но
   молча не работает» (`_sql_constraints`, `digits='Product Unit of Measure'`,
   `name_get`) заслуживают своего уровня, потому что их не поймает и тест установки.
2. **Поле `where`** (`static` / `server` / `any`) и **`auto`** (чем чинится
   автоматически, например `upgrade_code 18.1`). Это дёшево и снимает ложные
   срабатывания в `static/`.
3. **Проверка «импорт в try/except, который всегда падает».** Хорошая идея для
   19 (`from odoo.osv import expression` в 19 ещё работает, а в 20 — нет).
4. **Сигнатуры override против ядра.** Без исходников ядра на диске не работает,
   но в T2 можно держать короткий список изменённых сигнатур 18→19 (`_login`,
   `default_get(fields)`) с цитатами.

## Что хуже нашего

- Правила нацелены на 20, а для 19 часть из них — ложные срабатывания (например,
  `check_access_rights` в 19 ещё работает).
- Ссылка правила ведёт в их `references/*.md`, а не на `файл:строка` ядра. У нас
  каждое правило с цитатой из `odoo@19.0` — это сильнее.
- Требует `$ODOO20_PYTHON`, то есть готовое окружение Odoo 20.
