# odoo-mcp-19 (AlanOgic) — итог для главной сессии

- **Что это:** MCP-сервер для Odoo 19+ только через JSON-2 (`/json/2`), MIT
  (сверено по `LICENSE`, не форк), v2.2.0 @ `aea8542`, очень активен, 1 автор,
  ★11. 3 инструмента («любой метод»), 38 ресурсов, 12 промптов, слой безопасности.
- **JSON-2 против XML-RPC (сверено с `odoo@19.0` `e0b25b7`, 19 пунктов с
  `файл:строка` в `notes.md`):** права и транзакции **те же** (вызов = транзакция,
  ACL/record rules пользователя; XML-RPC тоже принимает API-ключ). Лучше:
  именованные аргументы с проверкой подписи (422), HTTP-коды и JSON-ошибки,
  `None` без `cannot marshal None`, приватные методы → 403, пароль не пройдёт.
  `/xmlrpc` и `/jsonrpc` deprecated в 19.0, удаление в Odoo 22.
- **Переходить ли `odoo-connector`:** не «вместо». В 18.0 JSON-2 нет
  (`odoo@18.0` `f0ef96d`), а дефолтная база коннектора `o18-artel-prod` — Odoo 18.
  Добавить JSON-2 вторым транспортом с выбором по версии, отдельной задачей после T3.
- **Реализация корректна:** подписи в `arg_mapping.py` совпали с 19.0; ошибки
  не теряются; побочные вызовы не повторяются при 429.
- **Главная находка для нас — дыры в ветке T3** (`claude/odoo-connector-safety`
  `c1e5462`, сверено через `add_repo`): (1) `default_get` и `onchange` в
  списке чтений — а `sale.order.line.default_get` в 19.0 создаёт `sale.order`
  (`addons/sale_project/models/sale_order_line.py:27-61`); (2) `create`/`write`
  разрешены на `*`, включая `res.users`, `ir.rule`, `ir.config_parameter`,
  `res.users.apikeys`; нет проверки записи в них через x2many
  (`res.partner.user_ids`), `default_*` в context и колонки `load`.
  У odoo-mcp-19 всё это есть (`safety.py:92-147`, `:366-559`), fail-closed.
- **Слабее нашего T3:** подтверждение проводит сам агент (токен в `hint`),
  аудит только stderr без ids, нет лимита записей и diff.
- **Оценка 12/18, вердикт: адаптировать.** Сервер не ставить. Взять в T3:
  список заблокированных и прокси-моделей, проверку x2many/`default_*`/`load`,
  «privileged»-модели, `default_get` ≠ чтение, привязку подтверждения к хешу
  payload. Факты JSON-2 → T1 (`odoo19-facts.md`).
- **Не проверено:** живой прогон (нужно разрешение и база 19), тесты автора,
  saas-19.x утверждения, `onchange` через RPC.
