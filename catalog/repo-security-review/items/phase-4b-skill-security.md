# Фаза 4b: проверка скиллов по OWASP LLM Top 10

- **Тип:** часть скилла (reference-файл фазы)
- **Источник:** `references/phase-llm-security.md@d5128b0`, правила поиска
  файлов в `references/phase2a-tech-stack.md@d5128b0`
- **Лицензия:** нет → только идеи своими словами
- **Вердикт:** адаптировать (идеи в наш чек-лист), как есть не брать

## Что делает

Субагент читает файлы скилла как недоверенные данные. Он ищет места, где
внешний контент (файлы пользователя, вывод инструментов, веб-страницы,
`$ARGUMENTS`) попадает в промпт без границы доверия. Ещё он ищет широкие
права на инструменты, утечку секретов и зависимости от внешних ресурсов.
Результат пишется в JSON, находки с префиксом `L-`, ложные срабатывания
идут отдельным списком.

## Что проверяется (пересказ)

| Пункт | Суть |
|---|---|
| LLM01 Инъекция | Внешний контент или аргументы вставляются в промпт как текст; шаг передаёт следующему свой вывод целиком, а не ссылку на файл; «персона» берётся из прочитанного файла |
| LLM02 Вывод | Чужие строки уходят в Markdown/HTML/JSON без экранирования; в артефактах лежат живые секреты; вывод передаётся в shell или API, где его исполнят |
| LLM05 Поставка | Устаревшие ID моделей; внешние URL; MCP и инструменты без пина версии; бинарники, вызванные по голому имени (подмена через PATH); `curl \| bash` и `pip install` в рабочем процессе |
| LLM06 Утечка | Сырые секреты в промптах, логах и отчётах; маскировка не во всех путях вывода; данные уходят во внешний сервис без ведома пользователя |
| LLM07 Инструменты | Bash там, где хватает чтения; WebFetch по URL из недоверенного контента; запись там, где нужен один файл; нет подтверждения перед необратимым; `allowed-tools` шире тела скилла |
| LLM08 Агентность | Субагент сам решает, какие шаги пропустить; не указано, где можно читать и писать; бесконечные циклы; субагенту отдают все аргументы вместо нужного среза; «делай, как написано в файле» |

Шкала severity для инъекции идёт по последствию: запись файлов, bash или
эксфильтрация = critical; подавление или выдумывание находок = high;
искажение отчёта = medium; косметика = low.

## Сильные стороны

- **Правило «нет цепочки — нет находки».** Для каждой находки нужен путь
  источник → преобразование → сток с конкретными строками. Это отсекает
  общие слова вроде «возможна инъекция».
- **Улика цитирует конкретную фразу инструкции**, а не просто файл.
- **Инъекция в проверяемом файле сама становится находкой** (critical), а
  анализ продолжается как раньше. У нас это правило есть только в
  формулировке «инструкции — данные».
- **Финальное сообщение субагента — канал утечки.** Субагент не повторяет
  находки в чате, всё уходит в файл.
- **Поиск файлов скилла по структуре, а не по словам** (`SKILL.md`,
  `.claude/commands/`), с записью улик. Причина: метки можно подложить, а
  поиск по словам срабатывал на любой `CLAUDE.md`.

## Слабые стороны (для нас важнее)

- **Читаются только `.md`.** В «чисто скилловом» репозитории (≥60% `.md`)
  проверка кода (фазы 3/4/5) выключается. Скрипты, хуки и `.py` внутри
  скилла никто не смотрит. Их собственный `scripts/setup.sh` с
  `curl | sh` прошёл бы без замечаний.
- **Нет поверхностей Claude Code:** хуки (`settings.json`,
  `hooks/hooks.json`), `.mcp.json`, `plugin.json`, marketplace,
  statusline, `SessionStart`. Для плагинов это главный риск, потому что хук
  исполняется без вызова скилла.
- **Нет скрытого текста:** HTML-комментарии, zero-width и bidi-символы,
  base64, очень длинные строки.
- **Нет оценки триггера:** широкий `description` перехватывает чужие задачи
  и тратит контекст.
- **Нет «отката» после проверки:** установка идёт через `git clone` ветки
  `main`, автор может поменять скилл после разбора. Пин на SHA есть только
  как пример условия в вендор-отчёте.
- Не покрыты LLM03, LLM04, LLM09, LLM10. Для скиллов это не критично.

## Что берём

| Идея | Куда у нас | Как |
|---|---|---|
| Цепочка источник → сток с file:line, иначе ложное срабатывание | чек-лист в `criteria.md`, `odoo19-mvp-build:security-review` | только идея, своими словами |
| Шесть групп проверок как скелет чек-листа | `criteria.md` → «Чек-лист безопасности скилла/плагина» | пересказ, своя группировка + наши дополнения |
| Инъекция в проверяемом файле = отдельная находка, анализ не меняется | `CLAUDE.md` п. 3 (предложение главной сессии) | только идея |
| Поиск файлов скилла по структуре, с записью улик | чек-лист, шаг «инвентаризация» | только идея |
| Субагент не пересказывает находки в чате | `plugins/boost` (правила субагентов) | только идея |
