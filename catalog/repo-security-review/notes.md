### Главное наблюдение по проверке скиллов (фаза 4b)

- Проверяются 6 пунктов OWASP LLM Top 10: LLM01, 02, 05, 06, 07, 08. Для
  каждой находки нужна цепочка источник → преобразование → сток с file:line.
  Нет цепочки — значит ложное срабатывание.
- **Слепое пятно:** читаются только `.md`. Если репозиторий признан «чисто
  скилловым» (нет кода или ≥60% файлов `.md`), фазы 3/4/5 пропускаются
  автоматически. Тогда `scripts/*.sh`, `*.py`, хуки внутри скилла не
  проверяются вообще. Пример — их собственный `setup.sh`: по их же правилам
  он остался бы непроверенным.
- Специфичные для Claude Code поверхности не проверяются: `hooks` в
  `settings.json` и `hooks/hooks.json` плагина, `.mcp.json`,
  `plugin.json`/marketplace, statusline-команды, `SessionStart`.
- Нет проверки скрытого текста (HTML-комментарии, zero-width/bidi,
  base64-блобы) и слишком широких триггеров в `description`.
- Признак «злого умысла» (обфускация, враждебные install-скрипты) есть в
  рубрике вердикта, но процедуры поиска нет.

### Решения

- Инструмент как есть **отклоняем**: он тяжёлый (22k токенов на запуск),
  экспериментальный, без лицензии, требует сканеров, которых нет в облаке,
  а скиллы проверяет хуже нашего ручного процесса (не видит хуки и скрипты).
- Идеи **адаптируем**: чек-лист безопасности скилла для `criteria.md`,
  вердикт вендор-аудита с условиями, раздел «отклонённые подозрения» и
  «что не проверено» в карточке, пин на проверенный SHA.
