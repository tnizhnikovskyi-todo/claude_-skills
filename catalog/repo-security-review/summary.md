# repo-security-review — summary для главной сессии

**Что это.** Скилл Consensys (★33, `experimental`, один автор, активен до
2026-10-21, **лицензии нет**: Apache-2.0 добавлен и через 2 минуты удалён).
Многофазный аудит репо субагентами: секреты, CVE, OWASP, валидация, PoC в
Docker. Отдельно есть **фаза 4b — проверка скиллов по OWASP LLM Top 10** и
режим **`--vendor`** («можно ли нам внедрить чужой инструмент»).

**Лучшие находки** (только идеи, своими словами):
1. Для каждой находки цепочка источник → преобразование → сток с
   файл:строка и цитатой фразы; нет цепочки — значит «отклонённое
   подозрение».
2. Вердикт вендор-аудита с **условиями безопасного использования**, каждое
   условие привязано к находке, плюс «чем закроем сами» и «что не
   проверено».
3. Инъекция в проверяемом скилле сама становится находкой, ход разбора не
   меняется.

**Главная дыра у них:** 4b читает только `.md`, а для «чисто скиллового» репо
проверка кода выключается. Скрипты, хуки, `.mcp.json`, `plugin.json` не
смотрит никто. Их собственный `setup.sh` (`curl | sh` из `main`,
`@latest`, `sudo`) прошёл бы без замечаний.

**Вердикт.** Инструмент **отклонить** (8/18: 22k токенов на запуск,
сканеров нет в облаке, дублирует `security-review` + Strix). Идеи
**адаптировать**: готовый черновик чек-листа «Безопасность скилла/плагина»
для `criteria.md` в `items/proposed-checklist.md`. Он дополнен тем, чего
нет у них: хуки и MCP, скрытый текст, `bypassPermissions`, широта
`description`, пин на SHA. Ещё предложение: добавить в `_TEMPLATE.md`
разделы «Условия использования», «Отклонённые подозрения», «Что не
проверено».

**Дальше:** A/B чек-листа на 3–4 подложенных «вредных» скиллах; решить,
включать ли чек-лист в первое сообщение сессий анализа или сделать
скилл `skill-vetting`.
