# ponytail: сводка

- **Что это:** плагин «ленивый сеньор» (MIT, v5.3.3, очень активный, 137 авторов):
  6 скиллов + хуки автоинъекции + UI-плашка метрик для Claude Code и ~20 других агентов.
- **Суть:** метод против overengineering: «нужно ли → есть в репо → stdlib →
  уже установленная зависимость → одна строка → минимум», без права резать
  валидацию/безопасность; тест на рискованную логику; финальная строка
  «что не проверено / риск».
- **Бенчмарк автора** (Opus 5.5, 39 задач × 5): −53% кода, −26% стоимости,
  −41% времени при той же корректности; тесты на рискованную логику 98% vs 68%.
  Не независимый.
- **Лучшие находки:** текст `ponytail` (метод), `ponytail-audit` (аудита
  целого репо у нас нет), 4-частный формат находки из `ponytail-review`
  («что это / проблема / фикс / если не чинить»), конвенция
  `shortcut: <предел>, <когда апгрейдить>`.
- **Безопасность:** код прочитан, сеть только через опциональный webhook (по
  умолчанию выкл.). Но хуки пишут в `~/.claude`, `~/.config` и скрыто просят модель
  править `settings.json`; правила вставляются в каждую сессию и в каждого субагента.
- **Вердикт:** **адаптировать.** Плагин целиком не ставить (band не работает
  в облаке, always-on меняет поведение наших процессных плагинов). Взять
  тексты `ponytail` и `ponytail-audit` как свои скиллы (с Odoo-вариантом:
  «stdlib» → стандартные механизмы Odoo 19), формат находок добавить в `pr-review`.
- **Дальше:** A/B на реальной Odoo-задаче с правилами и без.
