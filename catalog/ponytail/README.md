# Ponytail

- **Тип:** плагин Claude Code (6 скиллов + хуки SessionStart / SubagentStart / UserPromptSubmit + UI-модуль «band»); также порты под Codex, Cursor, Copilot, OpenCode и ещё ~15 агентов
- **Источник:** https://github.com/dietrichgebert/ponytail (npm `@dietrichgebert/ponytail`)
- **Версия / коммит:** v5.3.3, `96608e0` (2026-10-29)
- **Дата разбора:** 2026-11-02
- **Вердикт:** **адаптировать** (взять тексты скиллов и пару конвенций; плагин целиком с хуками и band не ставить)

## Что делает

«Режим ленивого сеньора»: набор инструкций, который заставляет агента делать
наименьшее *полное* изменение: сначала переиспользовать то, что уже есть в
репо, потом stdlib/платформу, потом установленные зависимости, и только потом
писать новый код. При этом явно запрещено резать валидацию, обработку ошибок,
безопасность и доступность, а нетривиальная логика обязана уходить с тестом.
Ответ заканчивается строкой «что пропустил / что не проверил / риск». Плюс
отдельные скиллы ревью диффа, аудита всего репо и учёта «долгов»
(`shortcut:`-комментариев), и плашка «band» с метриками сессии.

## Какую слабость Claude закрывает

- **Overengineering:** лишние абстракции, конфиги «на будущее», новые
  зависимости ради пары строк, самописные компоненты вместо уже имеющихся.
- **Неполные изменения:** правка в одном месте без обхода всех вызывающих.
- **Тихие допущения:** финальная строка «что не проверено и какой риск».
- Категории README: **Метод** (основное) и частично **Проверка** (тест на
  рискованную логику, review/audit с обязательным конкретным кейсом на находку).

## Как устроен

- `skills/*/SKILL.md`: чистый Markdown, без скриптов. Основной скилл ~3.5 КБ,
  review/audit по ~5 КБ.
- `hooks/ponytail-activate.js` (SessionStart): пишет флаг режима в
  `~/.claude/.ponytail-active`, вставляет правила в скрытый контекст (~2.9 КБ
  для `full`) плюс «карту кода» (`ponytail-map.js`: regex по `git ls-files`,
  до 2000 символов имён функций/классов). Копирует скрипт статуслайна в
  `~/.claude/` и один раз просит модель прописать его в `settings.json`.
- `hooks/ponytail-subagent.js` (SubagentStart): те же правила в каждого субагента.
- `hooks/ponytail-mode-tracker.js` (UserPromptSubmit): ловит `/ponytail lite|ultra|off|band`.
- `hooks/band/*.tsx|ts` (UI-модуль Claude Code ≥ 2.1.290): плашка с
  ценой/токенами/временем/«reuse»/тестами; после каждого хода пишет строку в
  `~/.config/ponytail/band/<project>.csv` и `board.html`; опционально POST на
  webhook (только https, по умолчанию пусто). В облачных сессиях не работает.
- Сеть: только опциональный webhook. Внешних URL, телеметрии, eval нет.
- Зависимости: только Node (встроенные модули). Лицензия MIT.

## Проверка

Сами не прогоняли (скрипты не запускали по правилам). Бенчмарк автора
(`benchmarks/results/2026-10-07-agentic.md`): Claude Code, Opus 5.5, 39 задач × 5 прогонов.

| Метрика (автор) | Без скилла | С ponytail 5 |
|---|---|---|
| Строк кода | 100% | 47% |
| Стоимость | 100% | 74% |
| Время | 100% | 59% |
| Скрытые проверки (18 задач) | 95.6% | 96.7% |
| Рискованная логика с тестом | 68% | 98% |

Оговорки: бенчмарк собственный, судья тоже LLM; качество не выросло, а
сохранилось при меньшем объёме. Слепой судья не нашёл значимой разницы в
качестве ответов против «без скилла». Стоит проверить на наших задачах
(Odoo-модули): см. открытые вопросы в `notes.md`.

## Риски и заметки

- Пересечение: встроенные `code-review` (ревью диффа) и `simplify` (упрощение
  после факта). Ponytail ценен тем, что действует *до* написания кода и
  требует финальную строку рисков; `ponytail-audit` аналога у нас нет.
- «Ultra» уровень спорит с пользователем о требованиях: в клиентских
  проектах по ТР это может мешать.
- Always-on инъекция в каждого субагента меняет поведение наших процессных
  плагинов (`odoo19-mvp-build` и др.) неявно.
- Цифры в README бенчмарк автора, а не независимый.
