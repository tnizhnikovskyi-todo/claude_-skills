- **Тип:** скилл (один `SKILL.md` + 2 справки, скрипт скриншота, HTML-шаблоны карточек)
- **Источник:** https://github.com/alchaincyf/darwin-skill (★6.8k)
- **Разобранный коммит:** `8a8b66258e3c45d6ae4aea39719468c6428fcb0a` (`main`, 2026-09-18)
- **Лицензия:** MIT (`LICENSE`, © 2026 alchaincyf (花叔)); файл добавлен только в `a1a5871` 2026-07-26, бейдж MIT был с начала
- **Дата разбора:** 2026-11-03
- **Вердикт:** **адаптировать 4 идеи** в еженедельное ревью скиллов; сам скилл **не ставить**

## Что делает

«Эволюция» скиллов в стиле Karpathy autoresearch: оценить `SKILL.md` по
9-мерной рубрике (100 баллов: структура 59, эффект 35, «чёрный список» 6),
взять самое слабое по весу измерение, внести одну правку, закоммитить,
дать 3 свежим судьям-субагентам сравнить старую и новую версию, по
большинству голосов оставить или сделать `git revert`, после каждого
скилла остановиться на чекпоинте для человека, в конце нарисовать
PNG-карточку результата. Всё делает сам агент по тексту `SKILL.md`; кода,
кроме скриншота, нет.

## Какую слабость Claude закрывает

Заявлено: скиллы пишутся один раз и не улучшаются; самооценка модели
оптимистична. Реально закрывает «полировку текста скилла по чек-листу» с
человеком в цикле. Ошибок поведения на реальных задачах не ловит: тесты
синтетические (2–3 промпта пишет тот же агент), решение keep/revert
принимается по тексту, а не по прогонам.

## Как устроен

| Фаза | Что делает | Заметки |
|---|---|---|
| 0 | Ветка `auto-optimize/<время>`, `results.tsv` | Ищет `.claude/skills/*/SKILL.md` |
| 0.5 | 2–3 тест-промпта на скилл → `test-prompts.json` в каталог целевого скилла; показать человеку | Пишет в чужие каталоги |
| 1 | Абсолютные баллы по рубрике; dim8 — субагенты с/без скилла на тест-промптах, иначе «dry_run» | Баллы только для сортировки |
| 2 | Раунд ≤ 3: худшее по `вес × (10 − балл)/10` измерение → 1 правка → коммит → **3 судьи парно** (старая vs новая в одном вызове) → `better ≥ worse` → keep, иначе `git revert` | Тесты не перезапускаются; ничья = keep |
| 2.5 | Переписать с нуля, если hill-climbing застрял (по согласию) | `git stash` |
| 3 | Отчёт, PNG-карточка (Playwright) | |

Ограничители: одно измерение за раунд; `SKILL.md` не больше 150% исходного;
нельзя добавлять файлы; стоп, если 2 раунда подряд Δ < 2 или «slight/tie»;
чекпоинты 🔴; чёрный список из 8 антипаттернов (самооценка в том же
контексте, абсолютная дельта как критерий, `reset --hard`, «вода ради
балла», пропуск тестов, несколько измерений за раунд, > 30% мысленных
прогонов, тихое проглатывание ошибок).

**Права и сеть.** Коммиты, `git revert`, `git stash` в репозитории
пользователя; запись `test-prompts.json` в каждый целевой скилл. Раз в 30
дней «тихо» `git ls-remote origin` для проверки версии (без автообновления).
Карточка: `execSync('npm root -g')`, фолбэк `npx playwright`, `xdg-open`;
шаблоны грузят Google Fonts. Телеметрии нет. Установка через
`npx skills add` или zip с R2 автора. Триггер широкий (китайские
«skill怎么样», «帮我改改skill», «skill review»), описание 737 символов,
сам скилл ~9–10k токенов. «Runtime-neutrality gate» требует вычищать
упоминания Claude Code — для нашего плагина вредно.

## Сравнение с нашим и прошлыми разборами

- **Дублирует:** человек одобряет правку (`weekly-review.md` §0, §3); одна
  группа правил на ветку = одна правка на измерение; запрет `reset --hard`
  у нас и так.
- **Хуже нашего:** решение по тексту, а не по поведению; ничья сохраняется;
  нет отложенных кейсов; рубрика содержит вкусовые пункты автора
  («стиль 花叔», запрещённые слова).
- **Против SkillOpt** (`catalog/skillopt/`): darwin берёт у SkillOpt
  название «validation-gated», но без отложенной выборки и без
  no-regression; бюджет правок и разбор «нарушение vs дефект» у SkillOpt
  сильнее и уже в T14. Новое у darwin — **парное сравнение одним судьёй**
  и лимиты роста/остановки.
- **Против one-skill** (`catalog/one-skill-to-rule-them-all/`): там сбор
  наблюдений из реальной работы, тут его нет совсем; darwin — только
  «оптимизатор» без входящего сигнала.
- **Слабость у нас, которую он подсветил:** `weekly-review.md` §5 велит
  сравнивать новый прогон «с прошлым результатом скилла» из отчёта —
  абсолютные числа разных прогонов (антипаттерн 1b darwin: шум ±8/100 у
  одного и того же текста).

## Риски и заметки

- README громко ссылается на Microsoft SkillOpt («официальная
  интеграция»), но механизм гейта другой (см. `notes.md` п. 2). Оценивали
  по `SKILL.md`, а не по README (принцип №24).
- Если когда-нибудь запускать: только в отдельной ветке, с явным списком
  скиллов, без карточек и без проверки версии; результат всё равно
  проверять нашим A/B.
