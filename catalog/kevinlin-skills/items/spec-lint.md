# spec-lint

- **Тип:** скилл · **Источник:** https://github.com/kevinlin/skills/tree/main/spec-lint · v1.2.1
- **Вердикт:** **адаптировать идею** (обратная согласованность), сам скилл не ставить

## Что делает

Линт дерева спек: определяет фреймворк (Kiro, OpenSpec, spec-kit, BMad,
GSD, Superpowers, default), копирует в проект `meta/convention.md` и дальше
читает правила только из этой локальной копии. Проверки: именование,
мёртвые ссылки, сироты, пустые разделы, TODO, расхождение индекса и
главное: **обратная согласованность** (5.8 дизайн покрывает каждое
требование, 5.9 план/задачи покрывают каждый пункт дизайна). Отчёт
`meta/lint-report-YYYY-MM-DD.md`, автоисправление только по запросу.
317 строк + `references/convention.md`, 6 eval-кейсов.

## Ценные приёмы

- **Recall важнее точности** для покрытия: сообщать пограничные случаи,
  человек отбросит ложные.
- **Критерий завершения проверки:** «каждый файл требований открыт, каждый
  пункт сопоставлен или выдан как warn». Это граница покрытия (№26).
- **Локальная копия конвенции — источник правды**: если отличается от
  поставляемой, не перезаписывать, а сообщить.
- Абсолютный путь к `meta/` вычисляется один раз, потому что после `cd`
  относительный путь создаёт вложенную копию дерева. Мелкий, но реальный баг.
- Идемпотентность: два прогона подряд дают одинаковый отчёт.

## Применение у нас

Наша цепочка тоже многослойная, но ID свои: журнал дискавери (D-N, Q-N, T-N)
→ ТР (требования, `AC-01`…) → `SPEC.md` (те же `AC-01`) → тесты/код →
акт приёмки. `tr-review` (по описанию) проверяет покрытие **внутри** ТР:
AC ↔ требования, реализация ↔ AC. Сквозной проверки между документами,
насколько мы видим, нет:

- каждое D-N «в scope» из журнала дошло до ТР;
- каждый `AC-NN` из ТР есть в SPEC дословно (spec-writer обещает, но кто проверяет?);
- каждый `AC-NN` из SPEC покрыт тестом (`testing`) и упомянут в акте;
- ничего лишнего: AC в SPEC без источника в ТР.

→ Кандидат в `boost`: **`trace-lint`** (только чтение, grep по ID,
таблица покрытия, recall > precision). Дёшево (ID у нас уже канонические),
легко проверить A/B на фикстурах с выкинутым AC. До постановки задачи
сверить с полным текстом `tr-review` и `track-convergence`.
