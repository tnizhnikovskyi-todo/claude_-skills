## Что делает

Набор из 9 независимых скиллов «по фазам поставки»: анализ разрывов в
требованиях (HTML-реестр), разработка по спеке (5 стадий с воротами), исследование →
план → реализация с 6 субагентами, ревью кода, сжатие и линт спек,
HTML-диаграммы, «де-слоп» текста, отчёт по логам агентов.

**Гипотеза «от gap-анализа до сданного кода» подтверждается только как
описание набора.** Цепочки нет: `gap-analysis` выдаёт HTML-реестр для
тендерной команды, `spec-coding` начинает с нуля с целей пользователя и
этот реестр не читает. Связаны между собой только `spec-coding` →
`spec-compact` / `spec-lint` (общая папка `docs/specs/`).

## Какую слабость Claude закрывает

- `gap-analysis`: без правил модель выдаёт разрывы произвольной формы,
  перенумеровывает ID при обновлении, не различает «блокер» и «замечание»,
  молча выбирает один из двух противоречащих терминов.
- `spec-lint`: модель доверяет устаревшим спекам; никто не проверяет, что
  дизайн покрывает все требования, а план — весь дизайн.
- `spec-compact`: после релиза план раздут кодом и шагами, которые уже живут в репо.
- Остальное закрывает слабости, которые у нас уже закрыты (см. таблицу).

## Как устроен

- Чистые `SKILL.md` + `references/` по требованию; у `research-plan-implement`
  и `code-review-expert` есть `agents/`.
- **Хуков нет, MCP нет.** `allowed-tools` объявлен только у `declawed` и
  `html-diagram` (Read/Write/Edit/Grep/Glob/Bash).
- Скрипты (прочитаны, не запускались): `declawed/scripts/scan.py`
  (stdlib, regex), `agent-insights/scripts/agent_insights.py` (stdlib +
  `sqlite3`, читает логи агентов в `~` и пишет в `~/.agent-insights/`,
  сетевых импортов нет), `html-diagram/scripts/html_to_png.py`
  (локальный HTTP на `127.0.0.1` + headless-браузер через `subprocess`),
  `research-plan-implement/scripts/spec_metadata.sh` (git-метаданные).
- **Сеть:** ни один скрипт не ходит наружу. Агент `web-search-researcher`
  использует обычный веб-поиск модели.
- Есть eval-кейсы (`evals/eval.yaml` + `assert-*.sh`) у 5 скиллов —
  полезный образец для наших `plugins/boost/evals/`.

## Риски и заметки

- `gap-analysis` заточен под один тендер: воркстримы WS1–WS7, владельцы
  BSC/Zühlke, SAP-коды (VA01, VK11), JARVIS. Брать надо структуру, а не текст.
- В репо лежит **заполненный** `gap-analysis/gap-register.html`
  (120 разрывов, «BSC», «Zühlke», японское регулирование), похоже на
  данные реального тендера с замаскированным только названием проекта.
  Это риск автора, а не наш, но копировать файл к себе не стоит.
- `spec-coding` пишет требования сам («сначала черновик, потом вопросы»).
  Это противоречит нашему правилу `odoo-spec-writer`: SPEC только из
  одобренного ТР, требования не выдумываются.
