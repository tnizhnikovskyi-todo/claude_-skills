# critical-business-issue-finder, do-nothing-buster, champion-health

- **Источник:** соответствующие `skills/*/SKILL.md` (MIT).
- **Вердикт:** адаптировать (как проверки в анализе брифа/журнала).

## Суть
- **Бизнес-проблемы против шума.** Из заметок выделяются 2–4 критичные
  бизнес-проблемы: у каждой есть владелец, последствие, событие, которое
  задаёт срок, и измеримость. Отдельно — то, что проблемой не является:
  симптомы, просьбы о функциях, предпочтения ИТ. Без события-срока —
  только «кандидат».
- **Риск «ничего не делать».** Проверка причин, по которым клиент
  останется на текущей системе, оценка риска, цена бездействия в месяц
  из чисел клиента, действия для чемпиона. (Свой список причин пишем сами,
  перечень из книги не копируем.)
- **Сила чемпиона по поведению.** Оценка по наблюдаемым действиям (знакомит
  с другими, даёт доступ к ЛПР, делится внутренней информацией), красные
  флаги («я передам»), и правило: материалы для «продажи внутри» отдаём
  только подтверждённому чемпиону.

## Куда у нас
- `odoo19-sales-prep:brief-transcript-analyzer`: разметка болей
  «проблема / симптом / хотелка» и поле «событие-срок».
- `deal-revival-check`: риск «ничего не делать» и сила чемпиона как
  причины застоя.

## Как проверить
На 3–4 журналах: сколько «болей» в брифе на деле хотелки; совпадение
оценки риска с исходом сделки.
