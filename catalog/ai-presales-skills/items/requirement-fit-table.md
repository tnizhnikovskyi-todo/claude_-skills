# capability-mapper: таблица соответствия требований

- **Источник:** `skills/capability-mapper/SKILL.md`, шаг 5b (MIT).
  Остальная часть скилла (тепловая карта, `.tsx`-артефакт) нам не нужна.
- **Вердикт:** адаптировать — самая применимая к Odoo идея репозитория.

## Суть
Каждое требование клиента получает рейтинг соответствия продукту: из коробки /
настройка / разработка / разрыв, плюс пометка «обязательное». Правила:
неоценённое требование = 🔴, а не «подходит»; рейтинг ставит специалист, а не
выводится из списка возможностей; обязательное с разрывом или 🔴 накладывает
вето на общий вывод о соответствии. Таблица — вход для шлюза квалификации.

## Куда у нас
- В `odoo19-sales-prep` перед `preliminary-estimate`: колонки «Стандарт Odoo
  19 / Настройка / Доработка (td.*) / Разрыв», модуль Odoo, «обязательное»,
  тег уверенности, источник рейтинга (кто подтвердил).
- `preliminary-estimate` берёт трудозатраты по категориям из этой таблицы.
- Дальше та же таблица продолжается в дискавери и `journal-to-tr-builder`
  (id требований сохраняются, №12).
- Рейтинг «стандарт» проверять по документации Odoo 19 (наш `source-check`/
  Context7), не по памяти.

## Как проверить
На пилоте: доля требований, ошибочно отнесённых к «стандарту», с таблицей и
сверкой по документации против оценки без неё.
