## Что делает

Большая библиотека QA-скиллов «от требований до релиза»: анализ требований и
AC, тест-дизайн (классы эквивалентности, таблицы решений, комбинаторика),
ручное и исследовательское тестирование, баг-репорты, регрессия, quality
gates, отчёты, релизные Go/No-Go, плюс десятки узких (API, UI-фреймворки,
перф, LLM/агенты, хаос). Каждый скилл — короткий `SKILL.md` (2.5–6 KB) +
`prompts/<name>.md` как «полная спецификация» + шаблоны вывода (md/csv/xlsx/
docx/xmind) + конвертеры на Python + evals для их движка `skill-up`. 14
workflow-скиллов связывают узкие скиллы по шагам (`workflow.yaml`).

## Какую слабость Claude закрывает

Не столько «как тестировать» (это модель умеет: собственный A/B автора на
`functional-testing` — 3/3 и с ним, и без него), сколько **дисциплину
доказательств**: раздельные статусы исполнения (не начато / прервано /
заблокировано / пройдено / провалено / неизвестно), запрет выдавать план за
результат, «отсутствие доказательства ≠ PASS», трассировка каждого кейса к
ID требования, решающие (проверяемые) ожидаемые результаты, отдельная
запись исключений с тем, кто их разрешил и до когда.

## Как устроен

- `skills/<lang>/testing-types/<skill>/`: `SKILL.md` (когда, порядок,
  ограничения, чек-лист перед выдачей) → `prompts/<skill>.md` (вход, правила,
  минимальное покрытие, порядок разделов вывода, планка качества) →
  `output-templates/`, `references/`, `scripts/` (конвертеры форматов),
  `evals/` (yaml-кейсы, грейдеры), `agents/openai.yaml`.
- `skills/<lang>/testing-workflows/`: сценарии-оркестраторы
  (`requirement-to-test`, `release-testing-workflow`, `change-to-regression`
  и др.) — по имени передают работу узким скиллам.
- Права: только чтение + запись файлов вывода; сеть только у API/перф-
  скиллов против тестируемой системы. Хуков, MCP, телеметрии нет.
- Установщик копирует каталоги в `~/.claude/skills` с `rsync --delete` по
  каждому скиллу (перетрёт одноимённый). Подробно: `notes.md`.

## Проверка

A/B на наших задачах не делали: брать как есть нельзя по лицензии, чужие
скиллы без разрешения не запускаем. У автора есть собственный честный A/B
(GPT, 3 прогона/плечо): `functional-testing` 3/3 vs 3/3 — прироста нет;
`testability-analysis` 3/3 vs 2/3; `skill-evaluation` 3/3 vs 0/3 (только
соблюдение формата состояний). Это совпадает с нашим `synthesis.md` (п. 1–2).

Предлагаемая проверка для нашей версии T11:

| Задача | Без скилла | С `uat-test-book` |
|---|---|---|
| UAT-книга по AC реального ТР (2–3 шт.) | — | — |
| Метрики: покрытие AC n/n; кейсы без AC; недоказуемые ожидаемые («работает корректно»); статус «пройдено» без факта; есть ли негатив/права на высокорисковых AC | — | — |

## Сравнение с тем, что есть

- **`catalog/generate-test-book`** (идеи для T11): даёт табличную форму
  UAT и «кейс только из AC, без AC — стоп». awesome-qa-skills **дополняет**:
  словарь статусов исполнения, решаемость ожидаемого, матрицу с колонкой
  «пробел», обязательность негатив/граница/права на высокорисковых AC (как раз
  слабость generate-test-book). Вместе закрывают T11.
- **`odoo19-tr-authoring:tr-usecases-acceptance` / `tr-review`** уже пишут и
  проверяют AC. Сверх них — режимы ревью AC (переформулировка не подменяет
  исходник; «неопределённое правило» остаётся открытым вопросом заказчику) и
  разбиение порогов. Дубль по сути «проверить AC на тестируемость».
- **`odoo19-mvp-build:testing`** (автотесты Odoo): из набора полезна только
  граница «регрессия vs приёмка» и запрет считать запланированное
  выполненным. Скиллы под pytest/Playwright — не наш стек (у нас Odoo
  `TransactionCase`/`HttpCase`), не берём.
- **`odoo19-implementation:acceptance-act-builder` / `hypercare-tracker`**:
  тексты недоступны (`add_repo` отклонён). По описаниям: акт приёмки и
  трекер инцидентов после go-live. Сверх — fail-closed критерии выхода и
  исключения с владельцем/сроком (для «принято с замечаниями»), поля дефекта.
  Сверить с текстами перед правкой.
- **Хуже нашего:** нет предметной области (ERP, роли/группы Odoo, многокомпанийность,
  локализация UI); шаблоны вывода общие; 2 языка — en/zh (нам нужен
  украинский); формат «под любого агента», без Claude-специфики.

## Риски и заметки

- Лицензия менялась трижды за 4 месяца — при любой попытке копирования
  текста перепроверять на актуальном SHA. Сейчас NC: копировать нельзя.
- Полная установка 169 скиллов (×2 языка) раздувает список скиллов в
  контексте и конфликтует по триггерам с нашими `odoo19-*` и `tr-*`.
- Эффект проверен автором на GPT/Codex, не на Claude.
