# generate-test-book

- **Тип:** скилл (Claude Code, один `SKILL.md` + 4 context-файла)
- **Источник:** https://github.com/Androbito/generate-test-book
- **Версия / коммит:** `1aa864ce0165e19a2159217df8c4b7795fef0e10` (main, 2026-08-07)
- **Лицензия:** нет (ни `LICENSE`, ни упоминаний в файлах и истории) → только идеи своими словами
- **Дата разбора:** 2026-11-03
- **Вердикт:** **адаптировать** (идеи формата и правил в свой скилл UAT-тест-книги)

## Что делает

По ключу пользовательской истории (`/generate-test-book QUF-21`) читает
историю и комментарии из бэклога (проверен Linear MCP; Jira, Confluence не
проверены), нумерует её AC, смотрит прикреплённые макеты (картинки в теле
истории, Figma), показывает план сценариев и вопросы, ждёт явного одобрения и
пишет черновик ручной тест-книги в Gherkin (`output/test-book-<key>.md`) с
трассировкой каждого сценария к AC. В бэклог не пишет.

Гипотеза из поиска **подтвердилась** с уточнением: скилл не пишет AC, а
требует готовых; без AC останавливается.

## Какую слабость Claude закрывает

Без правил модель охотно «досочиняет» тест-кейсы из описания, макетов или кода,
цитирует подписи кнопок из макета (тест падает на другой локализации), пишет
неисполнимые шаги («работает корректно») и не показывает, какие AC остались без
проверки. Скилл запрещает это явно и требует покрытия «n/n AC».

## Как устроен

- `SKILL.md`: фазы 0–5 — определить источники и проверить ключ → прочитать
  AC → макеты → **блокирующее ревью** → генерация → замеры.
- `context/sources.md`: контракт из шести «способностей» (проверить ключ,
  прочитать историю, обсуждения, список макетов, макет, записать файл) и их
  привязка к инструментам MCP. Записи в бэклог в контракте нет намеренно.
- `context/qa/test-conventions.md`, `test-book-template.md`,
  `test-data.md`: правила формулировок, скелет документа (+ табличный
  вариант), вымышленные данные.
- Скриптов, хуков, `.mcp.json` нет. Права: чтение через уже подключённые
  MCP-серверы, запись только в `output/`.

Подробный разбор формата, покрытия и сравнение: `items/generate-test-book.md`.

## Сравнение с тем, что есть

- `odoo19-tr-authoring:tr-usecases-acceptance` **пишет** AC в ТР (с
  обязательными негативными путями и правами). Этот скилл **исполняет** AC.
  Не дубль, а следующее звено.
- `odoo19-implementation:acceptance-act-builder` — акт приёмки; текста в
  сессии нет. Тест-книга ложится между AC и актом: клиент прогоняет её, акт
  ссылается на результаты.
