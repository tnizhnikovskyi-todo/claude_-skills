## Что делает

«Уборщик» скиллов для Claude Code и Codex: инвентарь скиллов, субагентов и
MCP-серверов во всех областях (user, project, плагины), оценка их цены в
контексте («всегда» — описания, «по вызову» — тела), частота использования
по транскриптам, поиск дублей и битых скиллов, автоисправление frontmatter,
эвристический скан на prompt injection и опасные приёмы в скриптах, поиск и
предпроверка скиллов на GitHub, TUI «свайп» для удаления. С 2026-09-30
автор перевёл проект в maintenance mode: ядро (цена, неиспользуемые)
теперь встроено в Claude Code (`/skill-doctor`, `/doctor`).

## Какую слабость Claude закрывает

Сам Claude не видит, сколько контекста съедают все установленные описания,
какие скиллы перекрываются триггерами и нет ли в чужом скилле скрытых
инструкций. Первое уже закрыто встроенными `/skill-doctor` и `/doctor`;
второе и третье — нет, и именно это нам нужно перед публикацией в
маркетплейс.

## Как устроен

- `SKILL.md` (92–123 строки) — обёртки: запустить
  `bash ~/.claude/skills/skills-janitor/scripts/<x>.sh`, честно изложить
  вывод. `allowed-tools: Read, Bash(bash:*)` у всех шести.
- Скрипты: bash 3.2 + python3 stdlib, без зависимостей. Тесты в `tests/`
  (регрессия frontmatter: CRLF, апострофы, блочные скаляры).
- Читает: каталоги скиллов/агентов/плагинов, `~/.claude.json`, `./.mcp.json`
  (имена, транспорт, `command` до 120 символов; env не выводит),
  транскрипты `~/.claude/projects/**/*.jsonl` (греп имён `Skill` и
  `mcp__*`).
- Сеть: только `/janitor-discover` (GitHub API; `GITHUB_TOKEN`, если есть).
  Телеметрии нет.
- Ничего не запускали; см. `notes.md`.

## Сравнение с нашим

- **`/skill-doctor`, `/doctor`** (встроены): цена контекста и
  неиспользуемые скиллы/MCP/плагины лучше, чем у janitor (видят реальную
  загрузку). Дублировать не нужно.
- **`boost:automation-audit`**: советует, что добавить; не считает, что
  уже стоит и сколько стоит. Идея «всегда / по вызову» дополняет раздел
  «Цена».
- **`catalog/repo-security-review/items/proposed-checklist.md`**: ручной
  чек-лист (хуки, MCP, `bypassPermissions`, широта `description`). janitor
  даёт автоматическую часть (регулярки), но без хуков и MCP. Вместе —
  чек-лист для разбора + линтер-барьер.
- **`catalog/claude-code-setup`**: только рекомендации, без инвентаря.
- **`synthesis.md` п. 8 «второе нарушение → барьер»**: линтер перед
  публикацией и есть такой барьер для маркетплейса.

## Риски и заметки

- Не ставить сотрудникам: `Bash(bash:*)` предразрешает любую
  `bash -c …`; `swipe`/`fix --prune` удаляют каталоги.
- Регулярки — нижняя планка: обходятся перефразированием. Линтер ловит
  небрежность и типовые приёмы, не умысел. Для чужих скиллов — ручной
  чек-лист из `repo-security-review`.
- Для главной сессии: дубль `meeting-protocol-builder` /
  `kickoff-survey-protocol`; реальную цену листинга ~100 скиллов снять
  `/skill-doctor` на машине сотрудника.
