# janitor-value (цена контекста и использование)

- **Тип:** скилл + скрипты (`skills/janitor-value/SKILL.md`,
  `scripts/value.sh` → `tokencost.sh` + `usage.sh`; `mcp.sh` для MCP)
- **Источник:** https://github.com/khendzel/skills-janitor @ `4b42f39`
- **Лицензия:** MIT
- **Дата разбора:** 2026-11-03
- **Вердикт:** отклонить как инструмент; идея «always / on-trigger» —
  в `automation-audit`

## Что делает

Для каждого скилла и субагента считает слова описания и тела, переводит в
«токены» коэффициентом 1.3 на слово (`tokencost.sh`, строка 133) и
разделяет: **Always** (описание, висит в системном промпте всегда) и
**Body** (тело `SKILL.md`, грузится при срабатывании). Использование
берёт из транскриптов `~/.claude/projects/**/*.jsonl` (греп строк
`"name":"Skill"` за N недель). Для MCP (`mcp.sh`) честно не выдумывает
токены: только где сконфигурирован, сколько вызовов, сколько разных
инструментов, когда последний раз.

## Где ошибается

- **Кириллица.** 1.3 токена на слово — оценка для английского. Для наших
  описаний (62–79% кириллицы) число занижено; насколько, не измеряли.
- **Не учитывает `when_to_use`**, хотя Claude Code добавляет его к
  описанию в листинге (лимит 1 536 символов на сумму, docs
  `code.claude.com/docs/en/skills`).
- **Не исключает `disable-model-invocation: true`** из «Always» — такие
  скиллы, судя по документации, в листинг модели не попадают.
- **Обрезка до 1 536 символов не учитывается** — длинное описание
  посчитано целиком.
- **В облаке бесполезен:** транскриптов прошлых сессий в контейнере нет,
  плагины организации там не лежат в `~/.claude/plugins` (проверено в
  этой сессии: каталог `synced/…` пуст).

## Сравнение со встроенным

`/skill-doctor` (Claude Code ≥ 2.1.252) показывает цену контекста и частоту
использования каждого скилла изнутри харнесса, отмечает ни разу не
вызванные и говорит, где выключить; `/doctor` делает то же для MCP и
плагинов. Автор janitor сам пишет, что для «урезать контекст» нужно брать
их. Для нашей задачи «сколько стоят описания ~100 скиллов» — снять
`/skill-doctor` на машине сотрудника.

## Что берём

Только идею (своими словами): в отчёте о настройке разделять «всегда в
контексте» (описания, MCP-схемы, CLAUDE.md) и «по вызову» (тела скиллов,
references). Куда: `plugins/boost/skills/automation-audit` (раздел «Цена»)
и правило линтера «описание + when_to_use ≤ 1 536 символов, ключевой
случай в начале».
