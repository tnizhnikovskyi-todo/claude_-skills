## Четыре вопроса к кейсам скилла

Набор кейсов отвечает на все четыре:

| Вопрос | Как проверяем | Где чинить при провале |
|---|---|---|
| **Срабатывает** — вызывается, когда надо, и только тогда | `tool_used: Skill` (отдельной строкой, не в балле); кейс «не срабатывать»; кейс «задача соседа» | `description` |
| **Работает** — после вызова делает дело | грейдеры результата | тело `SKILL.md` |
| **Окупается** — лучше, чем без него | плечо без плагина | задача (если база проходит так же) |
| **Держится** — не хуже прошлой версии | сравнение с прошлым прогоном того же набора | последняя правка |

- **Кейс соседа.** Для скиллов, которые могут перехватить чужую задачу
  (`repo-audit` ↔ встроенные `code-review`/`security-review`,
  `odoo-model-map` ↔ `odoo19-mvp-build`), один кейс с задачей соседа:
  наш скилл НЕ должен вызываться.
- **Диагноз в отчёте.** Каждый проваленный кейс относим к одному из:
  `description` (не вызвался / вызвался лишний), тело (вызвался, балл
  низкий), задача (база проходит так же; грейдер неоднозначен), окружение
  (лимит, таймаут, ошибка судьи, плагин не отключился).

## Шум и повторы

- **Непригодные прогоны не балл.** Таймаут, лимит API, ошибка судьи,
  пропуск грейдеров по `--max-cost-usd` — исключаем из среднего и пишем
  отдельной строкой «N непригодных», перезапускаем.
- **Порог шума.** При `--runs 3` один прогон из трёх — это 0.33 на кейсе.
  Разница плеч на кейсе, не превышающая разброс баллов внутри плеча
  (max − min по прогонам), считается нулём.
- **Интервал для доли успехов** (Уилсон, 95%): 9/9 → 0.70–1.00, 6/9 →
  0.35–0.88, 15/15 → 0.80–1.00, 10/15 → 0.42–0.85. При 3 кейсах × 3 прогона
  различим только сдвиг порядка +0.4 и больше; прирост меньше этого
  называем «в пределах шума», а вывод «взять» не строим на нём одном.
- **Подтверждение.** Спорный выигрыш или регресс (на грани порога, или
  решающий вердикт «взять/отказ») подтверждаем `--runs 5` по спорным кейсам,
  с согласия на бюджет.
- **Не pass@k.** В отчёте доля успешных прогонов, а не «прошёл хотя бы
  раз». Для скиллов, работающих без присмотра (задачи по расписанию),
  смотрим ещё «прошёл во всех прогонах».

## Контроль и бюджет

- **Контроль переиспользуем.** Базовое плечо (без плагина) зависит только
  от кейсов. Пока кейсы и судья не менялись, правку скилла сравниваем с
  сохранённым базовым `--json`, а не гоняем базу заново. При правке
  сравниваем дважды: с прошлым прогоном со скиллом (держится?) и с базой
  (окупается?).

## Шапка отчёта `reports/<slug>.md`

Перед таблицей с/без: версия Claude Code (`claude --version`), модель,
модель судьи, `--runs`, что загрузилось в каждом плече (плагины, MCP), число
непригодных прогонов, токены (вход/выход/кэш) и $ на прогон. Разные судьи
или версии CLI в плечах → сравнение недействительно.

## Фикстуры

- **Ключ ответа вне досягаемости.** Эталоны и ожидаемые ответы не кладём
  в рабочую папку агента; если без этого нельзя, грейдер
  `tool_used: Read` с `input_match` на путь ключа, `min: 0`, `max: 0`.
