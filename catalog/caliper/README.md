# Caliper

- **Тип:** CLI для проверки скиллов и MCP (Python, PyPI `caliper-eval`) + 2 скилла (`grill-skill`, `evaluate-skill`)
- **Источник:** https://github.com/edonadei/caliper
- **Версия / коммит:** v0.21.0 (`pyproject.toml`), `89ab3b0a14e6bddcae05cd3a320d9ad6757b8d6f` (2026-11-01)
- **Лицензия:** MIT, `LICENSE` сверен: «Copyright (c) 2026 Emrick Donadei». Чужих файлов
  с другой лицензией не нашёл (файлы от автора: ~97% из 318 коммитов его, ещё 3 соавтора с 1–3 коммитами).
- **Дата разбора:** 2026-11-03
- **Вердикт:** **адаптировать** методику в наши правила проверки; сам инструмент не ставить.

## Что делает

Гоняет настоящего агента (Claude Code, Codex, Pi, Hermes) по задачам из
`.eval.yaml` k раз, каждый раз в чистом временном HOME и пустой рабочей
папке. Скилл ставится туда, где агент сам его ищет (`.claude/skills/<name>/`),
в промпт его не подмешивают. Успех проверяет LLM-судья (`expect:`) или
Python-проверка (`assert:`). Отдельно от успеха считается **активация**:
выбрал ли агент нужный скилл (`activates:`). `--ablate <skill>` или
`--ablate mcp:<server>` прогоняет то же самое без компонента, а `caliper compare`
сравнивает два сохранённых прогона по задачам и по токенам и времени.

## Какую слабость закрывает

Ту же, что наш `claude plugin eval`: «скилл помог мне один раз» вместо
измерения. Сверх того — разделение «не сработал триггер» и «сработал, но
плохо», конкуренция скиллов за промпт и честный учёт шума инфраструктуры.

## Как устроен

| Компонент | Что | Карточка |
|---|---|---|
| CLI `caliper` (`caliper/`, ~18.6k строк Python, 42 ADR, ~60 файлов тестов) | `run`, `compare`, `report`, `list`, `validate`, `login chatgpt`, `telemetry` | [`items/caliper-cli.md`](items/caliper-cli.md) |
| Скилл `grill-skill` (94 строки + REFERENCE 166) | Интервью → спека → k=1 → контроль без скилла → цикл k=3 с диагнозом, где чинить | [`items/grill-skill.md`](items/grill-skill.md) |
| Скилл `evaluate-skill` (98 + 437) | Обёртка над CLI из чата агента: создать, проверить, запустить, свести | в карточке `grill-skill` |
| `examples/01–06` | 6 спек на типовые провалы: ложный успех, неверный инструмент, бесконечные повторы, регресс промпта, устаревший контекст, середина диалога | — |

**Права, сеть, что ставится.**

- Ставится `pipx install caliper-eval` (зависимости: typer, click, rich,
  pydantic, psutil, pyyaml, tomli-w) или скиллы через `npx skills@latest add`.
- Каждая попытка Claude Code запускается с **`--dangerously-skip-permissions`**
  (`caliper/harness/claude_code.py:283`).
- **По умолчанию попытка получает все настройки пользователя**: его MCP,
  коннекторы claude.ai (Gmail, Drive, Calendar), плагины, `CLAUDE.md`
  (ADR 0028). Вместе с пропуском разрешений это значит, что проверяемый скилл
  может действовать на реальном аккаунте без единого запроса. Изоляция:
  `--no-user-customizations` или `user_customizations: false` в спеке.
- Автор прямо пишет, что попытка — **не граница безопасности** (ADR 0027):
  агент работает от имени пользователя с его файловой системой.
- **Судья может написать Python-скрипт**, и он выполняется на хосте в рабочей
  папке попытки (`judge/eval_judge.py`, `_SYSTEM`, режим `script`). Текст для
  судьи — транскрипт агента, то есть возможна инъекция через вывод скилла.
- `setup:`/`cleanup:` из спеки — произвольный shell (лимит 600 с).
- **Телеметрия включена по умолчанию** (opt-out после уведомления, ADR 0042):
  PostHog `us.i.posthog.com`, одно событие на команду (команда, версия, ОС,
  бэкенд, исход, корзина длительности), общий `distinct_id`
  `caliper-anonymous`, IP `0.0.0.0`. Промпты, пути, имена скиллов не
  уходят. Выключить: `CALIPER_TELEMETRY_DISABLED=1` или `DO_NOT_TRACK=1`;
  в CI по умолчанию не шлёт.
- Git-источники соседних скиллов клонирует сам в кэш; незакреплённый ref
  разрешён, дрейф показывается в `compare`.
- Ничего из этого не запускал (п. 3 `CLAUDE.md`), выводы по чтению кода.

## Методика: Caliper против нашего `claude plugin eval`

| Вопрос | Caliper | Мы (`plugins/boost/evals/README.md`, `reports/`) |
|---|---|---|
| Кейсы | `.eval.yaml` рядом со скиллом: `prompt`, `setup`, `expect`/`assert`/`activates` | `case.yaml`/`prompt.md` + `graders/*.md`, минимум 3 кейса (2 «помогает», 1 «не срабатывать») |
| Повторы | `--k 3` по умолчанию; «спорную победу подтверждай на k≥5»; у k=3 одна попытка = 33 п.п. | `--runs 3` по умолчанию; правила подтверждения нет |
| Метрика | Доля успешных попыток (не pass@k: он льстит нестабильным скиллам, 1/3 → 70%); pass^k для работы без присмотра | Средний балл грейдеров по плечам |
| Шум | Типизированный исход: `infra_error`, `timeout`, `judge_error` выпадают из знаменателя и показываются отдельно; 429/503 повторяются 2 раза и считаются одной попыткой; лимит трат останавливает прогон | Есть одно правило: прогоны, где грейдеры пропущены по `--max-cost-usd`, не считать |
| Доверительные интервалы | **Нет.** В `compare.py:356` прямо сказано, что интервалы «должны быть на самом балле», но их нет; `compare` помечает любое падение и намеренно не валит выход, «на малом k это шум так же часто, как реальное изменение» | Нет; в отчётах вручную «в пределах шума» (`foundation.md`, `discovery-interview.md`) |
| Активация | Отдельное табло: `activates: [skill]`, `activates: []` (молчание), цепочка делегирования; recall/precision по скиллу | `tool_used: Skill` как индикатор, в балл не входит; кейс «не срабатывать» |
| Конкуренты | **Соседи** (`skills:` с чужими скиллами, в т.ч. из git @ SHA) и пробы «эта задача принадлежит соседу» | Нет: конкуренцию boost с `odoo19-*` и встроенными скиллами не меряем |
| Контроль | `--ablate` скилла или **`mcp:` сервера**; контрольный прогон хранится и **не перезапускается**, пока не поменялись задачи | Плечо «без плагина» в каждом прогоне; MCP-пилоты (rtk, cbm) — самописные скрипты (`run_ab.sh`) |
| «Задача не нужна скиллу» | Явное правило: контроль проходит так же → чинить задачу, а не скилл | Есть по смыслу (`general/` на потолке, уровень `hard`) |
| Окружение | Шапка `compare`: движок, версия CLI, судья, скиллы, MCP, загруженные настройки; предупреждения `judge_mismatch`, `mcp_mismatch`, дрейф скиллов по хешу файлов | Нет; мы наступали: `--ablation none` не отключил плагин (`reports/independent-check.md`) |
| Судья | Тот же бэкенд; промпт версионирован и восстанавливается из JSON; может писать assert-скрипт | haiku по умолчанию, у нас правило `--judge-model sonnet`; негативный и позитивный контроль грейдеров |
| Утечка ответа | `sandbox.forbidden_files` → исход `cheat` при чтении ключа | Нет |
| Стоимость | Токены (in/out/cache) и время на попытку; **доллары не считает** (ADR 0006) | Доллары из `claude plugin eval`, бюджет `--max-cost-usd` |
| Середина диалога | `history:` нейтральный транскрипт, резюмируется нативно | `context.history_file` (`--resume`) |

**Сильнее у них:** активация отдельно от успеха, соседи, переиспользование
контроля, типизация шума, сравнение окружений, ablation MCP одной командой,
защита от утечки ответа. **Сильнее у нас:** негативный/позитивный контроль
грейдеров, учёт денег и общий бюджет на оба плеча, практика с русскими
длинными отчётами (sonnet-судья). **Ни у кого:** доверительных интервалов и
правила, когда Δ считать шумом.

## Проверка

Не запускал (запрет на чужие бинарники без разрешения, п. 3 `CLAUDE.md`).
Свою проверку сделал на наших числах: интервал Уилсона (95%) для доли
успехов показывает, что при 3 кейсах × 3 прогона различимы только крупные
сдвиги.

| Успехов из n | 95% интервал |
|---|---|
| 9/9 | 0.70–1.00 |
| 8/9 | 0.56–0.98 |
| 6/9 | 0.35–0.88 |
| 4/9 | 0.19–0.73 |
| 15/15 | 0.80–1.00 |
| 10/15 | 0.42–0.85 |

Значит, наши +1.00 (`interview-me`, 0/9 → 9/9) и +0.45 (`skill-feedback`)
устойчивы, а +0.11 (`odoo-model-map`) и +0.23 (`repo-audit`) при n=9 в
пределах шума (баллы у нас дробные, поэтому оценка приближённая).

`CALIPER_TELEMETRY_DISABLED=1` для A/B Context7, если `claude plugin eval`
не умеет отключать MCP одним плечом (не проверено).

## Риски и заметки

- Значение по умолчанию «грузить настройки пользователя» опасно для нас: у
  сотрудников подключены Gmail, Drive, Odoo, Unitalk. Если кто-то поставит
  Caliper, обязательно `user_customizations: false` в каждой спеке.
- Скиллы `grill-skill`/`evaluate-skill` требуют `Bash` и ставят CLI сами
  (`pipx install caliper-eval if missing`) — против наших правил («без чужих
  установщиков»).
- Открыто: умеет ли `claude plugin eval` отключать MCP в одном плече и
  выдаёт ли он разброс по прогонам в `--json`. Спросить `claude-code-guide`.
