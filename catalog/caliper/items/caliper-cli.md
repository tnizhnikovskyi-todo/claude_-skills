# caliper (CLI)

- **Тип:** CLI на Python (`caliper-eval` на PyPI)
- **Источник:** https://github.com/edonadei/caliper @ `89ab3b0` (v0.21.0), `caliper/`, `docs/`
- **Лицензия:** MIT
- **Вердикт:** отклонить как инструмент, методику адаптировать (см. `../README.md`, «Что взять»)

## Что делает

`caliper run spec.eval.yaml --k 3 [--ablate <skill>|mcp:<server>]` гоняет
каждую задачу k раз в выбранном агенте и сохраняет JSON в
`.caliper/results/<spec>/<timestamp>.json`. `caliper compare A B` сравнивает
два прогона по задачам: доля успеха, Δ в п.п., отметки попыток `✓ ✗ ⊘ ·`,
токены и время, отдельная таблица активации, предупреждения о разном
окружении.

## Как устроен (по чтению кода)

- **Попытка** (`caliper/attempt.py`, `runner.py`): свежий HOME и пустая
  рабочая папка; скиллы копируются в `.claude/skills/<name>/`; `setup:` →
  агент → `assert:`/судья → `cleanup:`. Единица параллелизма — попытка,
  `--workers 4`, порядок round-robin (прерванный прогон даёт мелкую выборку
  всех задач, а не полную выборку первых).
- **Исходы** (`schema/results.py`): `pass`, `task_fail`, `cheat` считаются;
  `infra_error`, `timeout`, `judge_error` — «непригодные», вне знаменателя;
  `not_checked` — проба активации без проверки. Порядок:
  `setup failed → cancelled → timeout → infra_error → cheat → not_checked → judge`.
  `infra_error` включает «не видно ни одного вызова модели» (нет токенов).
- **Повторы:** 429/overloaded/503 — до 2 повторов (2 с, 4 с, джиттер),
  считается одной попыткой с полем `retries`. Таймаут и падение не
  повторяются (чтобы не прятать воспроизводимый дефект). Лимит трат
  останавливает весь прогон.
- **Активация** (`activation.py`): вызов инструмента `Skill` с именем скилла
  ИЛИ чтение `<name>/SKILL.md` по суффиксу пути. Встроенные скиллы CLI
  показываются, но не оцениваются. Наблюдение `null`, если увидеть было
  нельзя (не `[]`).
- **Судья** (`judge/eval_judge.py`): тот же CLI (`claude -p --output-format json
  --strict-mcp-config`), без коннекторов. Видит запрос, транскрипт (вывод
  инструмента обрезан до 2000 символов), ожидание. Отвечает вердиктом или
  Python-скриптом с `assert`, который выполняется в рабочей папке попытки.
  Версия промпта судьи хранится в прогоне, промпт восстанавливается.
- **Сравнение** (`compare.py`): задачи сопоставляются по имени; среднее
  только по задачам, измеренным с обеих сторон; регрессия — любое падение
  (правило «any-below»), выход не валится; токены и время не влияют на
  регрессию. Отказ сравнивать прогоны разных «эпох» загрузки скиллов.
- **Claude Code** (`harness/claude_code.py`): `claude -p --output-format
  stream-json --verbose --dangerously-skip-permissions --mcp-config … 
  [--strict-mcp-config] [--model] [--resume] -- <prompt>`.

## Права и данные

См. `../README.md`, «Права, сеть, что ставится». Главное:
`--dangerously-skip-permissions` + настройки и коннекторы пользователя по
умолчанию; судья исполняет свой код на хосте; телеметрия PostHog opt-out без
содержимого.

## Почему не ставим

1. Дублирует `claude plugin eval`, который у нас уже отлажен (frontmatter
   `name`, `--allow-tools`, `history_file`, бюджет на оба плеча).
2. Проверяет отдельные `SKILL.md`, а мы проверяем плагин целиком (агенты,
   хуки `cloud-memory`, `references/`).
3. В облачной сессии не проверен; нужен `pipx`, логин CLI внутри попытки.
4. Опасные умолчания (см. выше) для сотрудников с Gmail/Drive/Odoo.

## Когда пересмотреть

Если нужно сравнить MCP-сервер одним плечом (Context7, Firecrawl) и
`claude plugin eval` этого не умеет, или если понадобится сравнить движки
(Claude Code и Codex) на одной спеке.
