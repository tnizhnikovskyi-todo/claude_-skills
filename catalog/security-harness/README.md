## Что делает

Мультиагентный статический аудит безопасности приложения. Роутер `sh-router` отправляет
запрос либо в конвейер `sh-security-review` (recon → параллельные охотники по классам
уязвимостей → цепочки → верификация → отчёты README/JSON/SARIF/HTML/PDF), либо в
`sh-pr-review`: ревью одного PR с триажем по тирам, inline-комментариями на PR и commit
status как гейтом слияния. Знания по 15 классам (SQLi, XSS, IDOR, SSRF…) лежат в
скиллах `sh-kb-*`, которые раз в два дня обновляет агент в CI.

## Какую слабость Claude закрывает

Заявленно: ширину покрытия на большом коде (агент на класс), ложные срабатывания
(верификатор на opus), шум в PR (только то, за что отвечает PR, блокирует слияние).
Реально для нас: только второе и третье, и они уже в основном перенесены из Strix.
Знаний Odoo нет — KB про Express/Django/Spring/Rails.

## Как устроен

| Часть | Что внутри |
|---|---|
| `sh-router` | Таблица маршрутов: PR → `sh-pr-review`, кодовая база → конвейер, вопрос о классе → `sh-kb-*` |
| `sh-security-review` | Оркестратор Stage 0–5; модели по стадиям (recon sonnet, охотники haiku/sonnet/opus по тиру класса, chain/verify opus, report haiku) |
| Агенты | `sh-recon` (Graft-граф, SBOM, CVE, поверхность атаки), `sh-hunter` ×N (один класс, source→sink, ledger `attempts.md`), `sh-chainer`, `sh-verifier` («refute first», `verified` / `false-positive` / `needs-runtime`), `sh-reporter` |
| `sh-pr-review` | 8 фаз: резолв PR → триаж без агентов (Tier 0–3) → scoped recon → охотники по сработавшим классам → верификатор только на постящееся → цепочки → сборка, отпечатки, вердикт → постинг скриптом |
| `sh-kb-*` ×15 | Шаблон: когда искать, источники и синки, рецепт, PoC, фильтры ложных срабатываний, CWE/OWASP, chaining, mitigation |
| Скрипты | `sh-pr-post.py` (через `gh`: ревью + status, никогда не оставляет `pending`), `sh-review-cache.py` (локальный кэш, ключ включает хэш всех KB и модель), `sh-metrics.py` (локальные метрики) |
| CI | `update-knowledge-base.yml` (агент правит KB по allowlist доменов) → `kb-review-and-merge.yml` (агент-ревьюер, автослияние при APPROVE) |

**Сеть и права.** Скрипты без сетевого кода, телеметрии нет. Но Stage 0 сам ставит
глобальные инструменты (`npm install -g @nanonets/graft`, `curl … install.sh | sh` с `main`
вендора, допускает `sudo`), а `graft init` пишет в целевой репозиторий `.mcp.json`,
`.claude/settings.json` с хуками и скилл. `sh-pr-review` постит на PR и ставит commit
status **по умолчанию**, хотя его описание обещает «never posts without an explicit yes».
Подробно: `notes.md`.

## Риски и заметки

- Если когда-нибудь ставить плагин: только с пином коммита (не `main`, KB меняет агент),
  с отказом от Stage 0-установок и `graft init`, и `sh-pr-review` только с `--dry-run`
  или `--confirm`.
- Хорошая инженерная мысль, которую стоит запомнить: ключ кэша включает хэш всех KB и модель,
  «кэшированное чисто не должно подавлять находку, ради которой обновили KB».
- Чем отличается от `independent-check` и почему это не меняет вывода — `notes.md`,
  раздел «Почему мультиагентность тут другая».
- По скиллам подробно: `items/`.
