# sh-security-review + агенты (конвейер полного аудита)

- **Источник:** `plugins/security-harness/skills/sh-security-review/SKILL.md@68748d5`,
  `plugins/security-harness/agents/*.md@68748d5`
- **Вердикт:** отклонить

## Что делает

Stage 0 (оркестратор: установка инструментов, `scope.json`, выбор моделей) → recon (Graft,
SBOM, CVE, поверхность атаки) → охотники параллельно, по одному на класс, каждый грузит
свой `sh-kb-*` и пишет `findings.jsonl` + ledger `attempts.md` → chainer (opus) → verifier
(opus: сначала опровергнуть, потом построить payload/PoC, CVSS) → reporter (haiku, JSON и
SARIF скриптом). Агенты общаются только файлами (`references/state-files.md`).

## Что в нём хорошего

- Тиринг моделей по нагрузке: дешёвые классы-паттерны на haiku, логика доступа на opus.
- Ledger `attempts.md`: охотники пишут и «чисто» тоже — заодно таблица покрытия.
- Верификатор не удаляет ложные срабатывания, а оставляет с причиной (аудит-след).
- Отчёт в JSON/SARIF генерирует скрипт, а не модель.

## Почему отклонить

- Всё из «хорошего», что влияет на качество, у нас уже есть из Strix (closure states,
  coverage table, «downgrade, don't delete»).
- Stage 0 ставит глобальные пакеты и `curl | sh` без вопроса, `graft init` пишет хуки и MCP
  в целевой репозиторий.
- Нет знаний Odoo: recon ищет роуты Express/Flask/Spring, а не `@http.route`,
  `ir.model.access.csv`, `ir.rule`.
- Цена: до ~20 субагентов на прогон; на дифах `td.*` один агент уже на потолке.
- Мультиагентность здесь — разделение по ширине (класс на агента), а не «второй взгляд»
  как в `independent-check`. Польза возможна на полном аудите большого кода, но автор её
  не мерил, а у нас такой задачи пока нет.
