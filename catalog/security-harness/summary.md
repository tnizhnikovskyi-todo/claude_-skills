# security-harness — summary для главной сессии

**Что это.** Плагин Claude Code (MIT, ★42, один автор, 34 коммита авг–сен 2026, evals нет):
мультиагентный статический аудит безопасности. Конвейер recon → охотник на каждый из 15
классов уязвимостей (`sh-kb-*`) → chainer → verifier (opus) → отчёты/SARIF; плюс
`sh-pr-review` — ревью PR с триажем по тирам, inline-комментариями и commit status как гейтом.

**Чем отличается от `independent-check`.** Агенты делят ширину (класс на агента, модели по
тирам ради цены), а не перепроверяют одно и то же. Может помочь на полном аудите большого
кода, но автор качество не мерил, Odoo-знаний нет, а на наших дифах `td.*` наш
`security-review` уже 15/15 одним агентом. Ожидаемый прирост ≈ 0 при цене ×5–10.

**Лучшие находки (сверх уже перенесённого из Strix):**
1. Дополнение к нашим трём меткам (`pr-review` уже имеет regression / newly reached / pre-existing): ещё 3–4 критерия «усугубил» из закрытого списка `aggravated`, правило на сомнение (у них «→ pre_existing», у нас обратный уклон — решать A/B),
   `introduced` = строка добавлена **или стоит в функции с добавленной строкой». Последнее
   закрывает открытый вопрос P2 из `SCORES.md`.
2. Дешёвый триаж без агентов по добавленным строкам → тир → сколько агентов звать. У нас →
   правило запуска critic round с Odoo-сигналами.
3. Стиль находки: механизм вместо категории, фикс кодом, без хеджей (таблица «slop»).
