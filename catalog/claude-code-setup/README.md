# claude-code-setup

- **Тип:** плагин из одного скилла (`claude-automation-recommender`)
- **Источник:** https://claude.com/marketplace/plugins/claude-code-setup,
  код: https://github.com/anthropics/claude-plugins-official/tree/a7ba5b93db0c7c8d17f3f1d25853adca79598a1a/plugins/claude-code-setup
- **Версия / коммит:** 1.0.0 / `a7ba5b9` (2026-10-30)
- **Дата разбора:** 2026-11-02
- **Вердикт:** адаптировать (как есть — только для разового аудита)

## Что делает

По запросу вроде «recommend automations for this project» или «help me set up
Claude Code» Claude смотрит на репозиторий (`package.json`, `pyproject.toml`,
`.claude/`, `CLAUDE.md`, структуру папок) и выдаёт отчёт: по 1–2
рекомендации в каждой категории — MCP-серверы, скиллы, хуки, субагенты,
плагины. Если спросить про одну категорию, рекомендаций будет 3–5. Файлы
скилл не меняет: внедрять рекомендации предлагается отдельным запросом.

## Какую слабость Claude закрывает

Слабо закрывает одну: без подсказки Claude не перебирает все механизмы
расширения Claude Code системно. Скилл даёт чек-лист «признак в репо →
автоматизация» и формат отчёта. Новых инструментов и данных он не добавляет.

## Как устроен

| Компонент | Есть? | Подробности |
|---|---|---|
| Скиллы | 1 | `claude-automation-recommender`, 289 строк, + 5 справочников (~1 200 строк), грузятся по ссылке по мере надобности |
| Команды | нет | |
| Агенты | нет | |
| Хуки | нет | |
| MCP | нет | |
| Скрипты | нет | Только примеры `ls`/`cat` в тексте SKILL.md |

- Права: во frontmatter стоит `tools: Read, Glob, Grep, Bash`. Это
  нестандартное поле, поэтому «только чтение» обеспечено текстом
  инструкции, а не ограничением прав.
- Сеть: скилл велит использовать веб-поиск для рекомендаций под стек.
  Наружу уходят только поисковые запросы с названиями библиотек.
- Что меняет: ничего. Отчёт печатается в чат.
- Разбор справочников: [`items/claude-automation-recommender.md`](items/claude-automation-recommender.md).
- Полный текст оригинала: [`source/SKILL.md`](source/SKILL.md).

## Сравнение с тем, что у нас есть

| Наш скилл | Связь |
|---|---|
| `init` | Делает другое: пишет `CLAUDE.md`. Recommender его не создаёт |
| `update-config` | Дополняет: recommender советует хук, `update-config` его ставит |
| `fewer-permission-prompts` | Recommender даёт только общий пример `permissions.allow`; наш скилл строит allowlist по реальным транскриптам и полезнее |
| `session-start-hook` | Recommender не знает про SessionStart и облачные сессии |
| `plugin-authoring` | Почти не пересекается |

Сверх наших: обзор всех категорий сразу и готовая таблица признаков. Но он
не видит уже установленных у нас плагинов и коннекторов и легко предложит
дубли (`code-review`, GitHub MCP, docx/pdf).

## Риски и заметки

- Сильный уклон в JS/фронтенд; Odoo не упомянут вообще.
- Примеры уведомлений только для macOS (`afplay`, `osascript`) и
  бесполезны в облачной сессии.
- Описание широкое («mentions improving Claude Code workflows») и может
  сработать на вопросах, где нужен `update-config`.
- Если всё же ставить для разового аудита:
  `/plugin install claude-code-setup@claude-plugins-official`
  (официальный маркетплейс подключён в Claude Code по умолчанию).
- Что адаптировать: свой скилл `repo-automation-audit` = таблица признаков
  отсюда + наш стек (pylint-odoo, pre-commit, `odoo-connector`,
  `session-start-hook`) + обязательная сверка с `inventory/current.md`,
  чтобы не советовать дубли.
