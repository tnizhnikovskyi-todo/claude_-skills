## Что делает

Набор скиллов бизнес-аналитика по BABOK v3, Agile Extension v2,
ISO/IEC 25010:2023, ISTQB, ISO/IEC/IEEE 29148: от стейкхолдер-анализа и
бизнес-кейса до тест-кейсов и сборки BRD/PRD/SRS. Тексты на английском,
отвечают на языке пользователя. Общая сквозная договорённость: метки
происхождения `[Stated]` / `[Inferred]` / `[Assumption]`, стабильные ID
(`GOAL-`, `FR-`, `US-`, `AC-`, `BR-`, `NFR-`, `TC-`, `SH-`), свой ID
помечается «proposed», чужие коды не выдумываются.

## Какую слабость Claude закрывает

Главная — **выдумывание**: людей, ролей, отношений, чисел, ID, ссылок,
ожидаемых результатов тестов. Почти у каждого скилла есть «Hard rules»
против этого, включая «ловушки» (пользователь сам просит придумать —
вежливо отказать). Вторая — пропуски: чек-лист стандартных ролей BABOK,
признаки неполного списка стейкхолдеров, вариант «ничего не делать» в
бизнес-кейсе.

## Как устроен

Каждый скилл: `SKILL.md` 37–57 строк (правила + процесс + режимы),
подробности в `references/` и `templates/`, грузятся по необходимости.
Блок «Conventions» одинаковый во всех 11 (проверяет `scripts/validate.py`).
Перекрёстные ссылки «если установлен» — каждый скилл работает отдельно.
Скрипт один: `business-case-strategy/scripts/fin.py` (stdlib, без сети).
Хуков, MCP, телеметрии нет. `evals/run.py` вызывает `claude -p`, только
вручную.
