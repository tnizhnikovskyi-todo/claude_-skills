# arena-skill: сводка

- **Что это:** скилл `/arena`. N субагентов (по умолчанию 100, `--quick` 16) решают одну задачу с разными
  «карточками» (15 способов рассуждения × 12 порядков работы × 12 стратегий), потом турнир на выбывание:
  атака → защита с правкой → судья по взвешенной рубрике. Бухгалтерия в `bracket.py` (stdlib, тесты).
- **Чем силён:** метод + проверка. Разнообразие подходов вместо одинаковых retry, состязательный
  поиск контрпримеров, судья перепроверяет атаки. Главный контекст почти не тратится, а прогон
  возобновляется после компактизации. Финальный слепой судья против отвергнутого ответа честно говорит,
  если старый ответ лучше.
- **Чем плох:** цена. 595 вызовов субагентов (~20–45 млн входных токенов по нашей оценке, 70 волн) за
  один ответ; 100 копий одной модели не дают 100 независимых взглядов; шум судьи за 7 раундов. Широкий
  триггер («try again»). Граница записи `.arena/` держится только на промпте, субагенты `general-purpose`.
- **Безопасность:** код прочитан, сети и подпроцессов нет. Оценка 2/3.
- **Оценка:** 10/18 (прирост 2, частота 1, надёжность 2, контекст 2, безопасность 2, поддержка 1).
- **Вердикт:** адаптировать. Взять `strategies.json`, `rubric.md`, шаблоны атакующего/защитника/судьи
  и финальное слепое сравнение. Собрать свою «арену-лайт» на 4–8 агентов и 1–2 раунда (или как
  Workflow-скрипт), запуск только явной командой, агенты без права править проект.
- **У нас аналога нет:** `workflow-authoring` даёт механику оркестрации, `code-review` только для кода.
