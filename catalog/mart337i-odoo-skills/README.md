## Что делает

21 скилл для Odoo-разработки: справочники по версиям 17/18/19/20 (по 18
руководств: модели, поля, декораторы, вью, права, тесты, контроллеры,
отчёты, OWL, миграции и т.д.), методы ревью, трассировки вызовов,
написания тестов, веб-безопасности, отчётов, OCA-миграции, проверки
идеи модуля, плюс четыре общих скилла (grill-me, архитектура, zoom-out).
Около 49.5 тыс. строк markdown, кода в скиллах нет.

## Какую слабость Claude закрывает

Заявлено: модель путает версии Odoo и пропускает специфику (права,
`sudo()`, мультикомпания, порядок загрузки XML). Наша измеренная слабость
(`synthesis.md` п.3) — факты новой версии: модель пишет удалённое в 19.0.
Справочник Odoo 19 закрывает её **частично**: новые API 19.0 описаны верно,
но в 9 из 19 проверенных мест он сам учит устаревшему или неверному
(подробно в `notes.md`).

## Как устроен

- `skills/<имя>/SKILL.md` + справочные файлы рядом (progressive disclosure:
  руководства 244–642 строки грузятся по ссылке из таблицы).
- Маршрутизатор `odoo` с широким триггером («пользователь упомянул Odoo»)
  раздаёт задачи остальным скиллам.
- Переменные окружения `ODOO_SOURCE`, `ODOO_BASE_COMMAND`,
  `ODOO_TOOL_README`: «смотри исходник, а не память» и «спроси перед
  командой, которая трогает БД».
- Установщик `bin/odoo-skills.js` копирует все скиллы в `~/.claude/skills`
  и `~/.config/opencode/skills`, одноимённые переносит в бэкап.
  `scripts/link-skills.sh` делает симлинки и **удаляет без бэкапа**
  существующие одноимённые папки. Сети, хуков, телеметрии нет. Не
  запускали.

утверждений справочника с исходниками `odoo/odoo@19.0` (`e0b25b7`):
10 верны, 9 ошибочны.

| Задача | Без него | С ним |
|---|---|---|
| JSON-маршрут в Odoo 19 | — (не мерили) | научит `type='json'` (устаревший алиас, верно `jsonrpc`) |
| Тест с пользователем в группе | — | `groups_id` → падение (в 19.0 `group_ids`) |
| Хуки манифеста | — | `'module.hook'` → `AttributeError` |
| SQL-ограничение | — | верно: `models.Constraint` |
| Группы и привилегии | — | верно: `res.groups.privilege` |
