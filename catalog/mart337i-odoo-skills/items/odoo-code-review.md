# odoo-code-review

- **Путь:** `skills/odoo-code-review/` — `SKILL.md` (145 строк) +
  `ODOO-CODING-GUIDELINES.md` (317 строк, пересказ официального гайда)
- **Вердикт:** **адаптировать 2–3 идеи** в `odoo19-mvp-build:pr-review`

## Что это

Ревью Odoo-кода: сначала определить версию, модуль, диапазон диффа,
стабильная ли ветка, есть ли локальные исходники; затем чек-лист по
разделам (ORM, поля и декораторы, XML и данные, права, контроллеры и
отчёты, производительность и транзакции, тесты/миграции/манифест) и
вывод «находки по важности → открытые вопросы → что проверено →
остаточный риск → итог». Необязательная взвешенная оценка по просьбе.

## Сверх нашего (по описаниям; текст `pr-review` недоступен)

- **Правило стабильной ветки:** на стабильной ветке не просить
  рестайлинг, стиль файла важнее общего гайда; на ветке разработки гайд
  применять шире.
- **Обязательные блоки «Checks run» и «Residual risks»** — явное «что не
  смотрел». Совпадает с нашим принципом №28 и блоком «Где не искал» в
  `odoo-model-map`.
- Связка «неясен путь выполнения → трассировщик; слабые тесты → скилл
  тестов».

## Хуже / дублирует

- Чек-лист общий и версионно-нейтральный: про 19.0 почти ничего
  (`_read_group`/`read_group` «по версии», «синтаксис для версии»).
  Ловушки 19.0 (`group_ids`, `jsonrpc`, нет `@api.returns`) не названы.
- Формат находки беднее 4-частного (ponytail), который уже решено
  добавить в `pr-review`.
- Пересказ официального coding guidelines — модель знает и так.

## Что взять

В `pr-review`: (1) правило стабильной ветки; (2) обязательные разделы
«что проверено / что не проверено / остаточный риск»; (3) пункт
«версионные ловушки — сверить с файлом ловушек 19.0 из source-check».
Своими словами.
