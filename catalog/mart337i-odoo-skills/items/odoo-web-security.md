# odoo-web-security

- **Путь:** `skills/odoo-web-security/` — `SKILL.md` (~30 строк) +
  `references/SECURITY-CHECKLIST.md` (39 строк)
- **Вердикт:** **взять формат находки** в `security-review`

## Что это

Ревью веб-границы Odoo: сначала модель угроз (кто вызывает, режим
`auth`, какая запись, какое изменение, что уходит в браузер), всё из
запроса — недоверенное. Чек-лист по пяти границам: маршрут, запись, ввод,
вывод, браузер (CSRF, токены не в URL и логах, `innerHTML`, проверка
анонимом/порталом/внутренним/чужой компанией).

## Сверх нашего

- **Формат находки:** атакующий → точка входа → недостающий контроль →
  затронутые данные/действие → конкретный тест, который падает до
  исправления. Сильнее, чем просто «severity + fix»: сразу даёт
  регресс-тест.
- Пункт «отказ в доступе и отсутствие записи неразличимы, если важна
  перечислимость» — легко забывается.

## Хуже

- Про `type='json'` vs `jsonrpc` в 19.0 ничего; общий, не версионный.
- Пересекается с `anthropic-skills:security-review` (чек-лист Odoo) и
  перенесённой методологией Strix.

## Что взять

В `security-review`: формат находки с падающим тестом и пункт про
неразличимость «нет доступа / нет записи» для портальных маршрутов.
