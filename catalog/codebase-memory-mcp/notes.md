# codebase-memory-mcp: рабочий журнал

## 2026-11-02, первичный разбор

### Как нашли репозиторий и почему это он

- В `catalog/headroom-desktop/items/addons.md` аддон указан прямой ссылкой:
  `https://github.com/DeusData/codebase-memory-mcp` («Граф знаний по кодовой
  базе, постоянный», MCP). В `catalog/headroom-desktop/README.md` упомянуто,
  что headroom скачивает «бинарники rtk / codebase-memory с GitHub»; это
  совпадает: проект распространяется нативными бинарниками в GitHub Releases.
- Поиск GitHub (`search/repositories`, `repo:DeusData/codebase-memory-mcp`)
  подтвердил: репозиторий существует, MIT, ~48k звёзд, ~3,9k форков,
  создан 2026-02-24, последний пуш 2026-11-02. Имя пакета npm/PyPI
  `codebase-memory-mcp`, `mcpName: io.github.DeusData/codebase-memory-mcp`.
  Других проектов с этим именем, на которые мог бы ссылаться headroom, нет.

### Что смотрели

Клон в scratchpad (вне репо), коммит `a5b248f` (2026-11-01), последний тег
`v0.12.1` (2026-10-16). Ничего не запускали.

- `README.md` (1190 строк) целиком по разделам: установка, демон, Auto-Index,
  инструменты MCP, модель графа, Cypher, конфигурация, Hybrid LSP, языки,
  безопасность, производительность.
- `.claude-plugin/marketplace.json`, `plugin/.claude-plugin/plugin.json`,
  `plugin/.mcp.json`: плагин Claude Code регистрирует только MCP через
  `npx -y codebase-memory-mcp@0.12.1`.
- `pkg/npm/install.js`: postinstall качает архив с GitHub Releases
  (`releases/download/v<версия>`), проверяет SHA-256 по `checksums.txt` из
  того же источника.
- `src/cli/cli.c`: встроенный текст скилла `codebase-memory` (~60 строк,
  ~1k токенов), установка хуков Claude Code; функции скачивания
  (`curl` через `cbm_exec_no_shell`, только https, вызываются из update).
- `src/cli/hook_augment.c`: логика хука, добавляющего символы графа к
  Grep/Glob/Bash; лимиты токена запроса, дедлайн до 10 с, fail-open.
- Сеть: grep по `src/` на `connect(`, `getaddrinfo`, URL. Сокеты только
  `AF_UNIX` (IPC демона в `src/daemon/ipc.c`) и loopback HTTP для UI.
  `https://` в `http_server.c` строит ссылку на GitHub blob для UI, это не
  запрос. Внешние запросы: только `curl` в пути обновления/установки.
- Запуск процессов: `popen` для `git log`/`git` (история изменений,
  артефакт), `ps` в UI. Shell-строк с пользовательским вводом не нашли
  (поверхностно).
- `docs/BENCHMARK.md`: Python (django) 87%, 10.5/12; бенчмарк от 2026-03-01
  (v0.3.0), вопросы и оценка самих авторов.
- Odoo: `grep -i odoo` по `src/` и `internal/cbm` ничего не дал. Спецподдержки
  Odoo нет.

### Объём и активность

- ~5,1k коммитов за 8 месяцев, ~1,6k коммитов только с 2026-10-01.
- Основной автор Martin Vogel (~2,5k коммитов), далее Bernhard Jackiewicz
  (UI, ~190), остальные единицы–десятки. Bus factor фактически 1–2.
- 565 открытых issues/PR (по данным поиска GitHub).
- Репозиторий 1,7 ГБ, из них 1,3 ГБ `internal/` (вендоренные грамматики).
  Весь C-код прочитать невозможно, смотрели выборочно: CLI-установщик,
  хуки, сеть.

### Открытые вопросы (нужно испытание, запуск чужого бинарника)

1. Время индексации в нашем облачном контейнере: кастомные модули Odoo
   (ожидаем секунды) и ядро Odoo 19 (оценка: десятки секунд — минута-две по
   аналогии с Django ~6 с на M3 Pro, но у нас меньше CPU).
2. Что видно в графе для Odoo: `_inherit = 'sale.order'` (строка, а не
   класс), `self.env['res.partner']`, `super()` в цепочке наследования
   моделей, XML-вью/записи и связь с Python-моделями. Ожидание: наследование
   моделей Odoo граф не видит, XML разбирается только как разметка.
3. Работает ли MCP в облачной сессии через `npx` (нужен доступ к npm и
   github.com releases в сетевой политике) или проще ставить бинарник
   setup-скриптом.
4. Сколько токенов реально уходит на схемы 17 инструментов (в Claude Code
   MCP-инструменты, вероятно, откладываются через ToolSearch).
5. Сравнение с serena: ветка `analysis/serena` на момент разбора ещё не
   запушена; сравнение дано по общему знанию о serena, перепроверить по её
   карточке.
