# codebase-memory-mcp: сводка для главной сессии

- **Что это:** MCP-сервер DeusData (MIT, ~48k звёзд, очень активный): нативный
  C-бинарник индексирует репозиторий в постоянный граф (SQLite в
  `~/.cache`), tree-sitter 162 языка + свой вывод типов для Python и ещё 10
  языков. 17 инструментов: поиск, `trace_path` (кто вызывает / что вызывает),
  `detect_changes` (влияние диффа), Cypher, обзор архитектуры.
- **Сеть:** индексация и запросы локальные, телеметрии нет (подтверждено
  грепом: только Unix-сокеты и loopback UI); внешний трафик только при
  установке/обновлении с GitHub Releases. SLSA 3, cosign, SHA-256.
- **Лучшая находка:** плагин Claude Code, регистрирующий только MCP с
  пином версии (`npx -y codebase-memory-mcp@0.12.1`); `detect_changes` и
  `trace_path` — то, чего нет ни в graphify, ни в grep.
- **Минусы:** `install` правит конфиги 45 агентов и ставит always-on хуки на
  Grep/Glob/Bash; в облаке индекс теряется, переиндексация на каждом старте
  (секунды для модулей, оценочно минуты для ядра Odoo); спецподдержки Odoo
  нет (строковый `_inherit`, `env['…']`, XML-вью, вероятно, не видны).
- **Сравнение:** как MCP для кода сильнее graphify (быстрее, инкрементальный,
  дешевле по контексту); с serena скорее дополняют друг друга (граф вызовов
  против точных LSP-символов и правки), брать один по итогам испытания.
- **Оценка:** 13/18. **Вердикт: адаптировать** — только сервер с пином,
  вручную в `.mcp.json`, без `install`/хуков; свой короткий скилл на основе
  их ~1k-токенного.
- **Открыто:** испытание на Odoo-модуле и ядре Odoo 19 в облаке (нужно
  разрешение на запуск бинарника), сверка с карточкой serena.
