## Что делает

Для каждой прямой зависимости проекта ищет признаки риска захвата или
эксплуатации и пишет таблицу только по рискованным.

## Критерии риска

1. Один мейнтейнер или маленькая группа без организации; анонимный хуже.
2. Не поддерживается: давно нет коммитов, архив, «ищем мейнтейнеров»,
   висят баги безопасности без ответа.
3. Низкая популярность относительно остальных зависимостей.
4. Рискованные возможности: FFI, десериализация, выполнение чужого кода.
5. Прошлые CVE высокой важности (с поправкой на популярность).
6. Нет контакта для сообщений об уязвимостях (`SECURITY.md`).

Числа (звёзды, issues) — только через `gh`, «важно, чтобы цифры были
точными». Для каждой рискованной — предложить альтернативу.

## Сравнение с нашим

Наш `criteria.md` «Поддержка» = «заброшен / активно поддерживается».
Это одна шкала, а у ToB шесть конкретных признаков. Они же подходят для
оценки самих кандидатов на разбор (скилл/плагин/MCP — та же
зависимость). Для Odoo-модулей зависимости — `external_dependencies` в
манифесте и OCA-аддоны.
