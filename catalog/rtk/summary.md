# rtk — сводка для главной сессии

- **Что это:** Rust-бинарник + `PreToolUse`-хук на Bash: переписывает `git status`,
  `pytest`, `npm test`, `grep` и ещё ~100 команд на `rtk <cmd>` и отдаёт Claude сжатый
  вывод. Работает в облаке: нужен только бинарник в `PATH` и хук в `settings.json`.
- **Вердикт:** **адаптировать (пилот)**, 14/18. Код прочитан, сеть и телеметрия
  opt-in (`RTK_TELEMETRY_DISABLED=1` на всякий случай). Есть сборка `rtk-oss` (только
  Apache-2.0).
- **Авто-`allow`:** в отличие от Headroom, сам rtk выдаёт `allow` только при совпадении
  явного allow-правила пользователя; иначе решение за Claude Code. Не проблема.
- **Главный риск — тихие потери:** `find` → `rtk find` прячет скрытые и gitignored файлы;
  `git diff/show/log` урезаются (с пометками); `grep` и тесты режутся по лимитам; в
  1660 открытых issues много багов «строка пропала». Плюс их `RTK.md` велит Claude
  считать вывод полным — не ставить.
- **Как взять:** setup-скрипт с пином `v1.1.0` + SHA-256 (готов в `README.md`), конфиг с
  `exclude_commands = ["^find","^cat","^head","^tail",…]`, хук `rtk hook claude` без
  `rtk init`, строка в `CLAUDE.md` про `rtk bypass`.
- **Чего не хватает:** A/B на наших задачах (не запускали без разрешения). Реальная
  экономия неизвестна: хук не трогает `Read`/`Grep`, а Claude в облаке чаще пользуется ими.
- **Рекомендация хабу:** задача в `roadmap.md` — пилот на 1 окружении с A/B (5–10 задач).
