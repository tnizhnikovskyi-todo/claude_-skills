# rtk (Rust Token Killer)

- **Тип:** CLI-бинарник (Rust) + `PreToolUse`-хук для Claude Code
- **Источник:** https://github.com/rtk-ai/rtk
- **Версия / коммит:** код читали на `develop` @ `22812af6` (2026-11-02); последний релиз `v1.1.0` (2026-10-25). Логику хука и телеметрии сверили с `v1.1.0` — совпадает.
- **Дата разбора:** 2026-11-02
- **Вердикт:** **адаптировать (пилот)** — ставить OSS-сборку с пином версии и SHA-256, без `rtk init`, с исключениями для `find`/`cat`/`head`/`tail`, с выключенной телеметрией. Перед массовым внедрением нужен A/B на наших задачах (не проводился: чужой бинарник без разрешения не запускали).

## Что делает

Хук `PreToolUse` на `Bash` переписывает команду агента (`git status` → `rtk git status`,
`pytest` → `rtk pytest` и т. д.). `rtk` запускает настоящую команду и печатает сжатый
вывод: тесты — только упавшие, `git log` — хэш/автор/тема, `git diff` — статистика плюс
урезанные ханки, `grep` — сгруппировано по файлам с лимитами, лог-строки дедуплицируются.
~100 правил переписывания (`src/discover/rules.rs`) + ~60 TOML-фильтров (`src/filters/`).
Встроенные инструменты Claude (`Read`, `Grep`, `Glob`) хук **не трогает** — только Bash.

## Какую слабость Claude закрывает

Шумный вывод Bash (тесты, сборки, `npm install`, `git log/diff`, `docker`, `kubectl`)
съедает контекст и деньги. Это единственный найденный вариант сжатия, который работает
в облачных сессиях: нужен только бинарник в `PATH` и хук в `settings.json`, без прокси
и аккаунта. Качество ответов Claude он не повышает — только экономит контекст.

## Как устроен

| Часть | Где | Что делает |
|---|---|---|
| Правила переписывания | `src/discover/rules.rs`, `registry.rs` | regex по началу команды → `rtk <cmd>`; лексер отказывается переписывать «непрозрачные» конструкции (`contains_unattestable_construct`) |
| Решение хука | `src/hooks/decision.rs`, `permissions.rs` | читает `permissions` из `settings.json` Claude: deny → не трогает; ask/нет правила → переписывает **без** `permissionDecision` (решает сам Claude Code); `allow` выдаёт **только если совпало явное allow-правило пользователя** |
| Хук для Claude | `rtk hook claude` (нативный) или `hooks/claude/rtk-rewrite.sh` (bash+jq → `rtk rewrite`) | возвращает `updatedInput` с новой командой; при любой ошибке молча `exit 0` (fail-open) |
| Фильтры | `src/cmds/**`, `src/filters/*.toml` | парсинг вывода конкретных утилит |
| Восстановление | `src/core/retriever.rs`, `tee.rs` | полный вывод упавших команд кладёт в локальную SQLite, в выводе подсказка `[full output: rtk recall <hash>]`; урезанный `git show`/`diff` даёт подсказку `rtk proxy git …` |
| `rtk bypass <cmd>` / `RTK_DISABLED=1` | | прогон без фильтра |
| Учёт | `~/.local/share/rtk/history.db` | локальная статистика (`rtk gain`), 90 дней |
| PostToolUse, `pipeline.toml`, `rtk-proxy` | `engine/` (BUSL-1.1), `proxy/` | опционально, по умолчанию выключено; нам не нужно |

### Сеть

`ureq` используется только в: телеметрии (см. ниже), `rtk pipeline` (скачивание
`pipeline.toml` с GitHub/gist по явной команде), `rtk task` и классификаторах
`[classifier.*]` (шлют фрагмент вывода во внешний LLM **только** если пользователь сам
настроил pipeline с API-ключом), `rtk llm-proxy` (localhost). При обычной работе хука
сети нет.

**Телеметрия:** URL и токен вшиваются при сборке (`option_env!`), без согласия
(`consent_given = true` в `config.toml`) пинг не идёт; согласие спрашивает только
интерактивный `rtk init`. `RTK_TELEMETRY_DISABLED=1` блокирует всё. Шлёт раз в 23 ч
агрегаты (имена утилит, счётчики, хэш устройства), без аргументов и путей. В официальном
релизе URL вшит — поэтому ставим env-переменную на всякий случай.

### Лицензия

Двойная. CLI `rtk` — Apache-2.0, но полная сборка линкует `rtk-engine` (BUSL-1.1,
Additional Use Grant: бесплатное production-использование, нельзя продавать как сервис;
переход в Apache-2.0 в 2030-09-09). Есть сборка **`rtk-oss`** — только Apache-2.0, все
фильтры на месте, нет лишь движка `pipeline.toml`/PostToolUse. Нам подходит `rtk-oss`.

## Что теряется (риск «Claude не увидел строку»)

| Команда | Что делает rtk | Риск |
|---|---|---|
| `cat/head/tail` → `rtk read` | по умолчанию `--level none`: **полный текст** | почти нет; выгоды тоже нет. README обещает «signatures over bodies» — это только при `-l aggressive` |
| `git diff` / `git show` | `--stat`, затем ханки ≤100 строк, весь дифф ≤500 строк, контекст урезан; blob в `git show HEAD:file` режется на 8 КБ | **средний**: помечает `... (N additions truncated)` и даёт команду для остатка, но Claude может принять урезанный дифф за полный |
| `git log` | хэш, автор, тема; тело коммита отбрасывается, есть лимит | средний для разбора истории |
| `find` → `rtk find` | **уважает `.gitignore` и пропускает скрытые файлы**, лимит выдачи (`+N more`) | **высокий**: меняет семантику `find` — не найдёт `.github/`, `.env*`, игнорируемые артефакты (issue #2995, #3432) |
| `grep`/`rg` | группировка, лимит на файл и всего, обрезка длинных строк | средний: есть счётчики `+N more`, но строки за лимитом не видны |
| `pytest`/`cargo test`/`jest`/`vitest`/`go test` | только упавшие + счётчик | низкий–средний: открыты баги со скрытием строк диффа `E` (#4749), потерей итоговых строк в составных командах (#1035) |
| коды выхода | сохраняются в целом, но есть открытые инверсии (#3432, #4818) | средний |

Отдельно: awareness-текст, который `rtk init` добавляет в `CLAUDE.md` (`@RTK.md`), велит
«Treat it as the complete result» — подавляет здоровое недоверие к урезанному выводу.
**Его не ставим.**

Проект огромный и быстрый (85k звёзд, 1660 открытых issues, ~1100 коммитов за 3 мес.);
много issues именно про тихую потерю данных в фильтрах — их чинят, но появляются новые.

## Как поставить в облачное окружение (пилот)

**1. Setup-скрипт окружения** (настройки облачного окружения, не репозиторий):

```bash
# rtk-oss v1.1.0, Apache-2.0, пин версии и хэша (сверено 2026-11-02 с checksums.txt релиза)
set -euo pipefail
RTK_VER=v1.1.0
RTK_SHA=4dec94a64035e08189ae82fd5408fe4ae9ae27a665fc07e3e3ec3c4c2d8e8a3e
T=$(mktemp -d)
curl -fsSL -o "$T/rtk.tgz" \
  "https://github.com/rtk-ai/rtk/releases/download/$RTK_VER/rtk-oss-x86_64-unknown-linux-musl.tar.gz"
echo "$RTK_SHA  $T/rtk.tgz" | sha256sum -c -
tar -xzf "$T/rtk.tgz" -C "$T"
install -m 0755 "$T/rtk" /usr/local/bin/rtk   # архив: rtk + LICENSE (проверено)
mkdir -p ~/.config/rtk
cat > ~/.config/rtk/config.toml <<'EOF'
[hooks]
exclude_commands = ["^find", "^cat", "^head", "^tail", "git rebase", "git cherry-pick"]

[telemetry]
enabled = false
consent_given = false
EOF
rm -rf "$T"
```

И переменная окружения `RTK_TELEMETRY_DISABLED=1` в настройках окружения.
Не запускать `rtk init` (интерактивный, правит `~/.claude/settings.json` и `CLAUDE.md`).

**2. Хук** в `.claude/settings.json` целевого репозитория (или в user settings окружения):

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          { "type": "command", "command": "command -v rtk >/dev/null 2>&1 && rtk hook claude || true" }
        ]
      }
    ]
  }
}
```

Нативный `rtk hook claude` выдаёт `allow` только при совпадении **явного** allow-правила из
`permissions` (иначе решение остаётся за Claude Code), deny-правила уважает. Если нужна
полная гарантия «никаких allow от хука» — вместо него тонкая обёртка над `rtk rewrite`,
которая всегда отдаёт только `updatedInput` без `permissionDecision` (≈15 строк, см. `notes.md`).

**3. Строка в `CLAUDE.md` проекта** (вместо их `RTK.md`):
«Вывод Bash может быть сжат rtk. Если видишь `truncated`, `+N more` или `[full output: rtk recall …]`
и нужна полнота — перезапусти через `rtk bypass <cmd>`.»

## Риски и заметки

- Переписанная команда видна в транскрипте как `rtk …`; Claude может начать вызывать `rtk`
  сам — это нормально.
- Hook работает только для Bash: на `Read`/`Grep` экономии нет. Claude Code в облаке чаще
  пользуется встроенными инструментами, поэтому реальная доля сжимаемого вывода меньше
  рекламной — именно это и надо измерить.
- Обновлять пин осознанно: проект меняется ежедневно, правила и лимиты фильтров дрейфуют.
- Сравнение: в `inventory/current.md` ничего похожего нет; Headroom/OmniRoute используют
  rtk внутри, но как прокси/десктоп — для облака неприменимы.
