## Что делает

Украиноязычный скилл: машинный транскрипт встречи или сырые заметки превращает в
короткий «actionable follow-up» по рамке ARCV+ (Actions, Responsible, Clearly,
Verbs доконаного виду) с отдельными блоками «Рішення» и «Відкриті питання».
Перед стартом одним вопросом спрашивает режим вывода (общий follow-up, проблемы и
решения, задачи по исполнителям, полные технические детали; словами: ретро АПД,
одна тема, сообщение участнику). Вывод — plain text без markdown для вставки в
Telegram, почту, Worksection. Гипотеза из поиска **подтверждается**: язык
украинский, правило «одно действие — один владелец» — центральное.

## Какую слабость Claude закрывает

- Модель по просьбе «сделай итог» пересказывает ход разговора, а не «кто что делает».
- Придумывает сроки («до конца недели» → конкретная дата) и считает относительные
  сроки от неверной даты встречи.
- Верит меткам спикеров; при перепутанных метках действия уходят не тем людям.
- Молча «достраивает» искажённое ASR слово правдоподобным синонимом.
- Возвращает markdown во второй и следующих ответах, хотя первый был чистым.

## Как устроен

- `SKILL.md` (595 строк, ~29 тыс. символов кириллицы, по оценке 12–15 тыс. токенов
  при каждом срабатывании). Шаги: 0 — вопрос о режиме; 1 — восемь сущностей
  (тема, дата, участники, упомянутые, контекст, решения, действия, открытые
  вопросы); 2 — формула действия; 3 — раскладка по блокам; 4 — сборка; чек-лист
  самопроверки из 9 пунктов; стоп-листы UA/EN; шесть режимов вывода; пример.
- `references/roster.example.md` — образец справочника людей
  (`каноническое имя | варианты в транскриптах | роль | сторона`); настоящий
  `roster.md` в `.gitignore`.
- `references/SKILL.en.md` — полный английский перевод (в модель не грузится).
- `scripts/check_docs.py`, `scripts/selftest_checks.py` — проверка согласованности
  документации для контрибьюторов (паритет перевода, нет контактов, `roster.md` не
  закоммичен) и самотест чекера на 8 видах дрейфа. Читают файлы, вызывают только
  `git ls-files`/`git init` во временной копии. **Не запускались.**
- CI: GitHub Actions, `permissions: contents: read`.
- Сеть, телеметрия, хуки, MCP: **нет**. Скилл ссылается на внешние скиллы
  `humanizer` / `anthropic-skills:stop-slop` — у нас их нет.

### Ключевые правила (своими словами)

| Правило | Суть |
|---|---|
| Формула действия | `Владелец + глагол совершенного вида + что именно [+ до даты] [— зачем]`; один пункт — одно действие |
| Один владелец | не «команда»/«мы»; не назначен → ведущий встречи + `[уточнити власника]` |
| Срок только произнесённый | нет срока — действие без даты, без плейсхолдера; «ASAP», «до конца недели» датой не считаются |
| Лестница даты встречи | транскрипт → имя файла/метаданные → заголовок записи → текущая дата с пометкой «(припущення)»; от предполагаемой даты относительные сроки не пересчитываются |
| День недели | определить от даты встречи и от него считать «до пятницы» |
| Проверка меток спикеров | самоидентификация, сверка с ростером, логика сторон (кто описывает процесс — исполнитель, кто потребность — заказчик); при конфликте верить содержанию и писать строку-предупреждение в шапку |
| Роль и сторона | у каждого участника `Имя (роль, сторона)`; не ясно — `[уточнити роль]`; в участниках люди, не компании |
| Нормализация имён | написание из метки спикера, одна форма на весь документ, в алфавите языка вывода |
| Решение ≠ действие ≠ вопрос | решение — правило на будущее без владельца; вопрос с известным «кто и когда» — это действие |
| «По виконавцях» | дайджест «владелец: номера пунктов», если владельцев ≥ 2, по убыванию числа задач |
| Сомнительные места | искажённое слово, влияющее на пункт, не достраивается; после артефакта (в чат, не в документ) блок: цитата с таймкодом, как прочитано, вопрос «да/нет» |
| Plain text на всю сессию | запрет разметки действует на все следующие ответы, не только на первый |
| Порог humanizer | до ~40 слов — применить правила напрямую, длиннее — полный прогон |
| Самопроверка | в т.ч. латинские гомоглифы в кириллических заголовках (`Zустріч:`), сквозная нумерация, номера в дайджесте существуют |

## Сравнение с нашими скиллами

Сравнивали с `meeting-protocol-builder` и `session-transcript-analyzer`
(тексты в `~/.claude/skills/synced/*/`). `odoo19-sales-prep:client-followup-writer`
и `odoo19-sales-demo:demo-followup-writer` **в этом контейнере недоступны**
(`~/.claude/plugins/synced/*/` пуст) — их тексты не читали, сравнение с ними только
по роли в цепочке (`proposals/siblings-checked.md`); по правилу №28 отсутствие
правил в них не утверждаем.

| Аспект | follow-up | `meeting-protocol-builder` |
|---|---|---|
| Назначение | короткий внутренний/мессенджерный итог | официальный протокол для заказчика, .md + брендированный .docx |
| Сроки | только произнесённые, иначе без даты | обязательна конкретная дата; неизвестна — «до наступної зустрічі (дата)» |
| Владелец | ровно один человек, иначе пометка | колонка «Відповідальний», но «один человек» явно не требуется |
| Дата встречи | лестница источников + пометка «припущення» | ДД.ММ.РРРР, «звір рік», иначе `‹заповнити›`; день недели — `date -d` (сильнее) |
| Метки спикеров | явная проверка атрибуции | только «убрать следы транскрипта» |
| Искажения ASR | блок сомнений с таймкодом вне документа | нет |
| Справочник людей | `roster.md` (в .gitignore) | берёт из брифа/договора |
| Чувствительное | нет фильтра (цены попадают в решения) | фильтр: ставки, цены, внутренние нормы не в протокол |
| Структура | блоки решений/действий/вопросов | темы повестки, ВИРІШИЛИ, ПОГОДЖЕННЯ, ДОДАТОК 1 |
| Самопроверка | 9 пунктов, гомоглифы | QA-чек-лист под дефекты корпуса 1013 протоколов (сильнее по домену) |

**Что у них есть сверх нашего:** проверка меток спикеров; блок «сомнительные
места» вне артефакта; лестница даты с пометкой допущения и запрет пересчёта
относительных сроков от допущения; жёсткое «один владелец»; ростер; режим
«сообщение участнику» (≤120 слов, язык адресата, один конкретный следующий шаг);
plain text как контракт на всю сессию; порог для humanizer; гомоглифы в чек-листе.

**Что хуже:** тяжёлый (12–15 тыс. токенов на срабатывание); широкие триггеры
(«follow-up», «action items», «підсумок зустрічі») пересекаются с нашими
`*-followup-writer` и протоколами; шаг 0 добавляет лишний круг вопроса; нет
фильтра чувствительного; нет записи в файл и связи с журналами (D/X/C/Q/A-N);
зависит от внешнего `humanizer`. Мелкие противоречия внутри: в примере
«Сергій модеруватиме» — несовершенный вид, хотя правило требует совершенного;
в примере `[уточнити власника й дедлайн]`, хотя «Що НЕ робити» запрещает
`[уточнити дедлайн]`.

**Что дублирует:** разделение решений/действий/вопросов, стоп-лист канцелярита
(у нас Humizer), запрет «найближчим часом» как срока, «транскрипт ≠ протокол».

**Расхождение, требующее решения:** наше правило 11 (`meeting-protocol-builder`)
требует конкретную дату у каждого решения, а при её отсутствии ставит
«до наступної зустрічі (дата)» — это подставленный нами срок, а не
произнесённый. follow-up считает подстановку выдумкой. Предложение: оставить
конвенцию протокола, но помечать источник срока (сказано на встрече / назначено
по умолчанию), чтобы подставленный срок не выглядел договорённостью.

| Идея | Куда | Зачем |
|---|---|---|
| Проверка атрибуции меток спикеров + строка-предупреждение | `meeting-protocol-builder` (Крок 1), `session-transcript-analyzer`, `*-followup-writer` | действия и решения не уходят не тем людям |
| Блок «сомнительные места» (цитата + таймкод → прочтение → вопрос да/нет), вне документа | все скиллы, читающие транскрипт | не выдавать догадку за договорённость |
| Лестница даты встречи + «припущення» + запрет пересчёта от допущения | `meeting-protocol-builder`, `session-transcript-analyzer` | сроки не сдвигаются от неверной базы |
| Пометка источника срока (сказано / по умолчанию) | `meeting-protocol-builder` правило 11 | конвенция «до наступної зустрічі» не выглядит договорённостью |
| «Один владелец», иначе `[уточнити власника]` | ВИРІШИЛИ / Екшн-план, A-N | ответственность не размывается |
| Дайджест «по владельцам» | `*-followup-writer`, екшн-план | человек быстро находит свои пункты |
| Режим «сообщение участнику» (≤120 слов, язык адресата, один следующий шаг) | `client-followup-writer`, `demo-followup-writer` (сверить с их текстом) | короткие письма вместо пересказа |
| Plain text как контракт на всю сессию | скиллы с выводом в мессенджер/почту | разметка не возвращается во втором ответе |
| Гомоглифы в чек-листе | QA-чек-листы протоколов | реальный класс опечаток |
| Порог «до ~40 слов — правила напрямую» | Humizer в наших протоколах | экономия на мелких блоках |

Не переносить: шаг 0 с обязательным вопросом о режиме (у нас тип встречи и так
определяется), формат даты прописью (у заказчика ДД.ММ.РРРР), отказ от
фильтра чувствительного.

## Риски и заметки

- Ставить как есть не стоит: триггеры перекрывают наши скиллы, а вывод в чат без
  файла и журнала не встраивается в цепочку дискавери/продаж.
- Лицензия CC BY 4.0 разрешает адаптацию при атрибуции; всё равно пишем своими
  словами и в `references/` скилла ставим ссылку на источник, лицензию и отметку
  об изменениях.
- Транскрипты — чувствительные данные; ростер с ПДн держать вне git (у нас — в
  журнале клиента, а не в репозитории плагина).
