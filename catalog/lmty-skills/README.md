# Competitive Skills by LMTY (`LMTYdotcom/skills`)

- **Тип:** плагин (16 скиллов) + встроенный удалённый MCP-сервер `mcp.lmty.com`
- **Источник:** https://github.com/LMTYdotcom/skills (★84, MIT)
- **Версия / коммит:** 1.0.0, `18667e0` (2026-11-01)
- **Дата разбора:** 2026-11-03
- **Вердикт:** **адаптировать** (методы и шаблоны 3–4 скиллов в наши `odoo19-sales-*`); плагин как есть **не ставить**

## Что делает

Набор из 16 скиллов «конкурентной работы» продуктового маркетолога и
продавца SaaS: брифинги по рынку, профиль конкурента, позиционирование,
ценообразование, battlecard, ответ на возражение, подготовка сделки,
план POC/RFP, win/loss, аудит материалов. Все скиллы работают без
сервиса, но плагин везёт в комплекте MCP-сервер LMTY (платный сервис
отслеживания конкурентов) и при первом запуске просит войти в него.

Гипотеза из поиска («battlecards, win-loss, позиционирование,
ценообразование») **подтверждается**, но шире: это не про внедрение
ERP, а про SaaS-рынок с публичными прайсами и changelog-ами конкурентов.

## Какую слабость Claude закрывает

Не знания и не действия, а **метод и дисциплину доказательств**:
- без скилла модель охотно пишет «проиграли из-за цены», сливая версию
  продавца и слова клиента, обобщает 2–3 сделки в «паттерн» и выдумывает
  слабости конкурента;
- общая политика `TRUST.md`: факт → интерпретация → импликация → вариант
  действия, «не найдено» ≠ «нет», не выводить мотив конкурента без
  источника, свежесть и покрытие как часть утверждения;
- шаг «Hand off»: отвечать только на свою часть составного запроса и
  явно называть, какой скилл делает остальное.

## Как устроен

- 16 папок `skills/<name>/`: `SKILL.md` 180–350 строк (≈10 КБ), шаблон
  в `assets/`, 7 файлов `references/` (≈34 КБ на скилл). Шесть из них
  (`TRUST`, `CONTEXT`, `DEGRADATION`, `QUALITY`, `LMTY`, `INTERNAL`) —
  одинаковые копии из `shared-references/` (генерирует
  `scripts/build_skills.py`), свой у каждого только `METHODOLOGY.md`.
- Хуков нет, исполняемого кода в скиллах нет. `scripts/*.py` — сборка и
  валидация для CI автора, пользователю не нужны.
- **Сеть:** `.mcp.json` / `mcp.json` / `gemini-extension.json` объявляют
  удалённый HTTP MCP `https://mcp.lmty.com/mcp` с OAuth. При установке
  плагина Claude Code поднимет его автоматически и предложит вход.
  Запросы и контекст сделок уходят стороннему сервису (по их политике).
  Инструменты сервера, по `LMTY.md`, только чтение: `list_products`,
  `get_report`, `get_report_changes`, `get_evidence` и т.п.
- Телеметрии в самих скиллах нет (grep: упоминания «telemetry» —
  это про аналитику продукта пользователя как источник данных).

## Оценка

| Критерий | Балл (0–3) | Комментарий |
|---|---|---|
| Прирост | 2 | Метод win/loss и возражений сильнее типового ответа модели (не измерено) |
| Частота | 1 | Защита КП и разбор проигрышей — эпизодически; 11 из 16 скиллов нам не нужны |
| Надёжность | 2 | Описания точные, с явными «не для» и маршрутами; 16 похожих описаний рядом с нашими `sales-*` дадут конфликт триггеров |
| Стоимость контекста | 1 | ≈10 КБ описаний всегда в каждой сессии; вызов скилла тянет ≈10 КБ `SKILL.md` + до ≈34 КБ `references/` |
| Безопасность | 2 | Код прочитан, хуков нет; минус — автоматически подключаемый сторонний MCP с OAuth, куда утекает контекст сделок |
| Поддержка | 3 | Компания-автор, релиз 1.0.0, CI, OpenSSF, dependabot; активность с 2026-09-28 |

## Что и куда перенести

1. **`loss-pattern-analyzer`** ← `competitive-win-loss-analysis`
   + его `METHODOLOGY.md`: две колонки «клиент сказал / продавец
   записал»; знаменатель = сделки со словами клиента; «паттерн = счёт с
   исключениями»; порог сегментации 4–5 сделок; связь с событием рынка
   только если оно было ДО решения и клиент его упомянул; блок смещений
   выборки; гипотезы с тестом вместо причин; цитаты по роли, не по имени.
   Отдельная корзина «отказ от проекта» (no decision ≠ проигрыш
   конкуренту) — у нас это частый исход.
2. **`defence-brief`** ← `competitive-objection-response`: шаги
   «сохранить возражение дословно → проверить посылку (verified / partly /
   not supported / unknown + где проверить) → поза из 5 → 15-секундный
   ответ → 1–2 вопроса → что не утверждать → честность о fit».
3. **Общий фрагмент для `odoo19-sales-*`** ← `TRUST.md` (сжать до
   ~20 строк): четыре класса утверждений, «не найдено ≠ нет», не
   выдумывать мотив и слабости конкурента, `High/Medium/Low` без
   фальшивых процентов.
4. **По желанию:** «преимущество → событие-доказательство» и «no-go
   условия» из `competitive-poc-rfp-plan` в `demo-build-plan`.

Атрибуция при переносе: «по мотивам LMTYdotcom/skills, MIT,
© LMTY» в `references/` нашего скилла.

## Риски и заметки

- Не ставить плагин целиком: автоматический сторонний MCP, 16 широких
  описаний, SaaS-специфика (публичные прайсы, changelog, PMM).
- Наши тексты `defence-brief` и `loss-pattern-analyzer` в контейнере
  недоступны (`~/.claude/plugins/synced/*/` пуст), поэтому сравнение с
  ними — по известной цепочке из `proposals/siblings-checked.md`, а не по
  тексту. Перед переносом сверить построчно.
