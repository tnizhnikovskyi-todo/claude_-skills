## Что делает

Набор из 16 скиллов «конкурентной работы» продуктового маркетолога и
продавца SaaS: брифинги по рынку, профиль конкурента, позиционирование,
ценообразование, battlecard, ответ на возражение, подготовка сделки,
план POC/RFP, win/loss, аудит материалов. Все скиллы работают без
сервиса, но плагин везёт в комплекте MCP-сервер LMTY (платный сервис
отслеживания конкурентов) и при первом запуске просит войти в него.

Гипотеза из поиска («battlecards, win-loss, позиционирование,
ценообразование») **подтверждается**, но шире: это не про внедрение
ERP, а про SaaS-рынок с публичными прайсами и changelog-ами конкурентов.

## Какую слабость Claude закрывает

Не знания и не действия, а **метод и дисциплину доказательств**:
- без скилла модель охотно пишет «проиграли из-за цены», сливая версию
  продавца и слова клиента, обобщает 2–3 сделки в «паттерн» и выдумывает
  слабости конкурента;
- общая политика `TRUST.md`: факт → интерпретация → импликация → вариант
  действия, «не найдено» ≠ «нет», не выводить мотив конкурента без
  источника, свежесть и покрытие как часть утверждения;
- шаг «Hand off»: отвечать только на свою часть составного запроса и
  явно называть, какой скилл делает остальное.

## Как устроен

- 16 папок `skills/<name>/`: `SKILL.md` 180–350 строк (≈10 КБ), шаблон
  в `assets/`, 7 файлов `references/` (≈34 КБ на скилл). Шесть из них
  (`TRUST`, `CONTEXT`, `DEGRADATION`, `QUALITY`, `LMTY`, `INTERNAL`) —
  одинаковые копии из `shared-references/` (генерирует
  `scripts/build_skills.py`), свой у каждого только `METHODOLOGY.md`.
- Хуков нет, исполняемого кода в скиллах нет. `scripts/*.py` — сборка и
  валидация для CI автора, пользователю не нужны.
- **Сеть:** `.mcp.json` / `mcp.json` / `gemini-extension.json` объявляют
  удалённый HTTP MCP `https://mcp.lmty.com/mcp` с OAuth. При установке
  плагина Claude Code поднимет его автоматически и предложит вход.
  Запросы и контекст сделок уходят стороннему сервису (по их политике).
  Инструменты сервера, по `LMTY.md`, только чтение: `list_products`,
  `get_report`, `get_report_changes`, `get_evidence` и т.п.
- Телеметрии в самих скиллах нет (grep: упоминания «telemetry» —
  это про аналитику продукта пользователя как источник данных).
