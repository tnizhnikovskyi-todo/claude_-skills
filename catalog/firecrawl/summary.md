# firecrawl — сводка

- **Что это:** облачный API «веб → данные для LLM» (scrape с JS-рендером и
  антиботом, search с полным текстом, map/crawl сайта, interact в живом
  браузере, parse PDF, agent, monitor) + официальный MCP-сервер (MIT, 27
  инструментов, hosted `mcp.firecrawl.dev`) + CLI со скиллами + self-host
  ядро (AGPL-3.0).
- **Против WebFetch/WebSearch:** закрывает их главные дыры — JS-страницы,
  полный текст вместо пересказа, JSON по схеме, обход сайта, клики и
  пагинация, поиск не только по US. Простые страницы встроенные делают
  бесплатно и без третьей стороны.
- **Вердикт:** адаптировать, 14/18. Подключить hosted MCP по API-ключу
  (Free 1000 кредитов/мес хватит на пробу), feedback-инструменты выключить,
  версию пиннить, в `CLAUDE.md` правило «сначала встроенные, Firecrawl —
  для сложных случаев, без клиентских данных».
- **Не брать:** CLI-скиллы как есть (перехватывают любую веб-задачу,
  `setup defaults` запрещает WebFetch/WebSearch), self-host (без закрытого
  Fire-engine заметно слабее, 6+ сервисов в эксплуатации).
- **Риски:** все URL/запросы/контент уходят в облако (США), ZDR только
  Enterprise; feedback-инструменты просят отправлять цель пользователя;
  keyless-режим вставляет рекламную инструкцию в вывод.
- **Идея на заимствование:** вывод страниц в файлы (`.firecrawl/`) и
  чтение частями через grep — экономит контекст и снижает prompt injection.
- **Дальше:** живое A/B на 5–6 задачах (таблица в README) после получения ключа.
