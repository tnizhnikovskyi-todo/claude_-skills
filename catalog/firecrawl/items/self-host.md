# Firecrawl self-hosted

- **Тип:** собственное развёртывание (Docker Compose / Kubernetes / Helm)
- **Источник:** монорепо, `SELF_HOST.md`, `docker-compose.yaml`,
  `examples/kubernetes/`
- **Версия / коммит:** `6b02a6c` (v2.11.645)
- **Дата разбора:** 2026-11-02
- **Вердикт:** **пока нет** — смысл только при жёстком требовании «данные
  не уходят наружу»; качество заметно ниже облака

## Что входит

Compose поднимает: API и воркеры, `playwright-service`, Redis, RabbitMQ,
NuQ PostgreSQL (очередь), FoundationDB (опциональный бэкенд очереди).
Наружу публикуется только API на `:3002`. Есть Helm-чарт и манифесты k8s.

## Чего нет по сравнению с облаком

- **Fire-engine** — закрытый движок облака (антибот, ротация прокси,
  собственный поиск). В self-host: Playwright + обычный fetch, прокси —
  только свой (`PROXY_SERVER`).
- **Поиск:** по умолчанию DuckDuckGo, или свой SearXNG
  (`SEARXNG_ENDPOINT`); облачный поиск недоступен.
- **AI-функции** (JSON по схеме, agent/extract) — нужен свой провайдер:
  OpenAI / совместимый эндпоинт / Ollama. То есть данные уйдут к этому
  провайдеру, если он внешний.
- Индексы developer / gov / research и каталог Alexandria — облачные
  сервисы; по коду self-host их не воспроизводит (не проверял детально).

## Эксплуатация

- По умолчанию API **без аутентификации** (`USE_DB_AUTHENTICATION=false`);
  наружу выставлять только с TLS, авторизацией и сетевой политикой.
- Нет persistent volumes для Postgres/Redis/RabbitMQ в базовом compose.
- Админ-роуты (`BULL_AUTH_KEY`, `ADMIN_INTERNAL_PORT`) — внутренний порт
  без ключа, не публиковать.
- Пиннить релизный тег, не `main`.
- MCP и CLI подключаются к своему инстансу через `FIRECRAWL_API_URL`.

## Лицензия

AGPL-3.0. Для внутреннего использования без изменений — без последствий.
Если модифицировать и давать доступ к сервису по сети (в т.ч. клиентам) —
обязаны раскрыть исходники модификаций под AGPL. SDK (MIT), MCP (MIT) и
CLI (ISC) — отдельные лицензии, AGPL на наш код через них не
распространяется.
