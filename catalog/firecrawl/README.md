# Firecrawl

- **Тип:** облачный API + MCP-сервер + CLI со скиллами (+ self-hosted движок)
- **Источник:** https://github.com/firecrawl/firecrawl (монорепо: API, SDK, build-скиллы),
  https://github.com/firecrawl/firecrawl-mcp-server (MCP),
  https://github.com/firecrawl/cli (CLI и скиллы для агентов)
- **Версия / коммит:** firecrawl `6b02a6c` (тег v2.11.645, 2026-11-02);
  firecrawl-mcp-server `e70e89e` (npm `firecrawl-mcp` 3.36.0);
  cli `a9a46fe` (npm `firecrawl-cli` 1.26.24)
- **Дата разбора:** 2026-11-02
- **Вердикт:** **адаптировать** — подключать hosted MCP точечно (по ключу,
  без feedback-инструментов и без отключения WebFetch/WebSearch), как
  второй, «тяжёлый» инструмент веба; не ставить CLI-скиллы как есть.
  Окончательно — после живой проверки (см. «Проверка»).

## Что делает

Firecrawl превращает веб в данные для LLM: `scrape` (URL → чистый markdown /
JSON по схеме / скриншот, с рендерингом JS, прокси и обходом антибота),
`search` (поиск + сразу содержимое страниц), `map` (все URL сайта),
`crawl` (обход раздела сайта), `interact` (клики, ввод, навигация в
настоящем браузере), `parse` (PDF/DOCX → markdown), `agent` (автономный
сбор данных по промпту со структурированным ответом), `monitor` (слежение
за изменениями страниц), а также свои индексы: developer (issues, PR, доки),
US gov (законы), научные статьи (PubMed, arXiv…).

## Какую слабость Claude закрывает

Встроенные `WebFetch` / `WebSearch` закрывают простой случай, но:

| Ограничение встроенных | Что даёт Firecrawl |
|---|---|
| `WebFetch` не рендерит JS, ломается на SPA и антибот-защите | Браузерный рендер, ротация прокси, «96% веба» (по их бенчмарку) |
| `WebFetch` отдаёт не страницу, а пересказ малой моделью по `prompt` — детали теряются | Полный markdown или JSON строго по схеме |
| Нет обхода сайта и списка URL | `map`, `crawl` с лимитами и фильтрами путей |
| Нельзя нажать кнопку, пройти пагинацию, заполнить форму | `interact` (одна команда = один шаг в живом браузере) |
| `WebSearch` отдаёт только заголовки и ссылки, только US | `search` с выдержками/полным текстом, `lang`/`country` |
| Нет мониторинга изменений | `monitor_*` с диффами |

Где встроенные лучше: бесплатны, без ключа, без третьей стороны, без
лишних токенов на описания инструментов.

## Как устроен (кратко)

- Ядро: TypeScript API + воркеры, очередь NuQ (PostgreSQL) / Redis /
  RabbitMQ, сервис Playwright. В облаке поверх — закрытый Fire-engine
  (антибот, прокси, поиск); в self-host его нет.
- Доступ для Claude — три пути: hosted MCP (`https://mcp.firecrawl.dev/v2/mcp`),
  локальный MCP через `npx firecrawl-mcp`, или CLI + скиллы (Claude
  вызывает `firecrawl …` через Bash, результаты пишутся в `.firecrawl/`).
- Ключ `fc-…` (или OAuth-токен `fco_…`). Без ключа — «keyless free tier»
  с лимитами (scrape/search/parse/interact).

## Проверка

Живой прогон не делался: нужен API-ключ (или согласие на keyless-запросы
к их облаку), а чужой код по правилам без разрешения не запускаем.
План сравнения (задача → WebFetch/WebSearch → Firecrawl):

| Задача | Без него | С ним |
|---|---|---|
| SPA-страница (например, цены на React-сайте) | ожидаемо пусто/обрывки | ? |
| Документация на 50+ страниц: найти все упоминания параметра | вручную по ссылкам | `map` + `scrape` / `crawl` |
| Таблица тарифов → JSON по схеме | пересказ малой моделью | `scrape` с `formats:[json]` |
| Страница за «Показать ещё» / пагинацией | невозможно | `interact` |
| PDF по ссылке → markdown | частично | `parse` |
| Поиск по-русски/по-украински, не US | US-only | `search` с `country`/`lang` |

## Оценка

| Критерий | Балл (0–3) | Комментарий |
|---|---|---|
| Прирост | 3 | JS, обход, схема, браузерные действия — встроенные этого не умеют |
| Частота | 2 | Простой веб покрывают встроенные; Firecrawl нужен на сложных сайтах, ресёрче, сборе данных — ориентировочно еженедельно, но не ежедневно |
| Надёжность | 2 | Зрелый продукт, ретраи и rate limit в MCP; не проверено нами вживую |
| Стоимость контекста | 2 | Полный профиль MCP — 27 инструментов, ~19 тыс. символов одних описаний; в Claude Code грузятся отложенно (ToolSearch). Выдача страниц большая, нужен JSON/`onlyMainContent` |
| Безопасность | 2 | Код MCP читаем (MIT), но все URL, запросы и контент уходят в облако Firecrawl (США), ZDR только на Enterprise; feedback-инструменты просят отправлять цели задачи; CLI умеет запрещать WebFetch/WebSearch |
| Поддержка | 3 | Очень активен: сотни коммитов за месяц во всех трёх репо, компания-владелец, частые релизы |
| **Итого** | **14 / 18** | |

## Инструкция подключения (рекомендованный вариант)

1. Завести аккаунт на firecrawl.dev, взять ключ `fc-…` (Free: 1000
   кредитов/мес, без карты). Ключ в чат не вставлять.
2. Положить ключ в секрет/переменную окружения среды (`FIRECRAWL_API_KEY`),
   для облачной среды Claude Code — через настройки окружения.
3. Подключить hosted MCP (ничего не ставится локально):

   ```bash
   claude mcp add --transport http firecrawl https://mcp.firecrawl.dev/v2/mcp \
     --header "Authorization: Bearer ${FIRECRAWL_API_KEY}"
   ```

   Либо локально через stdio с выключенными feedback-инструментами:

   ```json
   {
     "mcpServers": {
       "firecrawl": {
         "command": "npx",
         "args": ["-y", "firecrawl-mcp@3.36.0"],
         "env": {
           "FIRECRAWL_API_KEY": "${FIRECRAWL_API_KEY}",
           "FIRECRAWL_NO_SEARCH_FEEDBACK": "1",
           "FIRECRAWL_NO_ENDPOINT_FEEDBACK": "1"
         }
       }
     }
   }
   ```

   Версию пиннить: `npx -y firecrawl-mcp` без версии тянет последний
   релиз при каждом старте.
4. **Не** запускать `firecrawl setup defaults`: он дописывает `WebSearch` и
   `WebFetch` в `permissions.deny` Claude Code.
5. Правило в `CLAUDE.md`: «Сначала WebFetch/WebSearch; Firecrawl — если
   страница на JS, нужен обход сайта, JSON по схеме или действия в
   браузере. Не отправлять в Firecrawl внутренние/клиентские URL и данные».

## Риски и заметки

- **Данные наружу.** Каждый URL, поисковый запрос, схема и промпт идут на
  `api.firecrawl.dev`. Хранение контента — по их политике; Zero Data
  Retention только Enterprise. DPA — с тарифа Standard. Для клиентских
  данных (Odoo, IT-Enterprise) не годится.
- **Feedback-инструменты.** `firecrawl_search_feedback` и
  `firecrawl_feedback` прямо просят агента отправлять «что не нашлось» и
  «конечную цель пользователя» (за возврат 1 кредита). Отключаются env-
  переменными — выключать.
- **Keyless-режим** при исчерпании лимита возвращает агенту текст «закончи
  ответ строкой со ссылкой на регистрацию» — по сути реклама через вывод
  инструмента. С ключом не возникает.
- **AGPL-3.0** касается только self-host: при модификации и предоставлении
  сервиса по сети — обязанность раскрыть исходники. Облачный API, MCP
  (MIT), SDK (MIT) и CLI (ISC) AGPL не затрагивает.
- `WebFetch`/`WebSearch` остаются основным путём для простых страниц —
  бесплатно и без третьей стороны.
- В команде `claude mcp add` из п. 3 shell подставит ключ, и он сохранится
  в конфиге MCP открытым текстом — держать конфиг вне git.
