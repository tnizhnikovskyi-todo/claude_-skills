### Гипотеза «SOW + анкеты»

Подтверждается частично. Это не набор анкет, а **одна** сводная анкета
с вариантами ответа (MCQ), которую генерирует `sow-intake` из звонка/BRD, плюс
конвейер SOW: черновик (Pass 1) → интеграция архитектуры и BoM (Pass 2) →
проверка по матрицам рисков. Статического банка вопросов нет намеренно: вопросы
генерируются заново, а страховка — список обязательных **тем**.

### Что выяснилось

| Идея из чужого плагина | У нас в продажах |
|---|---|
| Оценка только с основанием | **Есть и сильнее:** `preliminary-estimate` строит вилку по аналогам из Odoo (фактические часы таймшитов, год аналога), явно пишет, когда аналогов нет или Odoo недоступен, есть раздел «Чего эта оценка не содержит» |
| Противоречия источников | **Есть:** `brief-transcript-analyzer` — порядок приоритета источников + `R-N` 🔴 о расхождении; `data-completeness-scorer` не закрывает `Q-N` при противоречии. Отличие: мы берём значение по приоритету, они не выбирают вовсе. Наш вариант практичнее |
| Документ без цены = блокер | **Есть:** штамп «🚫 НЕ КП» в `offer-finalizer` |
| Внутреннее не уходит клиенту | **Есть по сути:** pre-save `offer-finalizer` (нет ID, ставки, коэффициента, механики, `R-N`, «ничего внутреннего»). Маржи/себестоимости в нашем потоке нет |
| MCQ-анкета с рекомендованным вариантом | **Нет:** наша `анкета.md` — 7 блоков открытых вопросов. Новое — как режим дозбора |
| Тема закрыта вопросом или снята с причиной | Не нашли явно; у нас строже по-другому (КО/ВО/ПП + формула). Проверить точечно |
