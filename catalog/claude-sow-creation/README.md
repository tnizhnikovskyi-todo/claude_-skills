## Что делает

Конвейер подготовки Statement of Work в presales: из звонка дискавери (и, если
есть, BRD) генерирует **одну сводную анкету** для клиента с вариантами ответов →
по ответам пишет черновик SOW (Pass 1) со всеми пробелами, помеченными явно →
после солюшенинга встраивает архитектуру и Bill of Materials (Pass 2) → проверяет
документ по матрицам рисков. Оркестратор сам классифицирует файлы в папке
(звонок, анкета пустая/заполненная, BoM, схема-картинка, чужой SOW), ведёт
журнал состояния с хешами входов и перезапускает только устаревшие стадии.
Выход — `.docx` (англ.).

**Гипотеза «SOW + анкеты» подтверждается частично:** анкета одна (MCQ), без банка
вопросов; основная ценность не в анкете, а в дисциплине черновика SOW.

## Какую слабость Claude закрывает

1. Модель «додумывает» цифры: сроки, состав команды, объёмы. Здесь оценка
   разрешена только с названным основанием, иначе каркас без чисел и флаг на весь
   раздел.
2. Модель молча выбирает одну из противоречащих версий (первую или последнюю)
   или усредняет. Здесь обе версии с источником и датой, решает человек.
3. Модель переносит внутренние цифры (себестоимость, маржа) в клиентский
   документ, если сказано «вставь BoM как есть». Здесь фильтр «по умолчанию
   внутреннее».
4. Модель путает «не решено» с «да». Здесь неопределённый ответ превращается
   в допущение с пометкой, а не в факт.

## Как устроен

- `SKILL.md` по 5–13 КБ, справочники грузятся по требованию. Самый тяжёлый вход —
  оркестратор (13 КБ) + `input-classification.md` (26 КБ) на каждый запуск `/sow2`.
- `sow-library/` (шаблон SOW из 24 разделов, банк из 9 оговорок, чек-лист из 12
  тем, правила docx) **скопирован в три скилла**, копии пока идентичны.
- Скрипт `fingerprint.py`: хеш текста docx/xlsx/pdf; вызывает только локальный
  `pdftotext`. Сети, хуков, `allowed-tools` нет. Прочитан целиком.
- ID для перекрёстных ссылок: `WP-n` (пакеты работ), `PR-n` (предусловия),
  `A-n` (допущения), `R-n` (риски); допущение ссылается на предусловие, риск — на
  допущение/предусловие.
