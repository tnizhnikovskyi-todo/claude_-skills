# sow-verifier

- **Источник:** `plugins/sow-creation-v2/skills/sow-verifier/@a2c4f18`
  (исходный автор — Shivendra Jadon, перенесено из `sow-creation`)
- **Вердикт:** частично адаптировать (предпроверка), матрицы отклонить

## Что делает

Проверяет SOW перед отправкой: сначала дешёвая предпроверка заглушек, затем
матрицы рисков выбранного «трека» (AI/агенты — 13 файлов, Power Platform — 1),
вердикт в YAML для оркестратора.

## Что ценно (идеи)

1. **Предпроверка заглушек:** любой оставшийся «блокер» = автоматический провал;
   «подтвердить» — список обязательного к закрытию.
2. **Чужой SOW** (не из этого конвейера): чистый поиск по своим меткам ничего не
   значит, ищем «TBD/TBC/pending/уточнить/будет определено» и прямо пишем, что
   полнота проверена по тексту, а не по меткам.
3. **Выбор матриц по реально поставляемой технологии** (объём, архитектура, BoM),
   а не по маркетинговому «AI-powered» в предыстории. «Ни один трек не подошёл» —
   отдельная находка в отчёте, а не тихий пропуск. Повод — реальный случай:
   AI-матрицы на проекте Power Platform дали «провал» по несвязанной причине и
   иллюзию полноты.

## Куда у нас

п. 1–2 → проверка SOW/КП перед отправкой (по аналогии с `tr-review`).
п. 3 → принцип для любых наших чек-листов с выбором по типу проекта.

## Что не берём

Матрицы рисков: AI/Azure/Power Platform, ссылки на несуществующие файлы
(`01_diplomatic_disclaimer.md` и др.), эмодзи-светофоры. Описание скилла
слишком широкое («review, check, analyze SoW»).
