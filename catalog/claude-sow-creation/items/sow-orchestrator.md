# sow-orchestrator

- **Источник:** `plugins/sow-creation-v2/skills/sow-orchestrator/@a2c4f18`
- **Вердикт:** отклонить как механизм, взять 2 идеи

## Что делает

Единая точка входа (`/sow2 <папка>`): классифицирует каждый файл в папке
(по имени, затем по содержимому; схема-картинка → извлечённый список
компонентов с флагом; пустая/частично/полностью заполненная анкета — даже если
клиент отметил ответы прямо в отправленном файле), считает хеши
(`scripts/fingerprint.py`), сравнивает с журналом `sow-ledger.md` и запускает
только устаревшие стадии. Спрашивает пользователя только в двух случаях: роль
файла неясна и найден чужой готовый SOW (проверить / продолжить с ним /
только справка).

## Идеи

1. **Устаревание идёт вниз по цепочке:** изменился вход стадии → стадия и все
   последующие устарели, предыдущие переиспользуются. Полезно для нашей цепочки
   журнал → scope → gap → SOW.
2. **«Сделать и пометить», а не «ждать»:** при неполных входах стадия всё равно
   выполняется, пробелы — явными заглушками. Единственное, что запрещено, —
   выдумать факт.

## Почему не механизм

У нас роль журнала уже играет `журнал_дискавері_[компанія].md` с реестрами;
классификация произвольной папки и хеши — 40 КБ инструкций на каждый запуск;
сквозной прогон автор сам не проводил.
