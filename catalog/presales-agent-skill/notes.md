### Гипотеза «дискавери → матрица скоупа → план спринтов»

Подтверждается: 5 шагов — дискавери по 7 измерениям → BRD (строка = требование)
→ ревью по 8 измерениям со скорингом → план спринтов и таймлайн → сводка.
«Матрица скоупа» — это лист Scope of Work в xlsx с колонками A–H + листы Out of
Scope, Business Process Guide, Effort Summary.

### Безопасность

- `SKILL.md`: пишет только в `opportunities/<Client>/` текущего проекта, запускает
  `node generate_xlsx.js` и при первом запуске `npm install --prefix …/scripts`.
- `generate_xlsx.js`: импорты только `exceljs`, `fs`, `path`; сети, `child_process`,
  `process.env` нет; пишет только xlsx в папку клиента.
- Зависимость `exceljs ^4.4.0` (диапазон, не пин), в `package-lock.json` 193
  пакета, все с `registry.npmjs.org`. Транзитивные зависимости не аудировали.
- Установщики: `curl | bash` / `irm | iex` с ветки `main` без пина и проверки
  подписи; сами скрипты читаемые, качают zip с codeload.github.com, переносят
  старую копию в бэкап. Для нас не нужны — достаточно прочитать тексты.
- Телеметрии нет. Хуков нет. Права: Bash для `node`/`npm`/`mkdir`.

### Найденные несостыковки (качество)

1. `SKILL.md` утверждает, что генератор «refuses» отчёт с нарушениями; на деле
   `validateBrd` проверяет только обязательные поля, тип `effortHours`, дубли ID и
   «старый» формат-массив. Слова `Assuming`/`etc.` никто не ловит — это остаётся на
   совести модели в шаге ревью.
2. Zod-схемы (`schemas/*.ts`) нигде не исполняются: `zod` нет в зависимостях.
   «Validate against schema» — только инструкция модели.
3. Ёмкость разработчика: в `SKILL.md`/`effort_reference.md` 35 ч/нед (70 ч/спринт),
   в `sprint_planning.md` 40 ч/нед. Hypercare: «1wk+» против «4–8 недель».
4. `Total Dev Effort = Grand − Data Load − Shared Activities` — «Shared Activities»
   нигде не определены.
5. Оценка — одна точка без вилки и без резерва; диапазоны 2–16 ч на требование
   считаются как «время человека на проверку AI-сборки», т.е. заведомо низкие и
   прямо показываются клиенту. Автор сам пишет «not a validated benchmark».

- У нас реестры журнала (D/X/C/T/Q/A-N), `X-N` только с источником — это сильнее,

- У нас оценка вынесена в отдельный `tr-effort-instruction` уровня ТР; у них оценка
