## 1. `odoo19-discovery-closeout:discovery-sow-builder` — главный получатель

Сейчас: оценка каждой позиции — «диапазон + допущения», отдельный раздел
«Допущения и зависимости». Именно эту форму presales-agent v2 сознательно убрал.

Предложение:
- Каждая позиция «Обсягу робіт» — одна возможность, которую клиент
  принимает отдельно; каждая интеграция и каждая группа миграции — своя.
- Вместо «допущений» у позиции три вида утверждений:

  | Вид | Где | Голос |
  |---|---|---|
  | Что делаем | Опис позиції | «Система буде…», «[Клієнт] зможе…» |
  | Что даёт/решает клиент и к какому сроку | Колонка «Потрібно від замовника» | «[Клієнт] надасть … до [кінця обстеження / початку налаштування / UAT]» |
  | Что не входит | «Що не входить» | «… не входить.» |

- Раздел «Допущения и зависимости» остаётся только для общих условий
  проекта (доступы, ответственные), и каждое — тоже со сроком.
- В pre-save добавить содержательные проверки (п. 3).

## 2. `odoo19-discovery-closeout:discovery-scope-mapper`

- Шаг «Інвентар scope»: колонка «Потрібно від замовника / до коли» у пункта.
  Неизвестное — туда или в «Відкрите», не догадкой (последнее у нас уже есть).
- Строки «Інтеграції»: обязательно что, направление, частота/триггер, что при
  сбое. «Дані та міграція»: объём, источник, глубина истории, сверка.
- Шаг «Поза scope»: после чинных `X-N` — короткий список «ймовірно
  очікуване, але не обговорене» для позиций с ИИ, порталом, аналитикой,
  обратной записью в ERP, мобильным приложением. Это **кандидаты в `Q-N`** на
  подтверждение, не `X-N`: правило «исключение только с источником» сохраняется.

## 3. Содержательные проверки (в pre-save `discovery-sow-builder`, частично `presale-pack-builder`)

По мотивам `review_checklist.md` (категории 2–4), без Salesforce-пунктов:

| Severity | Проверка |
|---|---|
| CRITICAL | Цифра, список или название системы без источника (D-N / журнал / бриф) |
| CRITICAL | Открытое обещание: «усі звіти», «будь-які джерела», «за потреби» |
| HIGH | Позиция с внешней зависимостью (вендор, ERP, банк) без пункта «Потрібно від замовника» |
| HIGH | Интеграция без направления, частоты или поведения при сбое |
| HIGH | Миграция без объёма, источника или сверки |
| HIGH | «тощо», «і т.д.», «та інше», «припускаємо» в клиентском тексте |
| MEDIUM | Пункт «Потрібно від замовника» без срока |
| MEDIUM | Люди названы «користувачі», а не ролями клиента |
| MEDIUM | Ссылка на позицию, которой нет |

Стоп на CRITICAL до подтверждения БА. Скоринг 0–100 не нужен.
Часть HIGH (запрещённые слова) можно поймать скриптом — кандидат на правило в
`check-humizer.py` у `presale-pack-builder` (барьер вместо формулировки).

## 4. Не переносить

- Модель оценки целиком: `preliminary-estimate` сильнее (аналоги по таймшитам,
  коэффициент, строка покрытия, белые пятна с последствием в часах, история
  версий, сверка с уже названной цифрой).
- «Миграция вне ёмкости разработки» — на пресейле у нас нет спринтового плана,
  ценность низкая (было в первой версии карточки, снято после сверки).

## Как проверить (A/B, нужно разрешение)

2–3 журнала дискавери из пилота → `discovery-КП` с правкой 1+3 и без.
Метрики: число «припущень»/«тощо», цифр без источника, позиций с внешней
зависимостью без пункта клиента, пунктов клиента без срока, число CRITICAL.
