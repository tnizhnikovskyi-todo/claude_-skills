## 1. `odoo19-discovery-closeout:discovery-scope-mapper` — правило «три места»

Из `references/requirement_writing.md`. Каждое утверждение строки скоупа —
одно из трёх, в своей колонке:

| Что | Колонка | Голос |
|---|---|---|
| Что делаем | Опис | «Система буде…», «[Клієнт] зможе…» |
| Что клиент даёт/решает и к какому сроку | Потрібно від клієнта | «[Клієнт] надасть … до кінця дискавері» |
| Что читатель мог бы ожидать, но не входит | Не входить (→ `X-N` с источником) | «… не входить.» |

Правила для вставки:
- Нет «припускаємо», «тощо», «за потреби», открытых списков — перечислять.
- Цифры, списки, названия систем — только из журнала (ссылка на D-N/бриф);
  неизвестное → пункт «Потрібно від клієнта» с якорем срока, не догадка.
- Термины Odoo (модели, поля, модули) — только в колонке «Підхід»; описание
  читает бизнес-владелец.
- Одна строка = одна возможность, которую клиент принимает отдельно; каждая
  интеграция и каждая группа миграции — своя строка.
- «Не входить» — специфично для строки, не общий дисклеймер.

## 2. Ревью скоупа — 15–20 проверок с severity

Из `review_checklist.md` взять категории 2–4 (читаемость, факты, защита
скоупа), выбросив Salesforce-пункты (SKU, лицензии DE/FSL, deprecated). Ядро:
- CRITICAL: цифра без источника; открытое обещание («усі звіти», «будь-які
  джерела»); перекрёстная ссылка на несуществующую строку.
- HIGH: нет «Потрібно від клієнта» у строки с внешней зависимостью;
  интеграция без направления/частоты/обработки сбоя; миграция без объёмов и
  сверки; «припускаємо»/«тощо».
- MEDIUM: людей зовут «користувачі» вместо ролей; пункт «потрібно» без срока.
Куда: шаг самопроверки `discovery-scope-mapper` или `discovery-gap-analyzer`
(решить по реальным текстам). Скоринг 0–100 — по желанию, вердикт «стоп на
CRITICAL» — да.

## 3. `odoo19-sales-prep:preliminary-estimate` — только две идеи

- Миграция данных — отдельная сумма, вне ёмкости разработки.
- Строки выше верхней границы диапазона — дробить, а не раздувать.
Модель «одна точка, 2–16 ч AI-проверки» **не брать**: наша вилка честнее.

## 4. `odoo19-sales-demo:presale-pack-builder` — глоссарий клиента

Лист «Як працюватиме процес»: 6–12 шагов «что происходит / где» + глоссарий
аббревиатур клиента, каждая раскрыта при первом упоминании в строке.

## Как проверить (A/B, нужно разрешение)

3 брифа из пилота → скоуп-таблица с вставкой 1 и без. Метрики: число
«припускаємо/тощо», цифр без источника, строк без «потрібно від клієнта» при
внешней зависимости, число CRITICAL по чек-листу 2.
