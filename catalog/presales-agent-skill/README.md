## Что делает

Пресейл внедрения Salesforce в 5 шагов с воротами качества: дискавери по
7 измерениям (по одному за раз) → BRD, где строка = одно требование, которое
клиент может принять или отклонить отдельно → ревью BRD по 8 измерениям и
40-пунктовому чек-листу со скорингом 0–100 и стопом на CRITICAL → план
спринтов (2 недели, 70 ч/разработчик) и таймлайн → сводка. Выход: JSON +
xlsx по фиксированному шаблону (Scope of Work, Out of Scope, Business Process
Guide, Effort Summary). Гипотеза из поиска подтверждается.

## Какую слабость Claude закрывает

Модель на пресейле по умолчанию пишет «Предполагаем, что…», открытые списки
(«и т.д.») и придумывает правдоподобные цифры (число пользователей, уровни
согласования). Скилл запрещает это и даёт каждому утверждению своё место:
**что делаем** / **что клиент должен дать и к какому сроку** / **что не
входит**. Плюс разделение языка: бизнес-колонки без терминов платформы,
термины — только в Solution Approach.

## Как устроен

- `SKILL.md` (20 КБ, ~5 тыс. токенов) — весь процесс, грузится при
  срабатывании; `references/` (11 файлов, ~51 КБ) читаются пошагово.
- Сильные тексты: `requirement_writing.md` (3 колонки вместо «Assuming», якоря
  сроков, анти-паттерны), `scope_boundary_patterns.md` (типовые «нужно от
  клиента» / «не входит» по областям), `review_checklist.md` (40 проверок с
  severity), `scope_review.md` (8 измерений, «Fact Integrity» — главное).
- Salesforce-специфика: `products_catalog.md` (SKU), `scope_patterns.md`
  (модули по облакам), `solution_approach_patterns.md`.
- `scripts/generate_xlsx.js` (exceljs) заполняет шаблон; проверяет только
  обязательные поля и дубли ID. Zod-схемы не исполняются.
- Сеть: нет (кроме `npm install` и установщиков `curl | bash` с `main`).
  Телеметрии и хуков нет. Пишет в `opportunities/<Client>/` проекта.

## Что переносимо на Odoo

- Почти всё про **текст BRD**: 3 колонки вместо «Assuming», якоря сроков,
  перечисления без «и т.д.», «что заблокировано, а не только что разрешено»,
  интеграционная строка = что, куда, когда, что при сбое; миграция = объёмы,
  источник, сверка.
- `scope_boundary_patterns.md` как структура: переписать таблицу под области
  Odoo (Продажи, Склад, Учёт, Производство, CRM, сайт, интеграции 1С/банк,
  миграция).
- Не переносить: SKU-каталог, модули облаков, Solution-паттерны Salesforce,
  модель часов «AI-assisted», фиксированную шкалу спринтов.
