# odoo-lens: LSP-сервер, скилл и хук

- **Тип:** плагин Claude Code (LSP-сервер через `.lsp.json` + скилл + хук `SessionStart`)
- **Источник:** https://github.com/ChengyanOo/odoo-lens, коммит `2482f92`
- **Вердикт:** отклонить для облака; для локальных машин разработчиков —
  кандидат на пробу только после появления лицензии

## Что делает

Индексирует исходники Odoo (community + enterprise + кастомные аддоны) так,
как их загружает сам Odoo: порядок модулей по `depends`, слияние полей по
всем модулям, цепочка `super()`, xml-id (включая неявные `model_*`/`field_*`),
вью и их наследование, QWeb/owl, CSV прав, `@module/...` в JS. Отвечает на
hover / definition / implementation / references / symbols / call hierarchy.

## Сравнение с serena и нашим `odoo-model-map`

| Вопрос | serena (pyright) | `boost:odoo-model-map` | odoo-lens |
|---|---|---|---|
| `_inherit` строкой/списком | не видит | видит (grep + AST), но список без `_name` в 19 трактует неверно | видит, с учётом версии |
| XML-вью, `inherit_id`, xpath | нет | да (дерево наследования) | да + проверка версии в xpath |
| Порядок переопределений (`super()`) | нет | нет | да — главная сила |
| Ядро Odoo и enterprise | нет | только если просканировать вручную; иначе «Где не искал» | да, если исходники на диске |
| Права (`ir.model.access`, `ir.rule`) | нет | да, включая модели без прав | ссылки из CSV да; модели без прав — нет |
| Работает в облачной сессии | да | да (stdlib, без исходников ядра) | формально да, но без исходников Odoo почти бесполезен; нужен LSP-инструмент |
| Стоимость | ~5.6k токенов описаний | только при вызове | скилл ~1.5k токенов при срабатывании + подсказка хука в каждой Odoo-сессии |

Вывод: odoo-lens решает слепоту LSP к строковому `_inherit` и XML, которую
мы зафиксировали у serena, — но только там, где на диске лежат исходники
Odoo нужной версии.

## Поведение Claude

- Триггер скилла широкий («любая задача по Odoo-коду ... используй до
  grep») + хук в каждой сессии с Odoo-кодом. По нашим правилам это минус,
  пока польза не измерена.
- README честно пишет, что `pyright-lsp` перехватит `.py`, а `claude -p`
  запретит запуск линтера без правила в `permissions.allow`.

## Безопасность

Код только stdlib, сети и телеметрии не нашли, `subprocess`/`eval` нет,
лаунчер с `python -I`. Кэш `marshal` в `~/.cache/odoo-lens`. Хук печатает
текст, ошибки глушит. Прочитана выборка (диагностика, CLI, лаунчер,
манифесты плагина), не все 27 тыс. строк.

## Почему не ставим

1. Нет лицензии.
2. Облако: исходников Odoo нет, ценность сжимается до правил версий,
   которые дешевле перенести в чек-лист.
3. Проекту 2 недели, один автор, 6 коммитов.
4. Пересекается с `odoo-model-map` по задаче «карта модели».
