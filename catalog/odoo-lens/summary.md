# odoo-lens: сводка для главной сессии

- **Что это:** плагин Claude Code (ChengyanOo/odoo-lens, `2482f92` = HEAD,
  ★21, **без лицензии**): LSP-сервер + линтер модулей + скилл + хук для
  Odoo 16–20. Чистый stdlib-Python, сети/телеметрии/subprocess нет.
- **Сила:** понимает Odoo как загрузчик Odoo — `_inherit`/`_inherits`,
  порядок `super()` по модулям, XML-вью и xml-id, CSV прав. Закрывает
  слепоту serena/graphify к строковым связям, но **только при исходниках
  Odoo на диске** — в облаке их нет.
- **Главная находка для нас:** в Odoo 19 `_inherit = ['x']` без `_name`
  создаёт НОВУЮ модель с именем из класса (в 18 — расширение). Сверено по
  исходникам 18.0/19.0. Наш `boost:odoo-model-map` (скрипт, пример в
  SKILL.md, фикстура и кейс `who-extends`) трактует это как расширение →
  ложный ответ под 19. Нужна правка.
- **Взять идеи (своими словами):** ~15 правил устаревшего API 17–19
  (`_inherits` без явного поля, `xpath //tree`, `tree_view_ref`,
  `name_get`, `user_has_groups`, `@api.returns`, `auto_join`,
  `group_operator`, поля `res.groups`…) и правила связности (внешний
  xml-id → `depends`, неимпортированный `.py`, кнопка на `_`-метод,
  серьёзность по месту ссылки) → `repo-audit/references/odoo-checklist.md`
  и предложение для `pr-review`. Часть правил помечена UNVERIFIED —
  сверить через `source-check`.
- **Не умеет:** безопасность (sudo, SQL, ACL), сверку со SPEC.
