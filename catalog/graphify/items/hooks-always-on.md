# graphify: always-on (хуки `PreToolUse` + блок в `CLAUDE.md`)

- **Тип:** хук Claude Code + инструкции в `CLAUDE.md`
- **Источник:** `graphify/install.py` (`_claude_pretooluse_hooks`), `graphify/cli.py` (`_run_hook_guard`), `graphify/always_on/claude-md.md`
- **Версия / коммит:** `32e5efe`
- **Дата разбора:** 2026-11-02
- **Вердикт:** отклонить для нас (идею можно взять)

## Что делает

`graphify claude install` добавляет в `.claude/settings.json` два хука:

- `matcher: "Bash|Grep"` → `graphify hook-guard search`
- `matcher: "Read|Glob"` → `graphify hook-guard read` (опционально `--strict`)

и секцию в `CLAUDE.md`: «если есть `graphify-out/graph.json`, запускай
`graphify query` перед первым grep/чтением, вписывай это правило в каждый
промпт субагента, после правки кода запускай `graphify update .`».

Хук читает JSON вызова из stdin и, если граф есть, возвращает
`additionalContext` с подсказкой «спроси граф». Со `--strict` первое чтение
проиндексированного свежего файла за сессию получает
`permissionDecision: deny`, дальше только подсказки.

## Оценка кода

Аккуратно: fail-open на любой ошибке, лимит 10 с, подсказка не чаще
определённого бюджета на агента, файлы вне проекта игнорируются, устаревший
граф смягчает подсказку. Тексты подсказок — факты, без «MANDATORY»
(авторы сами заметили, что императивы в выводе хуков выглядят как
prompt injection, #2202).

## Почему не ставить

- Каждый Grep/Read в проекте с графом получает лишний контекст.
- Меняет поведение Claude и субагентов глобально для проекта; при малых
  репозиториях это хуже прямого grep.
- В облачных сессиях `graphify` должен быть установлен в контейнере на
  каждом старте, иначе хук тихо ничего не делает.
- Ту же пользу даёт одна строка в нашем `CLAUDE.md` для конкретного
  большого репо, где граф реально построен.
