# graphify

- **Тип:** скилл + CLI (Python) + хуки Claude Code + опциональный MCP-сервер
- **Источник:** https://github.com/Graphify-Labs/graphify (PyPI: `graphifyy`)
- **Версия / коммит:** `32e5efe` (2026-11-01), тег `v1.0.0`, в `pyproject.toml` 0.9.100
- **Дата разбора:** 2026-11-02
- **Вердикт:** **адаптировать / взять точечно** — как инструмент по требованию
  для больших незнакомых кодовых баз; always-on режим (хуки + блок в
  `CLAUDE.md`) и автоустановку из скилла не ставить. Окончательно после
  испытания (см. «Проверка»).

## Что делает

Строит из папки проекта граф знаний и даёт его запрашивать вместо grep.
Код разбирается локально через tree-sitter (~40 языков, без LLM, без сети):
узлы — классы/функции/файлы, рёбра — `calls` / `imports` / `inherits` и т.д.,
с меткой `EXTRACTED` / `INFERRED` / `AMBIGUOUS`. Документы, PDF, картинки
идут через «семантический проход» LLM (в Claude Code это субагенты текущей
сессии). Затем кластеризация (Leiden/Louvain), «god nodes», неожиданные связи.
Результат: `graphify-out/graph.json`, `GRAPH_REPORT.md`, `graph.html`.
Запросы: `graphify query "<вопрос>"`, `graphify path A B`, `graphify explain X`.

## Какую слабость Claude закрывает

- **Память/контекст:** Claude в каждой сессии заново исследует незнакомый
  репозиторий grep'ом и чтением файлов. Граф сохраняется на диске между
  сессиями и отдаёт «срез» по вопросу дешевле, чем чтение файлов.
- **Знания (структура):** связи, невидимые текстовому поиску: кто кого
  вызывает через несколько файлов, кратчайший путь между модулями, циклы
  импортов, подсистемы. Для этого есть явные метки достоверности рёбер.
- Частично **метод**: `GRAPH_REPORT.md` как стартовая карта архитектуры.

## Как устроен

- `graphify/skill.md` (797 строк, ~10k токенов) копируется в
  `~/.claude/skills/graphify/SKILL.md`; плюс `references/*.md`, которые
  грузятся по требованию. Скилл в основном оркестрирует Python-однострочники
  и параллельных `general-purpose` субагентов для документов.
- Python-библиотека ~60k строк: `detect → extract → build → cluster →
  analyze → report → export`. Зависимости базовые: networkx, numpy, rapidfuzz,
  pyyaml, tree-sitter + ~25 грамматик. Всё прочее (MCP, PDF, видео, LLM-SDK,
  Neo4j) — опциональные extras.
- `graphify install` пишет: скилл в `~/.claude/skills/`, строку-регистрацию в
  `~/.claude/CLAUDE.md`; `graphify claude install` — секцию в `CLAUDE.md`
  проекта и `PreToolUse` хуки в `.claude/settings.json`.
- `graphify hook install` — git-хуки post-commit/post-checkout для
  пересборки (только AST, без LLM).

### Сеть и данные

| Что | Куда | Когда |
|---|---|---|
| Код | никуда, локально | всегда |
| Документы/PDF/картинки | модель текущей сессии Claude (субагенты) | при `/graphify` на корпусе с документами |
| То же, headless `graphify extract` | провайдер, **автоопределённый по переменным окружения**: Gemini → Kimi (Китай) → Claude → OpenAI → DeepSeek → Azure → Bedrock → Ollama | только если есть ключ; `GRAPHIFY_BACKEND=none` отключает |
| В скилле при `GEMINI_API_KEY` | Google Gemini вместо субагентов | если ключ в окружении |
| `graphify add <url>` | любой URL, arXiv, YouTube (yt-dlp) | явная команда; есть SSRF-защита |
| `graphify prs` | `gh` CLI → GitHub | явная команда |
| `graph.html` / callflow | CDN (unpkg, d3js.org, jsdelivr) | при открытии в браузере |
| Установка | PyPI (`graphifyy`) | скилл сам делает `uv tool install --upgrade graphifyy`, если пакета нет |

Телеметрии нет (проверено grep'ом: нет обращений к своему домену, кроме
печати рекламной ссылки на app.graphify.com). Лог запросов в коде
**выключен по умолчанию** (opt-in), хотя README утверждает обратное —
расхождение документации.

## Проверка

Пока не запускали: по правилам репо внешний код без разрешения пользователя
не исполняем. Предлагаемое испытание (нужно «да» пользователя):

| Задача | Без него | С ним |
|---|---|---|
| Незнакомый крупный Python-репо (напр. модули Odoo 19 core): «как связаны X и Y», «что сломается при изменении Z» | grep/Read, считаем токены и точность | `graphify extract --code-only` + `query/path`, те же вопросы |
| Наш кастомный `td.*` модуль Odoo (Python + XML) | — | Проверить, ловит ли граф `_inherit = 'model'` (строки, не классы) и XML-вью. Ожидаем: **нет**, XML уходит в LLM-проход |

Собственный бенчмарк авторов по коду слабый: ERPNext, **n=6 вопросов**,
покрытие ключевых фактов 82.0% против 70.8% у grep/read, ~140K токенов на
вопрос. Остальные цифры (LOCOMO, LongMemEval) про разговорную память, к
нашей задаче отношения не имеют. «−80% токенов» — маркетинг платного Cloud.

## Оценка

| Критерий | Балл (0–3) | Комментарий |
|---|---|---|
| Прирост | 2 | Реальный на больших/чужих кодовых базах и структурных вопросах; на малых репо grep не хуже (это признаёт сам скилл). Для Odoo ключевые связи (`_inherit` строкой, XML) скорее всего не видит |
| Частота | 1 | Наша работа в основном процессная (ТР, дискавери, Odoo-модули небольшого размера). Нужен эпизодически: разбор чужого/большого кода |
| Надёжность | 2 | Огромный набор тестов, CI, детерминированный AST. Но 2700 коммитов за 7 месяцев, 704 за октябрь, номера issue/PR в коде уже за #4300 — очень быстрый темп, частые смены схем кэша, регрессии вероятны |
| Стоимость контекста | 1 | Описание скилла агрессивное («для любого вопроса о кодовой базе»), тело ~10k токенов; always-on хуки добавляют подсказки к каждому Grep/Read. Сами ответы `query` компактные |
| Безопасность | 2 | Код аккуратный: нет `shell=True`/`eval`, хуки fail-open, SSRF-защита, редактирование секретов, MCP HTTP только на 127.0.0.1 с опциональным ключом. | Поддержка | 3 | Очень активно, компания (YC S26), Apache-2.0 (+MIT для старых вкладов), понятный автор |
| **Итого** | **11 / 18** | |

## Риски и заметки

- **Агрессивный триггер.** `description` скилла: «Use for any question about a
  codebase…». В нашей среде он будет перехватывать обычные вопросы по коду.
  При адаптации — сузить описание до явного вызова.
- **Always-on меняет поведение Claude глобально**: блок в `CLAUDE.md` велит
  запускать `graphify query` перед первым grep и вписывать это правило в
  каждый промпт субагента; строгий режим один раз за сессию запрещает Read.
- **Автоустановка.** Step 1 скилла: `uv tool install --upgrade graphifyy`
  (или `pip install ... --break-system-packages`). Это тянет непинованную
  последнюю версию при каждом отсутствии пакета — supply-chain риск.
- **Утечка в чужие LLM.** Если в окружении есть `GEMINI_API_KEY`, скилл
  отправляет документы в Gemini; headless CLI может выбрать Kimi (Китай) или
  DeepSeek по наличию ключа. Ставить `GRAPHIFY_BACKEND=none` или `--code-only`.
- **Апселл.** CLI печатает ссылки на Graphify Cloud; README наполовину реклама.
- **Расхождение документации**: README говорит, что лог запросов включён по
  умолчанию, код (`querylog.py`) — что выключен. `SECURITY.md` поддерживает
  «0.9.x», хотя вышел тег v1.0.0.
- **Альтернатива на 30 строк?** Нет: AST-резолвинг вызовов по 40 языкам и
  кластеризация — это не скилл, а инструмент. Но always-on «сначала спроси
  граф» — это 5 строк в `CLAUDE.md`, их можно написать самим под свой случай.
