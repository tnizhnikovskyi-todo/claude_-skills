# serena

- **Тип:** MCP-сервер (+ CLI `serena`, хуки Claude Code `serena-hooks`, опц. платный плагин JetBrains)
- **Источник:** https://github.com/oraios/serena (PyPI: `serena-agent`), автор Oraios AI (Германия)
- **Версия / коммит:** `ede329a` (2026-10-28), последний тег `v2.1.0` (2026-10-19), в `pyproject.toml` 2.1.1.dev0
- **Дата разбора:** 2026-11-02
- **Вердикт:** **отклонить для текущих задач (Odoo)**, вернуться при работе с
  большими не-Odoo кодовыми базами (Python/TS/Java). Идею «карта символов
  вместо чтения файлов» взять в свой Odoo-скилл (см. «Что взять»).
  Вердикт предварительный: живого испытания не было (нужно разрешение).

## Что делает

Даёт агенту инструменты уровня IDE поверх языковых серверов (LSP): обзор
символов файла, поиск символа по `name_path` с телом или без, поиск ссылок,
объявлений, реализаций, диагностику, правку по символу (заменить тело,
вставить до/после, переименовать, безопасно удалить) и простую «память
проекта» (markdown-файлы в `.serena/memories/`). Подключается к Claude Code
как MCP-сервер через stdio. Есть альтернативный «REPL-интерфейс» (агент
шлёт Python-код, Serena его исполняет) и платный бэкенд JetBrains с
move/inline/type hierarchy/отладчиком.

## Какую слабость Claude закрывает

- **Контекст:** вместо `Read` целого файла на 2000 строк агент берёт оглавление
  (`get_symbols_overview`) и тело одного метода (`find_symbol include_body`).
- **Действия:** атомарное переименование символа по всем файлам и поиск
  ссылок по семантике, а не по тексту (`grep` путает одноимённые методы).
- **Память:** заметки о проекте между сессиями. У нас это уже закрывают
  `CLAUDE.md` и разбор `claude-mem`, так что тут прирост малый.

## Как устроен

Компоненты:

| Компонент | Что это | Для нас |
|---|---|---|
| MCP-сервер, контекст `claude-code` | ~24 инструмента: символы, правка, память, диагностика. Файловые/shell-инструменты в этом контексте выключены, т.к. у Claude Code свои | ядро; см. оценку |
| Память `.serena/memories/` + `~/.serena/memories/global/` | markdown-файлы, список имён отдаётся агенту, читает по имени | дублирует `CLAUDE.md` |
| Хуки `serena-hooks` (alpha) | `remind` — **запрещает (deny)** Grep/Read после 3 подряд без вызова Serena; `activate`; `auto-approve` — авто-одобряет все `mcp__serena__*` в режимах `acceptEdits`/`auto`; `cleanup` | не ставить |
| Подмена системного промпта CC | `claude --system-prompt="$(serena prompts print-cc-system-prompt-override)"` — заменяет системный промпт Claude Code своим, где Read/Edit для кода «FORBIDDEN» | не ставить |
| Веб-дашборд | Flask на 127.0.0.1:24282, **включён по умолчанию**, может сам открыть браузер/трей | выключить |
| JetBrains-бэкенд | платный плагин IDE | вне рамок |

Установка: `uv tool install -p 3.13 serena-agent`, затем `serena init` и
`serena setup claude-code` (или вручную
`claude mcp add serena -- serena start-mcp-server --context claude-code --project "$(pwd)"`).
Python 3.11–3.14, зависимости в `pyproject.toml` **пинованы точно** (≈35
пакетов, в т.ч. `anthropic`, `flask`, `tiktoken`, `pywebview`, `pystray`).

Языковые серверы: 40+ языков. Для Python по умолчанию **pyright**,
скачивается при первом запуске через `uvx` с PyPI (пин версии); можно
`jedi`, `ty`, `pyrefly`, `basedpyright`. Прочие LS качаются в
`~/.serena/...` с пином версии, SHA256, белым списком хостов; npm-серверы —
через пользовательский npm. **XML-сервера нет.**

### Сколько контекста

Оценка статическим разбором docstring'ов (код не запускали), скрипт в notes:

| Что | Объём |
|---|---|
| Описания всех инструментов (вкл. JetBrains и опциональные) | ~54k символов ≈ 13.5k токенов |
| Инструменты, включённые в контексте `claude-code` с LSP | ~22.5k символов ≈ **5.6k токенов** (самые тяжёлые: `find_symbol` 3.7k симв., `replace_in_files` 3.3k) |
| Инструкции сервера при подключении | 1 строка: «CRITICAL: вызови `initial_instructions`» |
| `initial_instructions` (системный промпт + контекст + режимы) | ≈ 2–3k токенов при вызове |

В Claude Code MCP-инструменты отложенные (tool search), поэтому постоянная
стоимость невелика. Но промпт контекста `claude-code` требует **сразу**
загрузить все инструменты Serena и запрещает Read/Edit для кода — это
меняет поведение Claude глобально, не по запросу.

## Odoo: насколько поможет

Ключевой вопрос задачи. Вывод по коду (не по запуску):

| Что нужно в Odoo | Serena (pyright) | Почему |
|---|---|---|
| Оглавление большого файла модели, тело одного метода | **да** | обычный Python-синтаксис, LSP это видит |
| «Кто наследует `sale.order`» (`_inherit = 'sale.order'` строкой) | **нет** | для LSP это строковый атрибут, не наследование классов. Классы разных модулей не связаны в Python |
| Все переопределения `action_confirm` в разных модулях | **нет / частично** | только текстовый поиск по имени; `find_implementations` работает по Python-иерархии, которой нет |
| Ссылки на метод из `self.env['sale.order'].action_confirm()` | **нет** | тип `env[...]` pyright не выводит, вызов не связывается |
| Ссылки из XML: `<button name="action_confirm">`, `field name=`, `inherit_id`, `ref=` | **нет** | XML-сервера нет вообще |
| Домены, `depends`, `related='partner_id.name'` | **нет** | строки |
| `rename_symbol` метода/поля | **опасно** | переименует только Python-ссылки, пропустит другие модули с `_inherit`, XML, домены, `depends`. А режим `editing` прямо велит агенту: «рефакторинг завершён, не перепроверяй» |

Итог: на Odoo Serena даёт только экономию токенов при чтении больших
файлов по методам, а семантическая часть (ссылки, переименование), ради
которой её ставят, в Odoo промахивается и может ложно успокоить.
Плюс pyright на ядре Odoo (тысячи файлов) — долгая индексация и память.

## Сравнение с graphify

| | serena | graphify (`catalog/graphify/`) |
|---|---|---|
| Суть | живые точные запросы и **правка** через LSP | статический **граф** всего репо, обзор архитектуры, пути между модулями |
| Сильная сторона | переименования/ссылки в типизированном коде; чтение по символам | «как связаны X и Y», подсистемы, god nodes, карта при первом знакомстве |
| Правка кода | да | нет |
| Сеть | телеметрия по умолчанию (opt-out), LS с интернета | код оффлайн; LLM-провайдеры по ключам (выключается) |
| Стоимость контекста | ~5.6k ток. инструментов (отложено) + агрессивный промпт/хуки | скилл ~10k ток. + always-on хуки |
| Odoo `_inherit` строкой | не видит | вероятно не видит (не проверено) |
| Odoo XML | не видит | только через LLM-проход |
| Лицензия | GPL-3.0+ (SolidLSP — MIT) | Apache-2.0 |

Они **дополняют** друг друга (граф для обзора, LSP для точечной навигации и
правки), но для Odoo у обоих одна дыра: связи в Odoo живут в строках
(`_inherit`, `_name`, `env['...']`) и в XML. Для наших задач полезнее
свой скилл/скрипт «карта моделей Odoo»: grep/AST по `_name`/`_inherit`/
`_inherits` + разбор XML (`model=`, `inherit_id`, `name=` у кнопок/полей) →
таблица «модель → файлы, поля, методы, вью». Это десятки строк, без сети,
и закрывает именно то, что пропускают оба.

## Проверка

Не запускали: по правилам репо нужно разрешение пользователя. Предлагаемое
испытание:

| Задача | Без него | С ним |
|---|---|---|
| Модуль Odoo 19 (напр. `sale` + наш `td.*`): «где переопределён `action_confirm`», «что затронет переименование поля X» | grep/Read, считаем токены, полноту | `find_symbol`/`find_referencing_symbols`; ожидаем пропуски `_inherit` и XML |
| Прочитать 3 метода из `sale_order.py` (~2000 строк) | Read с offset | `get_symbols_overview` + `find_symbol include_body` — замер токенов |
| Чистый Python-репо (не Odoo) ~30k строк: переименование метода | Grep+Edit по файлам | `rename_symbol` |

Собственная оценка авторов — самооценка агентом по 20 задачам (качественная,
не числовая), и в отчёте Claude Code использовался **платный JetBrains-бэкенд**,
а не бесплатный LSP. Для нашего случая не показательна.

## Оценка

| Критерий | Балл (0–3) | Комментарий |
|---|---|---|
| Прирост | 1 | Для Odoo — только экономия при чтении больших файлов; ссылки/rename промахиваются на `_inherit` и XML. Для больших типизированных репо было бы 2–3 |
| Частота | 1 | Наша работа — ТР, дискавери, небольшие `td.*` модули |
| Надёжность | 1 | Сам продукт зрелый (много тестов, 40+ языков), но авторы прямо пишут, что Claude Code/Opus «почти невозможно убедить» пользоваться Serena без хуков-запретов и подмены системного промпта; запуск LS требует `MCP_TIMEOUT=60000` |
| Стоимость контекста | 1 | Инструменты ~5.6k ток. (отложенные — ок), но промпт контекста велит грузить всё сразу и запрещает Read/Edit; рекомендуемые хуки делают deny на Grep/Read |
| Безопасность | 2 | Код открыт, пины зависимостей, SHA256 для LS, сервисы на 127.0.0.1, shell-инструмент в CC выключен. Минусы: телеметрия включена по умолчанию, дашборд с походами в PyPI/свой сервер, `auto-approve` хук, REPL исполняет код, модель «доверяем всему» |
| Поддержка | 3 | Oraios AI, очень активно (406 коммитов с августа, v2.0.0 13.10, v2.1.0 19.10), документация подробная. Лицензия сменилась на GPL-3.0+ с v2 (до v1.7.0 MIT); для использования не мешает, для копирования кода — да |
| **Итого** | **9 / 18** | |

## Что взять

- Не ставить сейчас. Если поставить для не-Odoo проекта: контекст
  `claude-code`, `SERENA_USAGE_REPORTING=false`, `web_dashboard: false`,
  без хуков `remind`/`auto-approve`, без подмены системного промпта, без REPL,
  `--project "$(pwd)"` в scope проекта, не глобально.
- **Идея для своего скилла:** «сначала оглавление, потом тело нужного метода»
  + Odoo-карта моделей (`_name`/`_inherit` + XML). Можно сделать задачей в
  `roadmap.md` (решение за главной сессией).

## Риски и заметки

- **Агрессивное вмешательство в поведение Claude.** Контекст, хуки и подмена
  промпта построены вокруг того, чтобы запретить встроенные инструменты.
  Хук `remind` возвращает `permissionDecision: deny` на Read/Grep.
- **Ложная уверенность при rename в Odoo** (см. таблицу выше).
- **Телеметрия по умолчанию.** Анонимная и минимальная, но opt-out.
- **Лицензия GPL-3.0+.** Код Serena в наши скиллы не копировать;
  `src/solidlsp/` под MIT можно.
- **README предупреждает не ставить через маркетплейсы MCP/плагинов** —
  там устаревшие команды. Это касается и аддона в `headroom-desktop`
  (проверить, какую команду он использует).
- Тег `mit-final` / v1.7.0 — последняя MIT-версия, если когда-то понадобится
  форк под MIT.
