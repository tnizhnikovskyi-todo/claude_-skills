# skill-comply

- **Тип:** скилл + Python-скрипты (`uv run python -m scripts.run`)
- **Источник:** `affaan-m/ECC@b38be6a`: `skills/skill-comply/` (`SKILL.md`
  59 строк, `prompts/scenario_generator.md`, `prompts/classifier.md`,
  `scripts/*.py`)
- **Лицензия:** MIT
- **Вердикт:** адаптировать идею в наш эвал-контур; скрипты не ставить

## Что делает

Из `SKILL.md` или правила генерирует ожидаемую последовательность шагов
(spec), затем сценарии на **трёх уровнях строгости промпта**:
supportive (просьба прямо велит следовать скиллу), neutral (не упоминает),
**competing** (в промпте есть указание, конфликтующее со скиллом).
Запускает `claude -p` со `stream-json`, классифицирует вызовы
инструментов LLM-ом и проверяет порядок шагов детерминированно. Итог —
доля соблюдения по уровням и подсказка «какой шаг перевести в хук».

## Сравнение с нашим

`plugins/boost/evals/README.md` меряет прирост качества «с / без»,
но не проверяет, **соблюдается ли процедура скилла, когда промпт тянет в
другую сторону** (например, «быстро, без вопросов» против `interview-me`,
«просто поправь» против `skill-feedback`). Это как раз тот случай, где наши
скиллы ценны (меняют действие). Наш `claude plugin eval` умеет прогоны,
так что скрипты ECC не нужны.
