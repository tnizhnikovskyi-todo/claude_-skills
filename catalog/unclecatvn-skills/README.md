# unclecatvn/agent-skills (Odoo 16–19)

- **Тип:** плагин Claude Code (8 скиллов + 2 агента) и npm-CLI установки; также ставится через `npx skills`
- **Источник:** https://github.com/unclecatvn/agent-skills (MIT, © 2026 UncleCat)
- **Версия / коммит:** 1.0.20, `82ebbae` (2026-10-16)
- **Дата разбора:** 2026-11-03
- **Вердикт:** **адаптировать** (взять справку API 19.0, формат Context Brief и, после проверки, хелпер `odoo_trace.py`; плагин целиком не ставить)

## Что делает

Даёт ассистенту три вещи против выдуманного Odoo-кода: справочники по API
фреймворка для каждой версии 16–19 (с коротким списком «чего не использовать
в этой версии»), скилл `odoo-workflow` — процедуру «сначала найди версию и
трассируй реальные исходники, потом пиши код» с read-only хелпером
`odoo_trace.py` и чек-листом готовности, и два агента (ревьюер с баллами и
трассировщик). Гипотеза «документация Odoo в виде скиллов» верна лишь
наполовину: главная ценность в методе и хелпере, а не в тексте справочников.

## Какую слабость Claude закрывает

Ровно ту, что `synthesis.md` называет главной: факты новой версии Odoo.
Поля, методы, xmlid и xpath-якоря, которых нет в базовом аддоне; переопределение
не того метода; хранимое поле без миграции; `sudo()` без обоснования;
«тесты прошли», когда не запустился ни один тест. Метод: «нет цитаты
`file:line` — нет кода».

## Как устроен

- Плагин: `.claude-plugin/plugin.json` с `source: ./`, все скиллы и агенты
  сразу. Хуков и MCP нет.
- `skills/odoo-19.0/SKILL.md` (115 строк) — индекс 18 справочников
  (~180 КБ всего, грузятся по требованию) и `api-highlights.md` (50 строк).
  Описание очень широкое: «любой Python/XML код Odoo 19».
- `skills/odoo-workflow/SKILL.md` (273 строки, ~18,7 КБ): шаг 0 — версия и
  рантайм через `odoo_trace env` (`odoo/release.py`, `odoo.conf`,
  `.claude/odoo.json`); шаг 1 — `odoo_trace model|field|method|depends|xmlid|unlisted`
  и grep-рецепты для XML/JS/контроллеров/прав; шаг 2 — Context Brief;
  шаги 3–6 — минимальный план, реализация, definition of done, ревью.
- `scripts/odoo_trace.py` (1356 строк, stdlib, только чтение): разбирает
  классы через `ast`, применяет правила `_name` версии, идёт по `_inherit`,
  `_inherits`, `base`, `BaseModel`; печатает `file:line`; коды выхода
  0 = найдено, 1 = NOT FOUND (с ближайшими реальными символами), 2 = не знаю.
- Сеть: только у CLI установки (npm registry, GitHub releases). Телеметрии нет.

## Что перенести и куда

1. **`api-highlights.md` 19.0** (50 строк, все проверенные факты верны) →
   `plugins/boost/skills/source-check/references/odoo19-api-changes.md`
   с атрибуцией (MIT) и нашими дополнениями: `res.partner.mobile`/`title`
   удалены, `res.users.groups_id` → `group_ids`, `type='json'` → `jsonrpc`,
   `res.groups.category_id` → `privilege_id`. Каждый пункт с `file:line` 19.0.
2. **Формат Context Brief** (ячейка «Источник» = `file:line` / `NOT FOUND` /
   `UNCERTAIN: …` / `AMBIGUOUS: …`; «нет цитаты — нет кода»; NOT FOUND только
   по реальному поиску, сломанный grep не считается) → в `source-check` и
   предложением в `odoo19-mvp-build:code-dev` (`proposals/`).
3. **Исходники 19.0 в облаке**: рецепт sparse-клона `odoo/odoo@19.0`
   (`odoo/` + нужные `addons/*/models`, несколько секунд) в scratchpad,
   чтобы цитировать `file:line`, а не память. В `source-check` как
   источник уровня выше документации.
4. **`odoo_trace.py`** — кандидат в движок проверки `field`/`xmlid`/`method`
   поверх нашего `odoo-model-map`. Сначала прогон на клоне 19.0 (нужно
   разрешение), потом A/B на кейсах `partner_id.mobile` / `groups_id`.
   Если работает — вендорить с пином коммита и атрибуцией.
5. **Definition of done** → `odoo19-mvp-build:testing`: ловушка `of 0 tests`
   при `-u` на БД без модуля; миграция выполняется, только если её версия
   выше установленной и не выше манифеста; `--test-tags /module`; 19.0 без
   демо-данных по умолчанию.
6. **Правила ревью** → `proposals/odoo19-mvp-build/security-review`:
   переменная от `sudo()` с суффиксом `_sudo`, не возвращать её из
   публичного метода; каждый `sudo()` обоснован ACL/правилом, которое он
   обходит, и проверкой перед ним.

## Риски и заметки

- Не ставить плагин целиком: `odoo-workflow` описан как «Mandatory … ANY
  Odoo change» и перехватит наши процессные цепочки (`odoo19-mvp-build`);
  `odoo-commit` «имеет приоритет над общими скиллами коммита» и запрещает
  атрибуцию.
- Без исходников Odoo рядом метод деградирует до справочников, а они не
  покрывают поля бизнес-моделей.
- Поле `globs:` во фронтматтере — формат Cursor, Claude Code его не читает.
