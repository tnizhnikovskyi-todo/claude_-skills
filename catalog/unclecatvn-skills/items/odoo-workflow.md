- **Дата разбора:** 2026-11-03
- **Вердикт:** адаптировать

## Что делает

Процедура для любой Odoo-правки: определить рантайм и версию, трассировать
каждый затронутый символ по реальным исходникам, записать Context Brief
(у каждой строки `file:line` или явный `NOT FOUND`/`UNCERTAIN`/`AMBIGUOUS`),
сделать минимальный план, реализовать по правилам версии и закрыть
чек-листом: установка с тестами на одноразовой БД, проверка миграции,
загрузка всех файлов, права, i18n. Три режима: полный путь, только Brief
(вопросы «где определено X»), быстрый путь для подписей и опечаток.

## Какую слабость Claude закрывает

Выдуманные поля/методы/xmlid/якоря xpath; переопределение публичного метода
вместо хука; неверный порядок `super()`; хранимое поле без миграции;
магические поля у `_auto = False`; `sudo()` без обоснования; «тесты прошли»
при `of 0 tests`.

## Как устроен

- `SKILL.md` 273 строки: шаги 0–6, таблица команд хелпера, grep-рецепты
  V1–V3 (вью и якоря), W1–W2 (OWL/JS), C1 (роуты), S1 (права), U1 (все
  использования перед переименованием), T1 (тесты); бюджет чтения
  (≤120 строк на хоп, ≤3 хопа, дальше — агент).
- `scripts/odoo_trace.py`, 1356 строк, stdlib: `env`, `roots`, `model`,
  `field` (путь через точки проверяется по хопам), `method` (порядок
  переопределений, `NOT in depends`, AMBIGUOUS), `depends`, `xmlid`
  (включая генерируемые `model_*`, `field_*`, `base.module_*`), `unlisted`.
  Без `subprocess`, сети и записи; манифесты через `ast.literal_eval`.
- `references/definition-of-done.md`, 142 строки: точные команды
  `odoo-bin` для 18/19, ловушки (`of 0 tests`, занятый порт, `--workers=0`,
  версия миграции против манифеста, `db duplicate` рвёт соединения).
- `templates/CLAUDE.md`: шаблон проектных правил.

## Сравнение с нашим

- **`boost:odoo-model-map`**: тоже stdlib-скрипт, но про наши аддоны:
  строковые связи, вью, права, «что заденет переименование», ядро не
  смотрит. `odoo_trace` идёт в ядро по `addons_path`, знает правила `_name`
  версии, порядок `super()`, генерируемые xmlid, незагружаемые файлы, и
  даёт однозначный NOT FOUND. Пересечение — рецепт U1 и наш поиск
  использований; в остальном дополняют друг друга.
- **`boost:source-check`**: тот же принцип «нет источника — нет утверждения»,
  но доказательство у нас URL документации, у них `file:line` исходника.
  Для Odoo исходник сильнее и ловит то, чего нет в документации (удалённые
  поля бизнес-моделей). Правило «сломанный grep не равен NOT FOUND» у нас
  отсутствует.
- **`odoo19-mvp-build:code-dev`**: не сравнили, текста нет в сессии.

## Риски и заметки

  граница покрытия).
- DoD рассчитан на локальную машину с Postgres; у нас в облаке его нет.
