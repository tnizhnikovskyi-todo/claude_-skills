# claude-mem-cowork (`cowork/`)

- **Тип:** плагин (хуки + скиллы `mem-search`, `mem-setup`, `agent-cost-report`)
- **Источник:** https://github.com/thedotmack/claude-mem/tree/main/cowork
- **Версия / коммит:** 0.1.4, `26ccf4d`
- **Дата разбора:** 2026-11-02
- **Вердикт:** **отклонить** (безопасность 0 для наших данных)

## Что делает

Вариант claude-mem для облачных сессий Claude (Cowork, веб, мобильное
приложение). Локальный воркер в эфемерном контейнере не выживает, поэтому
хуки — тонкие HTTPS-прокладки к `cmem.ai`. Там платный Pro-сервис крутит
наблюдателя и хранит память, а на старте сессии и при запуске субагента
подмешивает скомпилированный контекст.

## Как устроен

`cowork/hooks/hooks.json` → `node scripts/cmem-hook.mjs <событие>` (1186 строк):

| Хук | Что отправляет на cmem.ai |
|---|---|
| `SessionStart` | регистрация сессии, получение контекста (до 6000 символов) |
| `UserPromptSubmit` | **текст промпта**; при первом промпте — поиск по памяти |
| `PostToolUse` `*` | **сырой вход и вывод любого инструмента**, обрезка 16 КБ на поле |
| `PreToolUse` `Task\|Agent` | промпт субагента → релевантные наблюдения подставляются в него |
| `Stop`, `SubagentStop`, `SessionEnd` | сигналы границ |

Если cmem.ai недоступен, события копятся в `~/.claude-mem/cowork-spool.jsonl`
и досылаются позже. Ключ берётся из env `CMEM_API_KEY`, из `config.json`
плагина (рекомендуют вписать прямо туда и перепаковать плагин) или из
`~/.claude-mem/settings.json`. Для режима Claude Duet проект называется
по имени и id канала.

## Почему отклонить

- Весь вывод инструментов, включая Gmail, Odoo, Drive и Unitalk, и все
  промпты уходят третьей стороне (cmem.ai, один автор, коммерческий сервис).
  У нас нет договора об обработке данных с ними.
- Рекомендуемый способ хранить ключ — вписать его в `config.json` плагина,
  то есть в распространяемый артефакт.
- Чтобы работало, политика сети окружения должна разрешить `cmem.ai`.
- Альтернатива для облака без третьих сторон — своя память в репозитории
  (см. `summary.md`).
