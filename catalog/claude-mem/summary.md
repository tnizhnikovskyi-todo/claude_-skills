# claude-mem: итог для главной сессии

**Что это.** Плагин Claude Code (Apache-2.0, v15.8.3, очень активный). Хуки
перехватывают каждый промпт и каждый вызов инструмента (полный вход и вывод),
локальный воркер на Bun сжимает их моделью-наблюдателем (по умолчанию Haiku
на вашей подписке) в «наблюдения» и хранит в SQLite + Chroma в `~/.claude-mem`.
На старте сессии подмешивает индекс (≤ 10 000 символов), дальше Claude ищет
в истории через MCP (search → timeline → get_observations).

**Безопасность.** По умолчанию сохраняет всё, включая вывод MCP-коннекторов
(Gmail, Odoo, Unitalk) и секреты из `Bash`. Маскировка секретов выключена,
телеметрия PostHog включена (обезличенная). HTTP API на 127.0.0.1 без
токена. Установщик выполняет `curl | bash` (Bun, uv) и зазывает на cmem.ai Pro.
Наблюдатель изолирован хорошо (`tools: []` и т.д.).

**Облако.** В нашей эфемерной облачной сессии память умирает с контейнером.
Выжить может только через `claude-mem-cowork`/cloud-sync, то есть отправку
сырых данных на cmem.ai. Это отклонить.

**Вердикт.** Ядро 11/18, **адаптировать**: как есть не ставить. Облачный
вариант **отклонить** (безопасность 0). Локально на личных некоммерческих
проектах — можно, только со строгими настройками (в `README.md`).

**Что взять.** 1) Индекс на старте вместо полного содержимого и
трёхшаговый поиск. 2) Типизированные наблюдения (decision/bugfix/discovery).
3) Тег `<private>`. 4) Идея `handoff`: `HANDOFF.md`/`memory/` в ветке
переживает контейнер. Свой скилл + `SessionStart`-хук на ~50 строк закроет
пробел памяти для облачных сессий без третьих сторон.
