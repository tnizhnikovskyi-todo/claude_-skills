# claude-mem

- **Тип:** плагин Claude Code (хуки + MCP-сервер + скиллы + фоновый воркер); отдельно плагин `claude-mem-cowork` для облачных сессий
- **Источник:** https://github.com/thedotmack/claude-mem
- **Версия / коммит:** v15.8.3, `26ccf4d` (2026-11-02)
- **Дата разбора:** 2026-11-02
- **Вердикт:** **адаптировать** (идею и приёмы). Как есть не ставить: ни в облачные сессии, ни на машины с клиентскими проектами. Облачный вариант `claude-mem-cowork` **отклонить**.

## Что делает

Пишет всё, что Claude делает в сессии, и на следующий день подсказывает ему,
что было вчера. Хуки Claude Code перехватывают каждый вызов инструмента
(полный вход и полный вывод) и каждый промпт пользователя и складывают их в
локальный фоновый воркер. Воркер отдаёт сырые события отдельной
модели-«наблюдателю» (по умолчанию Haiku через вашу подписку Claude).
Наблюдатель сжимает их в короткие «наблюдения» (decision / bugfix / feature /
discovery…) и сводки сессий. Всё хранится в SQLite и векторной базе Chroma
в `~/.claude-mem/`. При старте новой сессии в контекст подмешивается индекс
последних наблюдений (до 10 000 символов). Дальше Claude сам ищет подробности
через MCP-инструменты `search` → `timeline` → `get_observations`.

## Какую слабость Claude закрывает

Пробел из `inventory/current.md`: между сессиями помнится только `CLAUDE.md`.
claude-mem даёт автоматическую память по проектам. Что решали, какие баги
чинили, какие файлы трогали. Ничего не нужно записывать руками.

## Как устроен (кратко, подробно в карточке ядра)

- **Хуки** (`plugin/hooks/hooks.json`): `Setup`, `SessionStart` (×3),
  `UserPromptSubmit`, `PreToolUse` (на `Read|Bash|Grep|Glob`),
  `PostToolUse` и `PostToolUseFailure` на `*`, `Stop`, `SubagentStop`,
  `SessionEnd`. Каждый запускает бинарник-лаунчер `claude-mem` с PATH.
- **Что пишется:** полный `tool_input` и `tool_response` каждого инструмента,
  текст промптов, последнее сообщение ассистента (для сводки), копии
  «результатов» хода в `~/.claude-mem/deliverables/` (по умолчанию ВКЛ).
- **Куда уходит:** локально в SQLite/Chroma; модели-наблюдателю (по умолчанию
  `claude` через Agent SDK и вашу подписку, можно Gemini, OpenRouter, любой
  OpenAI-совместимый, Pro-наблюдатель на cmem.ai). Поля режутся до 16 000
  символов. Телеметрия в PostHog **включена по умолчанию** (обезличенная,
  без содержимого). Синхронизация с `sync.cmem.ai` по умолчанию выключена.
- **Сеть:** воркер слушает `127.0.0.1`, порт `37700 + uid%100`. Запросы без
  `Origin` (хуки, curl, любой локальный процесс) принимаются без токена.
  Установщик запускает `curl … | bash` для Bun и uv, а Chroma тянет
  `chroma-mcp` из PyPI и модель эмбеддингов.
- **Подмешивание в контекст:** на `SessionStart` до 10 000 символов
  (≈2,5–3 тыс. токенов), плюс описания 30 скиллов (~8 КБ, ≈2 тыс. токенов),
  плюс ~26 MCP-инструментов. На каждый `Read` файла > 1,5 КБ добавляется
  таймлайн наблюдений по нему. Целое чтение файла ≥ 32 КБ с историей
  **блокируется** («File Read Gate»): Claude отправляют к `smart_outline`.

## Оценка (ядро)

| Критерий | Балл | Комментарий |
|---|---|---|
| Прирост | 2 | Реально закрывает пробел памяти, но часть пользы уже даёт аккуратный `CLAUDE.md` + handoff-заметки |
| Частота | 3 | Работает в каждой сессии |
| Надёжность | 1 | Много движущихся частей (Bun, uv, Chroma, воркер, лаунчер на PATH); 878 коммитов за октябрь: всё постоянно меняется; гейт может запрещать `Read` |
| Стоимость контекста | 1 | ~5 тыс. токенов на старте всегда + добавки на каждый `Read` |
| Безопасность | 1 | Код открыт и местами грамотно защищён, но по умолчанию сохраняет всё, включая секреты из вывода; маскировка выключена; телеметрия включена; HTTP без авторизации на localhost; `curl \| bash` при установке |
| Поддержка | 3 | Очень активно, Apache-2.0, но по сути один автор и коммерческий upsell (cmem.ai Pro) |
| **Итого** | **11/18** | Безопасность не 0 только потому, что локальный режим можно настроить строго |

## Облачная сессия vs локальная машина

| | Облачная сессия Claude Code (наш случай) | Локальная машина |
|---|---|---|
| Где живёт память | `~/.claude-mem` в эфемерном контейнере, **исчезает** вместе с ним | Сохраняется |
| Чтобы память пережила сессию | Только облако `cmem.ai` (третья сторона, платно) или свой сервер (`docker-compose`, Postgres + Redis) | Не нужно |
| Установка | Каждый новый контейнер: Bun, uv, chroma-mcp, модель эмбеддингов (минуты, сеть) | Один раз |
| Наблюдатель | Нужен логин Claude/ключ API внутри контейнера, отдельный процесс `claude` | Подписка пользователя |
| Сеть | Политика окружения должна пускать `cmem.ai`, `bun.sh`, `astral.sh`, PyPI, PostHog | Свободно |
| Вывод | Практически непригодно без отправки данных в cmem.ai | Работает, но требует строгой настройки |

## Рекомендация

1. **Не ставить** claude-mem в облачные сессии и на машины, где есть клиентские
   данные (Odoo-базы, ITE, письма, транскрипты): он сохраняет и отдаёт модели
   полный вывод всех MCP-инструментов, включая Gmail, Odoo и Unitalk.
2. **Адаптировать идеи** в свой лёгкий механизм памяти (см. «Что взять»
   в [summary.md](summary.md)): индекс на старте сессии вместо полного
   содержимого, поиск в три шага, типы наблюдений, тег `<private>`,
   handoff-файл в репозитории.
3. Если кто-то хочет попробовать **лично на своей машине и на своих
   некоммерческих проектах**, только со строгими настройками (ниже).

## Если всё же ставить локально: безопасная настройка

Установка без облачного входа и без телеметрии:

```bash
export DO_NOT_TRACK=1                # телеметрия PostHog выключена всегда
export CLAUDE_MEM_ONLINE_OPTIN=false # установщик не предлагает вход на cmem.ai
npx claude-mem@15.8.3 install --provider claude   # версию фиксировать!
npx claude-mem telemetry disable
```

`~/.claude-mem/settings.json`:

```json
{
  "CLAUDE_MEM_PROVIDER": "claude",
  "CLAUDE_MEM_QUOTA_FALLBACK_PROVIDER": "off",
  "CLAUDE_MEM_CLOUD_SYNC_HUB_URL": "",
  "CLAUDE_MEM_REDACT_ENABLED": "true",
  "CLAUDE_MEM_REDACT_GENERIC_ENABLED": "true",
  "CLAUDE_MEM_EXCLUDED_PROJECTS": "**/clients/**,**/odoo*/**,**/*-prod/**",
  "CLAUDE_MEM_SKIP_TOOLS": "ListMcpResourcesTool,SlashCommand,Skill,TodoWrite,AskUserQuestion,mcp__*",
  "CLAUDE_MEM_SKIP_BASH_PATTERNS": "(\\benv\\b|printenv|\\.env|secret|token|password|passwd|credentials|id_rsa|\\.pem)",
  "CLAUDE_MEM_SKIP_SUBAGENT_OBSERVATIONS": "true",
  "CLAUDE_MEM_DELIVERABLES_ENABLED": "false",
  "CLAUDE_MEM_MEDIA_CAPTURE_ENABLED": "false",
  "CLAUDE_MEM_FILE_READ_GATE_ENABLED": "false",
  "CLAUDE_MEM_TRANSCRIPTS_ENABLED": "false",
  "CLAUDE_MEM_CONTEXT_OBSERVATIONS": "20"
}
```

Оговорки: формат шаблонов в `CLAUDE_MEM_SKIP_TOOLS` (поддерживается ли
`mcp__*`) и в `CLAUDE_MEM_EXCLUDED_PROJECTS` по коду не до конца проверен,
это нужно проверить на тесте. Маскировка регулярками ловит известные форматы
ключей (`sk-`, `ghp_`, AWS, JWT, PEM…) и `password=`/`*_TOKEN=`, но не ловит
произвольные пароли Odoo, персональные данные и содержимое писем. Для
разовых секретов в промпте оборачивать их в `<private>…</private>`.

Удаление: `npx claude-mem uninstall`, затем вручную `rm -rf ~/.claude-mem`
(деинсталлятор данные **сохраняет**) и убрать лаунчер из PATH.

## Риски и заметки

- В названии и README обещаны «4 MCP-инструмента», по факту в `mcp-server`
  их ~26 (corpus, team, work_state, smart_* и др.).
- Установщик по умолчанию ведёт в вход на cmem.ai и 30-дневный триал
  Pro-наблюдателя. Это хостинговая обработка ваших данных. По README,
  вынос наблюдателя за пределы плана даёт «до 100% больше usage». Значит,
  наблюдатель на вашей подписке может съедать до половины лимита: каждый
  вызов инструмента (до 16 000 символов входа и столько же вывода) уходит
  в Haiku, плюс сводка на каждом `Stop`.
- Плагин обновляется через маркетплейс; при ~30 коммитах в день поведение
  хуков меняется без ревью с нашей стороны. Версию фиксировать.
- Подробности по каждому пункту и ссылки на файлы: [notes.md](notes.md).
