# SkillOpt — кратко для главной сессии

- **Что это:** Microsoft Research (MIT, ★18.9k, активно). Обучение текста скилла как «весов»: модель решает задачи, оптимизатор по провалам предлагает ≤4 правки, правка принимается только если поднимает счёт на отложенной выборке. Плюс SkillOpt-Sleep: плагин Claude Code, который ночью майнит задачи из транскриптов `~/.claude/projects` и предлагает правила в `CLAUDE.md`/`SKILL.md` через staging и ручной `adopt`.
- **Гипотеза подтверждается частично:** улучшает автоматически, но только под машинную проверку (exact-match, рубрика LLM-судьи). Replay — ответ текстом без инструментов, ≤512 токенов: наши скиллы-действия (`interview-me`, `skill-feedback`, `source-check`) так не измерить. Нужен датасет.
- **Не ставить:** не работает в облаке (транскрипты, cron и состояние эфемерны), шлёт куски транскриптов провайдеру без гарантии очистки, `pip install`, широкий триггер, второй писатель в `CLAUDE.md` рядом с `cloud-memory`. Стоимость ~до 400k токенов/ночь (учёт занижен).
- **Лучшее доказательство для нас:** без гейта качество 0.554 → 0.026 за 5 итераций, с гейтом без потерь — подтверждает правило «без положительной A/B не сливать».
- **Взять в `weekly-review.md` / `skill-feedback`:** (1) решение о слиянии по кейсам, не писавшимся под правку (отложенные); (2) no-regression по каждому кейсу, а не по среднему; (3) бюджет ≤4 правил за ревью в форме op/anchor/правило/почему, отклонённые правки — в `resolution`; (4) тест «нарушение vs дефект» (есть правило, которое предотвратило бы? → `violation`, текст не трогать; при сомнении — `violation`); (5) правка описывает поведение, а не текст грейдера.
- **Опционально (решение пользователя):** поиск замечаний по русским фразам недовольства в облачных сессиях через `list_events`.
