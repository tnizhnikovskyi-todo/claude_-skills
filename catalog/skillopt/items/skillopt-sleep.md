# SkillOpt-Sleep (плагин для Claude Code + `skillopt-sleep` CLI)

- **Тип:** плагин (скилл + 2 команды + хук `SessionEnd`) поверх Python-движка `skillopt_sleep/`
- **Источник:** https://github.com/microsoft/SkillOpt/tree/main/plugins/claude-code
- **Разобранный коммит:** `bc0a392ef0a7f92840ec673d80204d34ced169d0` (плагин 0.1.0, движок 0.2.0)
- **Лицензия:** MIT
- **Дата разбора:** 2026-11-03
- **Вердикт:** отклонить установку; адаптировать идеи в `skill-feedback` и еженедельное ревью

## Что делает

«Ночной цикл» самоулучшения по своим сессиям: читает транскрипты Claude Code
за 72 часа, LLM-майнер выделяет повторяющиеся задачи (до 40) с проверками и
рубрикой, прогоняет их с текущими `CLAUDE.md` и управляемым `SKILL.md`
(`~/.claude/skills/skillopt-sleep-learned/`), оптимизатор по провалам на
train предлагает до 4 правил, гейт на 34% задач (val) принимает только
улучшение. Предложение кладётся в `<project>/.skillopt-sleep/staging/<ts>/`
с отчётом; живые файлы меняет только `adopt` (с бэкапом).

## Какую слабость Claude закрывает

Повторяющиеся поправки пользователя не превращаются в правила сами. То же,
что у нас закрывает `skill-feedback` + еженедельное ревью, но автоматически,
без человека в начале цепочки.

## Как устроен

- **Скилл** `skillopt-sleep`: широкое `description` («make my agent better
  the more I use it», «review my past sessions»…), ~150 строк, вызывает
  `scripts/sleep.sh` → `run-sleep.sh` → `skillopt-sleep` CLI из `pip`/`uv`.
- **Хук** `SessionEnd`, async: пишет `время\tPWD` в
  `~/.skillopt-sleep/session-end.log`. Больше ничего.
- **Расписание:** `schedule` ставит cron-запись.
- **Бэкенды:** `mock` по умолчанию (без сети), `claude` = `claude -p
  --disallowedTools '*' --disable-slash-commands
  --exclude-dynamic-system-prompt-sections` в пустом temp-каталоге, модель
  `sonnet`; также codex, copilot, cursor, Azure, OpenAI-совместимые.
- **Промпты** (`skillopt_sleep/prompts.py`): miner, attempt (ответ до 512
  токенов, только текст), judge (рубрика, hard при score ≥ 0.8), reflect
  («общее правило, а не ответ на задачу», «чини поведение, а не подражай
  проверке», «правила только дописываются в Learned preferences»).
- **Бюджет:** 400 000 токенов и 40 задач за ночь (учёт `len//4`, без
  системного промпта Claude Code, т.е. занижен).
- **Данные:** обрезанные куски транскриптов уходят провайдеру; авторы
  прямо пишут, что секреты не гарантированно вычищены. Локальный
  `evidence.jsonl` хранит копии всех промптов.

## Проверка

Не запускали. Теоретически применимость к нашим скиллам:

| Скилл | Что надо мерить | Меряет ли Sleep |
|---|---|---|
| `interview-me` | вопрос задан ДО правок | нет: reflect запрещает правило «спросить пользователя», replay без инструментов |
| `skill-feedback` | файл в `observations/`, скилл не тронут, нет пароля | нет: replay без Write, только текст |
| `source-check` | URL и цитата в ответе | частично: regex/рубрика по тексту, но без WebFetch |
| `repo-audit` | формат из 4 частей | да (по тексту), но это мы уже меряем в `evals/` |

## Риски и заметки

- Облако: транскрипты, `~/.skillopt-sleep` и cron живут в эфемерном
  контейнере, следующая сессия их не увидит.
- Автоматически правит `CLAUDE.md`: у нас память в git через `cloud-memory`,
  двойной писатель в одну память — конфликт.
- Широкое `description` противоречит нашему правилу узкого триггера.
