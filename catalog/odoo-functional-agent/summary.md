# odoo-functional-agent — итог для главной сессии

- **Что это:** плагин Claude Code (MIT, сверено по `LICENSE`; 1 автор, 0★, неделя
  жизни, v0.1.3 @ `084b690`) «требование → план конфигурации → явное одобрение →
  freeze по SHA-256 → идемпотентный apply → JSON-сценарии → отчёт» для **Odoo 20**
  на **локальной** демо-базе через CLI `ofa` (stdlib, JSON-2 на loopback). Телеметрии нет.
- **Защита записи — лучшая идея:** позитивный маркер. `ofa` пишет UUID в
  `ir.config_parameter` при создании базы и сверяет его с реестром перед каждым
  открытием клиента; плюс имя `ofa_demo_*`, loopback, `dbfilter`, `max_cron_threads=0`.
  Наш `demo-base-builder` проверяет негатив («`web.base.url` = прод → стоп»), а
  `odoo-connector` не проверяет ничего (F1).
- **Сверх нашего:** правила одобрения («вопрос/комментарий/давнее "делай всё" —
  не одобрение», правка → новое одобрение, цитата в отчёте); `pre_state` («уже
  было в шаблоне — ничего не доказывает»); чтение назад `VALUE_NOT_HELD`; «Test
  plan» на каждую потребность с **Not tested**; роли на тест-пользователях без
  админ-групп (админ обходит согласования); негатив с текстом ошибки из исходника.
- **Минусы:** хуки на каждый Bash/Skill/промпт во всех сессиях машины (запуск
  Python), очень широкий триггер, только Odoo 20 + локальный Odoo/Postgres, в
  облаке не работает; отчёты прогонов в `.gitignore` — результаты не проверить.
