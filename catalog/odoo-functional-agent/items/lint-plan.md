# `ofa lint-plan`: имена плана против базы и исходников

- **Источник:** `docs/plan_format.md` («lint-plan»), `src/ofa/lint.py`,
  `src/ofa/source_index.py` @ `084b690`
- **Вердикт:** идея для T2 (линтер-барьер); код не берём

## Что делает

Проверяет каждый модуль, модель, поле, ключ настроек, метод, xmlid и значение
selection в `plan.json`, и каждое имя в обратных кавычках в `plan.md`:
1. сначала по целевой базе — `ir.module.module`, `ir.model`, **`ir.model.fields`
   (не `fields_get`, который прячет поля по группам)**, `ir.model.data`;
2. чего нет в базе (модуль ещё не установлен) — по статическому индексу исходников
   (`ast` по Python, regex по XML), кэш вне репо, ключ — коммиты checkout'ов.

Коды: `NOT_IN_20`, `NEEDS_MODULE` (имя есть только в модуле, который план не
ставит), `BAD_SELECTION`, `UNRESOLVED_REF`, `EDITION`. Ошибки в `plan.json`
блокируют (exit 2), в `plan.md` — предупреждения, которые нельзя «чинить»
переформулировкой: они идут в раздел «Names to review» стопа ревью. Единственное
разрешённое игнорирование — имя, которое проза упоминает именно как удалённое.

## Сравнение

Тот же класс проблемы, что T1/T2 (поля, удалённые в 19.0). Новое для нас:
`NEEDS_MODULE` и подход «база + индекс исходников для неустановленных модулей»;
правило «предупреждения прозы не прятать, а показывать ревьюеру».

Факт сверен: `fields_get` в 19.0 фильтрует по `_has_field_access`
(`odoo/orm/models.py:3364` @ 19.0 `e0b25b7`).
