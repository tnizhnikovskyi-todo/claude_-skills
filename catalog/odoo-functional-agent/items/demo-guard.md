# Guard: защита от записи не в ту базу

- **Источник:** `docs/guard.md`, `src/ofa/guard.py`, `src/ofa/client.py`,
  `hooks/hooks.json`, `hooks/ofa_guard.sh`, `hooks/ofa_guard_hook.py` @ `084b690`
- **Вердикт:** адаптировать идею слоя a (маркер); хук не берём

## Что делает

Три слоя, ни одному не доверяют в одиночку:

1. **Слой a — клиент `ofa`.** Единственный конструктор `open_client` проверяет до
   первого вызова: цель есть в локальном реестре (`~/.config/ofa/config.toml`),
   имя базы `^ofa_demo_[a-z0-9_]{1,40}$`, хост URL — loopback, и в базе
   `ir.config_parameter` `ofa.demo_marker` равен UUID, записанному при
   `ofa provision`. Маркер проверяется **на каждое открытие**, для чтения тоже.
   Нет маркера → `MARKER_MISSING`, не совпал → `MARKER_MISMATCH`, ключ не может
   прочитать → `MARKER_UNVERIFIABLE` (это отказ guard, а не ошибка среды).
   API-ключи создаёт только `provision`, и только для демо-баз.
2. **Слой b — `PreToolUse`-хук.** Разбирает каждую Bash-команду (shlex, подстановки,
   `bash -c`, `eval`, префиксы вроде `sudo`/`xargs`) и запрещает `psql`, `odoo-bin`,
   HTTP к `/json/2/`, `/jsonrpc`, `/xmlrpc`, порты 8060–8099 и 5432; навигацию
   браузера вне loopback и allowlist доков. Включается только после того, как
   сессия «использовала агента», и остаётся включённым после `/clear`, `/compact`,
   форков.
3. **Конфиг сервера:** `dbfilter = ^ofa_demo_.*$`, `list_db = False`,
   `max_cron_threads = 0`, `proxy_mode = False`; `ofa server start` отказывается
   стартовать без них.

## Что сверх нашего

Наш `demo-base-builder` (Шаг 0) проверяет **негатив**: читает `web.base.url` и
останавливается, если это прод. Это ловит только известный прод. Маркер — это
**позитив**: писать можно только туда, где лежит наш UUID, который мы сами
положили при создании стенда. Чужая база, копия прода под другим URL, база без
маркера — всё отказ по умолчанию. Плюс проверка вшита в код, а не в текст скилла
(F1: у `odoo-connector` серверных проверок нет).

## Перенос на Odoo 19 и наш стек

- В 19.0 нет `get_str`: маркер читается `ir.config_parameter.get_param`
  (`odoo/addons/base/models/ir_config_parameter.py:60` @ 19.0 `e0b25b7`), пишется `set_param` (`:82`).
  Чтение требует `base.group_system`, как и у них.
- Куда: в сервер `odoo-connector` (T3) — перед любым изменяющим вызовом
  (`create`/`write`/`unlink`/`execute` не из allowlist чтения) сверять маркер базы
  `connection_id` с реестром «стенд → UUID»; кэш на сессию. В `demo-base-builder`
  Шаг 0 — заменить/дополнить проверку `web.base.url` проверкой маркера, а `database.uuid`
  оставить как идентификатор в знімку (снимке).
- Прод никогда не получает маркер: процедура создания стенда пишет его, а реестр
  живёт в git с ревью.

## Не берём

Хук: always-on (каждый Bash/Skill/промпт во всех сессиях → Python), шаблонный
анализ команд с известными дырами, рассчитан на локальный Odoo. Наша запись идёт
через MCP — барьер должен быть в MCP-сервере.
