# Odoo-модуль `mcp_server` (much. Consulting)

- **Источник:** https://apps.odoo.com/apps/modules/19.0/mcp_server (версии 16–20)
- **Лицензия:** **OPL-1** (Odoo Proprietary License): код нельзя
  распространять и публиковать; 7679 строк; зависимости `authlib`,
  `defusedxml`, `packaging`; зависит от `mail`
- **Что читали:** только страницу описания (2026-11-03). Код модуля не
  читали — всё ниже «по описанию», не проверено.

## Что заявлено

- Собственный MCP-эндпоинт `/mcp` (Streamable HTTP, JSON-RPC 2.0) прямо в
  Odoo: Claude.ai / Desktop / Code подключаются без отдельного процесса;
  `mcp-server-odoo` нужен только как stdio-мост.
- OAuth 2.1 (DCR, PKCE S256, привязка токена к ресурсу по RFC 8707,
  экран согласия), либо bearer-ключ со scope «MCP only».
- Группы **MCP User** / **MCP Administrator**; без группы — отказ (с
  записью в аудит), снятие группы гасит ключи и токены.
- Модели: allowlist с флагами read/write/create/delete + «Allow Method Calls».
- **Custom Tools:** именованные глаголы на серверных действиях со своей
  схемой, группами, флагом read-only; исполняются под правами вызывающего,
  откат всего вызова при ошибке, аудит.
- Аудит каждого вызова, отказа и входа; хранение `log_retention_days`
  (по умолч. 30), чистит cron. Rate limit на пользователя. Allowlist Origin.
- Несколько баз: host → база (`dbfilter`) или заголовок `X-Odoo-Database`.

## Для нас

Это и есть настоящий «сервер с проверками», которого не хватает
`odoo-connector` (F1). Варианты:

1. **Не ставить у клиентов** без отдельного решения: OPL, сторонний
   вендор с доступом к данным, код не читали.
2. **Взять идеи** в T3: группа-допуск, scope ключа, Custom Tools как
   альтернатива общему `write`, аудит в самой Odoo (а не в файле у
   агента) — если когда-то будем делать свой Odoo-модуль для коннектора.
3. Если пользователь захочет оценить сам модуль — нужен отдельный разбор
   кода (скачивание с apps.odoo.com требует аккаунта), публиковать его
   код у нас нельзя.
