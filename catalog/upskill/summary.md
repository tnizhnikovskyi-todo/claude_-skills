# upskill (huggingface/upskill) — кратко для главной сессии

- **Что это:** CLI Hugging Face (Apache-2.0, сверено по `LICENSE`; разобран `eec8ab4`, 2026-10-14). Сильная модель пишет `SKILL.md` (200–400 слов) и 3–5 синтетических кейсов с подстроками, A/B со скиллом/без, до 2 правок по провалам; `eval -m haiku -m sonnet` — матрица «скилл × модель»; запуск через fast-agent локально или в HF Jobs.
- **Методически слабее нашего `claude plugin eval`:** правит и оценивает на одних кейсах (без отложенной выборки), в промпт правки уходят строки грейдера, грейдер — подстрока, нет негативных кейсов и проверки триггера, 1 прогон, меряет в fast-agent, а не в Claude Code.
- **Безопасность 2/3:** телеметрии нет; но пример-конфиг пробрасывает `HF_TOKEN` и `ANTHROPIC_API_KEY` в HF Jobs и грузит скилл/кейсы/ответы в датасет HF, верификатор `command` — `shell=True` из файла кейсов, `propose-skills.sh` шлёт 50 сообщений истории в `claude -p` и пишет в глобальные `~/.claude/skills`.
- **Сверх нашего (взять идеями):**
  1. вклад каждого скилла в плагине (leave-one-out, флаг «прошло и без скилла» → кандидат на вывод) — `evals/README.md`, `weekly-review.md`;
  2. A/B только для скиллов, чьи папки изменились (`git diff` → `SKILL.md`) — `weekly-review.md`;
  3. правило принятия «Δ > 0.05 или качество то же и токенов −20%» — `evals/README.md`, `criteria.md`;
  4. A/B на второй, дешёвой модели для скиллов субагентов и задач по расписанию;
  5. ≤ 2 итерации правки скилла за ревью, стоп по плато (< 0.05).
- **Антипаттерны в `weekly-review.md`:** правка и оценка на одних кейсах; строки грейдера в промпте правки — подтверждает выводы skillopt.
