# upskill generate + цикл улучшения

- **Тип:** команда CLI (`upskill generate`)
- **Источник:** `src/upskill/generate.py`, `src/upskill/agent_cards/skill_gen.md`, `src/upskill/cli.py:582-797` @ `eec8ab4`
- **Лицензия:** Apache-2.0
- **Вердикт:** отклонить как инструмент; взять идею «стоп по плато» (README, идея 5) и записать антипаттерны (идея 6)

## Что делает

Модель-генератор по описанию задачи (и, по желанию, примерам или трейсу,
обрезанному до 4000 символов) пишет `SKILL.md`: frontmatter `name` +
`description` (< 100 символов), тело 200–400 слов, 2–3 примера кода. Затем
кейсы прогоняются со скиллом и без; если прирост не дотягивает до
`is_beneficial`, скилл правится по трём провалам (до 2 попыток), стоп при
плато (< 0.05 между попытками). `--from <папка>` улучшает готовый скилл по
инструкции.

## Сильное

- Явный критерий остановки: успех или плато, не больше N попыток.
- Учитель и ученик разделены: генерирует `--model`, проверяется ещё и
  `--eval-model`.

## Слабое

- Правит и оценивает на одних и тех же кейсах: прирост завышен.
- В промпт правки уходят `Expected: {"contains": [...]}` — скилл
  подгоняется под строки грейдера.
- Правка видит только первые 500 символов тела скилла.
- Генерирует только `SKILL.md`: нет `references/`, нет «когда не
  использовать», триггер не проверяется.
- Few-shot примеры — общие «best practices» (git commit, API errors), это
  то, что модель и так знает; наш опыт (`synthesis.md`, п. 2) говорит, что
  такие скиллы прироста не дают.

## Сравнение

`anthropic-skills:skill-creator` + правила `plugins/boost/README.md` (узкий
триггер, компактность, `references/`, A/B) покрывают генерацию лучше.
Цикл правки у нас — `skill-feedback/references/weekly-review.md` с A/B до
слияния; из upskill добавить только лимит итераций и стоп по плато.
