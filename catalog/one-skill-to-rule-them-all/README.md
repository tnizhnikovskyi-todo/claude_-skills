# One Skill to Rule Them All (task-observer)

- **Тип:** скилл (+ манифест плагина `task-observer`, без хуков/MCP)
- **Источник:** https://github.com/rebelytics/one-skill-to-rule-them-all
- **Версия / коммит:** 3.8.1 / `ba696b2` (2026-10-26)
- **Дата разбора:** 2026-11-02
- **Вердикт:** **адаптировать** (метод, формат наблюдений, принципы); как есть не ставить

## Что делает

Мета-скилл, который «наблюдает» за каждой рабочей сессией и копит
структурированные наблюдения: поправки пользователя, нарушения правил
скиллов, повторяющиеся ручные процессы, кандидаты в новые скиллы. Одно
наблюдение = один Markdown-файл с YAML-frontmatter. Раз в неделю (вручную
или по расписанию) проводится ревью: наблюдения превращаются в правки
скиллов на staged-копиях, человек ставит итоговый `.skill`-бандл. Скилл
наблюдает и за собой («улучшает сам себя»). Сам скилл ничего не
устанавливает и чужие живые скиллы не правит.

## Какую слабость Claude закрывает

- **Память и контекст:** поправки не теряются между сессиями; при загрузке
  скилла подтягиваются открытые наблюдения по нему.
- **Метод:** дисциплинированный цикл «трение → запись → ревью → staged →
  установка человеком», плюс правило «второе нарушение одного правила →
  структурный барьер (хук, линт), а не новая формулировка».

## Как устроен

| Компонент | Размер | Что делает |
|---|---|---|
| `SKILL.md` | 682 стр., ~11k токенов | Session Start Protocol, когда/как логировать, формат, статусы, правила действия |
| `references/` (7 файлов) | 8 600 стр., ~500 КБ | Ревью, авторинг скиллов, окружения и хуки, формат лога, сигналы, миграция, стартовые принципы |
| `scripts/` (5 шт.) | bash + python | Создание записи с безопасным id, скан, поиск по скиллу, миграция, валидатор бандла |

- **Активация:** description велит запускать скилл перед ПЕРВЫМ вызовом
  инструмента в ЛЮБОЙ сессии; автор дополнительно требует блок в
  `CLAUDE.md` и/или SessionStart-хук.
- **Сеть:** нет; единственное исключение (по запросу пользователя) это
  `curl` raw-файла с GitHub при подготовке отчёта автору.
- **Запись:** только в свою рабочую папку (`skill-observations/`,
  `skill-updates/`); без `rm`, `mv -n`, noclobber.
- **Лицензия:** CC BY 4.0 (нужна атрибуция при адаптации).
- **Активность:** 374 коммита с 2026-02, релиз 3.8.1 от 2026-10-26.

## Сравнение с тем, что уже есть

- `anthropic-skills:skill-creator`: создаёт/правит/тестирует скилл по
  запросу. task-observer дополняет его, давая входящие «что править и
  почему». Пересечение только в советах по авторингу.
- `cowork-plugin-management:*`: упаковка плагинов, не пересекается.
- `plugin-authoring`: можно использовать, чтобы поставить предлагаемые
  хуки, если решим.
- `CLAUDE.md` / память: факты о проекте; task-observer же про правки
  переиспользуемых скиллов с ревью человеком.

## Применимость к нашему процессу

Наш репозиторий сам похож на лог наблюдений про скиллы. Предложение:
лёгкий вариант без самого скилла:
1. `observations/NNNN-slug.md` в этом репо, тот же frontmatter
   (`status`, `skill`, `proposes_skill`, `siblings_checked`) и тело
   Issue → Improvement → Principle; git = постоянное хранилище.
2. Короткий свой скилл (40–60 строк): когда записывать, формат, «второе
   нарушение → барьер».
3. Главная сессия раз в неделю сводит открытые записи в правки наших
   скиллов через `skill-creator`.
4. Выборку из `starter-principles` и pre-delivery gate из `weekly-review`
   добавить в чек-лист `criteria.md` (по решению главной сессии).

## Риски и заметки

- Если описание сработает «не на той задаче» (а срабатывает на любой):
  постоянный расход ~11k токенов, лишние вызовы, попытки создать папки и
  предложить правку `CLAUDE.md` (для сессий анализа это запрещено нашими
  правилами), Stop-хук может блокировать завершение.
- Модель пишет наблюдения сама: инструкции из недоверенного контента могут
  попасть в лог, а оттуда в правки скиллов. Гейт человека обязателен.
- Подробности: [notes.md](notes.md), коротко: [summary.md](summary.md).
