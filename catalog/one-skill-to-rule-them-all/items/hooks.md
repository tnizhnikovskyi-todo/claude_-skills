# Хуки активации и enforcement (из environments.md)

- **Тип:** хуки Claude Code (образцы кода в `references/environments.md`, не ставятся автоматически)
- **Источник:** https://github.com/rebelytics/one-skill-to-rule-them-all/blob/main/references/environments.md (разделы «A session-start hook», «A stop hook», «A pre-tool hook», «A skill-file write gate»)
- **Версия / коммит:** 3.8.1 / `ba696b2`
- **Дата разбора:** 2026-11-02
- **Вердикт:** адаптировать идею «второе нарушение → барьер»; конкретные хуки не ставить без самого скилла

## Что делает

- **SessionStart** (sh): считает открытые наблюдения и дату ревью, через
  `additionalContext` велит первым вызовом запустить скилл.
- **Stop** (node): если сессия сделала ≥3 вызовов инструментов и ничего
  не записала в лог/`checkpoints.log`, блокирует остановку один раз за
  сессию с напоминанием.
- **PreToolUse** на `Write` (node): запрещает создавать новый `.md` в
  каталоге лога в обход `new-observation.sh` (exit 2).
- **Skill-file write gate**: перед записью любого `SKILL.md` требует
  загрузить `skill-authoring.md`.

## Какую слабость Claude закрывает

Проверку/дисциплину: правило в тексте Claude нарушает; хук отказывает
вызову и не «конкурирует» с остальным контекстом. Это главный тезис
`signals.md` «Second violation — why a barrier, not a rewording».

## Как устроен

Код короткий, читаемый, без сети; fail-open на любые ошибки (кроме
Stop-хука, который при неизвестном времени старта блокирует один раз).
Пишет только маркер в `os.tmpdir()`.

## Риски и заметки

Stop-хук в облачных сессиях с дочерними сессиями может мешать завершению
хаба. Если когда-то ставить, то через `plugin-authoring` / `update-config`.
