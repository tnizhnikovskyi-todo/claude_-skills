# starter-principles (29 кросс-скилловых принципов)

- **Тип:** reference-файл (`references/starter-principles.md`, 504 строки, ~30 КБ)
- **Источник:** https://github.com/rebelytics/one-skill-to-rule-them-all/blob/main/references/starter-principles.md
- **Версия / коммит:** 3.8.1 / `ba696b2`
- **Дата разбора:** 2026-11-02
- **Вердикт:** адаптировать (выбрать 8–10 принципов в наш чек-лист автора скиллов)

## Что делает

Набор общих правил для любых скиллов, выведенный автором из ~1 900
наблюдений по 84 скиллам. При первом запуске task-observer предлагает
импортировать непокрытые пункты (одна строка, по выбору пользователя).

## Какую слабость Claude закрывает

Метод и проверка при написании скиллов: повторяющиеся ошибки авторов.

## Как устроен

Чистый текст. Каждый пункт: «Applies to», «Requirement», обоснование.
Самые полезные для нас:

| № | Принцип | Где у нас пригодится |
|---|---|---|
| 7 | Субагенты получают полный вход, их выход проверяется | Хаб → сессии анализа; `odoo19-mvp-build` |
| 12 | Канонические идентификаторы из исходных данных, не реконструировать | Odoo/ITE: id записей, коды форм |
| 14–15 | Задачи по расписанию вызывают скилл, а не дублируют его логику | `loop`, триггеры |
| 16 | Прерванная операция частична: проверь состояние перед повтором | Odoo-записи, Google-файлы |
| 20 | В скилле только то, что меняет поведение | Наши `tr-*`, протоколы |
| 24 | Сначала получи экземпляр, потом описывай | Разбор чужих скиллов, Odoo-модели |
| 26 | Скилл-компаньон объявляет границу покрытия | `odoo19-*` семья |
| 28 | Отсутствие не доказывается «суммирующим» инструментом (поиск, RAG, превью) | AIKB, ITE-KB, Drive search |
