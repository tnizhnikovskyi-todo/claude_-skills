# weekly-review (процедура ревью и staging)

- **Тип:** reference-файл скилла (`references/weekly-review.md`, 2 185 строк, ~140 КБ)
- **Источник:** https://github.com/rebelytics/one-skill-to-rule-them-all/blob/main/references/weekly-review.md
- **Версия / коммит:** 3.8.1 / `ba696b2`
- **Дата разбора:** 2026-11-02
- **Вердикт:** адаптировать (approval policy и staging-гейт), сам файл не брать

## Что делает

Превращает накопленные наблюдения в правки скиллов. Интерактивно:
группирует по скиллам, помечает «нужно ваше решение», ждёт явного
одобрения. По расписанию без человека: применяет «не-эскалированные»
наблюдения к staged-копиям (`skill-updates/<date>/`), эскалирует новые
скиллы, удаления/перестройки, сомнения и конфликты. Ничего не ставит
сам: человек устанавливает `.skill`-бандл.

## Какую слабость Claude закрывает

Метод: Claude, правя скилл, склонен править «живой» файл, решать по
заголовкам вместо тел, не проверять соседние скиллы и не сверять итог.

## Как устроен

Самое ценное:
- **Approval policy:** «отклонённый диалог одобрения не есть одобрение»,
  «classify before you ask» (сначала читать тела, потом предлагать
  разбивку с реальными числами), отказ инструмента на одобренный шаг не
  повторяется, а передаётся пользователю с путями.
- **Pre-delivery gate** из 8 пунктов: все пути из SKILL.md есть в бандле,
  description ≤1024 символов, `name` = каталог, один frontmatter, нет
  остатков правок (`\1`, конфликт-маркеры, `{{slot}}`).
- **Staged-work reconciliation:** `diff -rq` staged против live и
  классификация каждого расхождения.

Сеть: нет. Записи: только `skill-updates/` и статусы наблюдений.
