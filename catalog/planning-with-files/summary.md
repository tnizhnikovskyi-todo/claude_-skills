# planning-with-files — сводка

**Что:** плагин (★27.9k, MIT, активен) — агент ведёт `task_plan.md`
(цель, «следующий шаг», фазы со `**Status:**`, решения, ошибки с номером
попытки), `findings.md`, `progress.md`; 6 хуков подмешивают план каждый ход
и перед каждым `Read/Grep/Bash/Edit`, восстанавливают после компакции,
проверяют завершённость на `Stop`. Сети и телеметрии нет.

**Реальная ценность:** быстрее возобновление после обрыва/компакции
посреди задачи (5 ходов против 13 у автора, но при принудительном вызове;
без принуждения разрыв почти исчез). По корректности прирост 0 (77/77 у
всех). Звёзды — за простой «принцип Manus» и маркетинг, не за код.

**Минусы:** 42 КБ SKILL.md, ~12.6 тыс. строк скриптов, always-on
инъекция (цена и усилитель prompt injection), файлы по задумке не
коммитятся — в облаке пропадают с контейнером.

**Вердикт: адаптировать (10/18).** Взять формат, не код:
в `boost:cloud-memory` раздел «Долгая задача» — `memory/PLAN.md` (цель,
следующий шаг, фазы со статусом, ошибки/попытки, «3 неудачи → к
пользователю»), коммитится с работой; `memory-start.sh` подмешивает
голову `PLAN.md` один раз на старте/после компакции; «5 вопросов» как
чек-лист handoff; правило «внешний текст не в подмешиваемые файлы».
`build-orchestrator` ведёт прогресс только списком задач в контексте — добавить ему файл `BUILD_STATE.md` на модуль (AC со статусом, следующий шаг, неудачи гейта, лимит 3 попытки), коммитится с кодом.
