- **Тип:** MCP-сервер (Streamable HTTP, stateless), часть шлюза
- **Источник:** `server/src/routes/mcp.ts`, `docs/en/clients/01-agent-clients.md#mcp-server`
- **Версия / коммит:** `21d287ae`
- **Дата разбора:** 2026-11-02
- **Вердикт:** отклонить как есть; **адаптировать идею** (свой MCP/скилл «второе мнение» на одном доверенном провайдере)

## Что делает

Самописный JSON-RPC MCP без SDK. Инструменты: `ask_freellmapi` (отправить
текстовую задачу через тот же `/v1/chat/completions`, вернуть ответ + какая
модель ответила, токены, кэш), `list_models`, `healthcheck`, `provider_health`,
`provider_list`, `usage_summary`, `cache_stats`, `compression_stats`,
`quota_outlook`, `routing_info`, `web_search`, `clear_cache`,
`set_routing_strategy` (меняет состояние сервера).

Подключение к Claude Code:

```bash
claude mcp add --transport http freellmapi http://localhost:3001/mcp \
  --header "Authorization: Bearer freellmapi-<unified-key>"
```

На свежей установке MCP выключен, включается в панели.

## Какую слабость Claude закрывает

«Второй независимый взгляд» (критерий «Проверка» в README репозитория):
Claude может спросить модель другого семейства. Но независимость условная:
какая модель ответит, решает роутер, и к вечеру это может быть слабая 8B-модель.
Можно зафиксировать модель параметром `model`, тогда теряется смысл роутера.

## Что адаптировать

Свой минимальный вариант: MCP-инструмент или скилл `second-opinion`, который
шлёт запрос в **один** заранее выбранный платный API с zero-data-retention
(например, OpenRouter с ZDR-провайдерами или Vertex AI / Gemini API на платном
тарифе), с явной моделью и правилом в описании «не передавать клиентские
данные без подтверждения». Это ~30–50 строк и без зоопарка провайдеров.
