# Данные, сеть и воронка Salespeak

- **Источник:** `salespeak-ai/buyer-eval-skill@ebb0e06`: `SKILL.md` §1,
  `references/frontdoor-api.md`, `references/telemetry.md`, `bin/track.py`,
  `bin/update-check`, `bin/profile.py`, `MEASUREMENT.md`, история `03b18a4`.
- **Вердикт:** не ставить; в оценке безопасность 1.

## Что ставится на машину

- Клон репозитория в `~/.claude/skills/buyer-eval-skill` (13 МБ из-за промо).
- `~/.buyer-eval/last-update-check` — кэш проверки версии.
- `~/.salespeak/buyer-eval-profile.json` — профиль покупателя (белый список:
  компания, размер, отрасль, регион, системы, требования, жёсткие ограничения
  с потолком бюджета, критерии, последняя категория; без имён и документов).
- `~/.salespeak/buyer-eval.json` (согласие и `user_id`), `buyer-eval.log`
  (аудит всего отправленного).
- `~/buyer-eval-reports/*.html` + копия JSON.

Хуков, MCP, бинарников, сторонних пакетов нет. Скрипты stdlib; сеть — через
`curl` в подпроцессе.

| 2 | Каждый запуск, на каждого вендора | `https://hpklbne62y3wpitjb6lc6zyxza0wobdv.lambda-url.us-west-2.on.aws/frontdoor/api/{domain}/discover` | домен вендора (и IP запуска) | **нет** |

| 5 | По согласию | GitHub | `git pull --ff-only origin main` | вопрос перед обновлением; код обновляется с `main` без пина |

## Воронка

- Бизнес Salespeak — ИИ-агенты для сайтов вендоров. Скилл приводит к ним
  покупателей (п. 3) и измеряет спрос (п. 2): `MEASUREMENT.md` называет
  `discover` «лучшим счётчиком запусков, не зависящим от согласия», и
  предлагает группировать логи Lambda по IP источника и часу.
- Телеметрия (п. 4) даёт Salespeak, **какие вендоры сравниваются в какой
  категории, какие вопросы покупатели задают и кто лидирует** — ценные
  данные для продажи агентов вендорам.
- Агенты вендоров — каналы продаж и «логируют разговоры» (их же
  формулировка): вопросы покупателя видит вендор.
- v3 давала преимущество вендорам с агентом Salespeak («authoritative
  source», «Evidence Completeness»); v4.0.0 убрала, ввела правило
  нейтральности. В v3.5 расширили события для уже согласившихся без
  повторного согласия.

## Что хорошо

- README честно перечисляет, что уходит без согласия, даёт адрес
  эндпоинта для блокировки, локальный аудит-лог, отзыв согласия,
  выключатель для админов.
- Правило «не отправлять агенту вендора имя, бюджет, других вендоров»
  появилось после найденной утечки бюджета в v3 — хорошая практика,
  которую стоит помнить, если мы когда-то сделаем свой чат-бот на сайте:
  клиенты будут осторожны с тем, что ему пишут.
