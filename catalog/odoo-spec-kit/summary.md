# odoo-spec-kit: итог для главной сессии

- **Что это:** испаноязычный кит Focuz AI для Odoo поверх OpenSpec: `CLAUDE.md`/`AGENTS.md` → `docs/base-standards.md`, 10 документов стандартов, 3 агента, 16 скиллов (enrich → propose → build-and-qa → ship), `pre-commit` по шаблону OCA. MIT (сверено по `LICENSE`), но внутри чужое: superpowers (MIT), копия документации Anthropic, 3 скилла LIDR.co (лицензия не установлена). ★2, 1 автор, 124 коммита.
- **Главная находка:** ветки `16.0`/`17.0`/`18.0`/`19.0`/`main` — **одно дерево** (`86c4484`). «19.0» — кит под 16.0 (`ODOO_TARGET_VERSION: "16.0"`, `valid-odoo-versions=16.0`).
- **Сверка с `odoo@19.0` (`e0b25b7`):** 14 из 17 утверждений неверны или устарели. Кит **требует** `attrs`/`states` (в 19.0 это ValidationError, `ir_ui_view.py:495-497`), а ещё `<tree>`, `type='json'`, `read_group`, `_sql_constraints`, `hr.contract`, `SavepointCase`, `oe_chatter`, XML-RPC, `useService("rpc"/"user")`, QUnit-хелперы. Модуль по этим правилам не установится. Плюс внутренние противоречия: язык кода, язык коммитов, `_() % x` против их же pylint.
- **Линтеры:** своих правил нет, OCA hooks v0.1.6 и pylint-odoo версионные ловушки 19.0 не ловят. Это подтверждает, что T2 (`boost:odoo19-lint`) не дублирует стандартные инструменты.
- **Безопасность:** хуков, MCP и телеметрии нет; но скиллы сами пушат и открывают PR, `openspec@latest` без пина, хук переписывает `website` манифестов на репозиторий Focuz.
- **Оценка 5/18, вердикт: отклонить.**
- **Что взять (идеи и пересказ, MIT):**
  1. Odoo-чек-лист ложных «мёртвых» элементов (кнопка `type="object"`, XML из манифеста, `_inherit`/`env['…']`, `registry`, хуки) → `boost:repo-audit/references/`.
  2. Для T13: `[x]` только после выполненной команды проверки, результат пишется рядом с планом.
  3. Изменение после начала кода идёт через ТР/SPEC, потом код и повторное ревью → `code-dev`/`build-orchestrator`.
  4. Ранний выход «закрывается стандартом или настройкой» → сверить с `tr-odoo-tech-design`.
  5. Поле «где чинить: код/тест/спека/доки» в находке → `pr-review`.
  6. Для T2: 9 кандидатов правил сверх плана (`read_group`, `hr.contract`, `SavepointCase`, `oe_chatter`, JS rpc/user/fields-registry/QUnit-хелперы, `/xmlrpc`, префикс версии в манифесте), каждый с `файл:строка` из 19.0 в `notes.md`.
- **Побочная находка для T2:** в `odoo@19.0` есть официальные кодмоды `odoo-bin upgrade_code` (`tree-to-list`, `sql-constraint`, `route-jsonrpc`; LGPL, только идея). На них можно ссылаться в сообщениях линтера как на автоисправление.
- **Урок для `templates/CLAUDE.md`:** «одна переменная версии наверху» у них не дошла ни до линтеров, ни до примеров. Версия без барьера не работает.
- **Не проверено:** приватный маркетплейс (`add_repo` отклонён классификатором), поэтому сравнение со `spec-writer`/`pr-review` сделано по описаниям. Фактический вывод pylint-odoo на 19.0 не смотрели: чужое не запускали.
