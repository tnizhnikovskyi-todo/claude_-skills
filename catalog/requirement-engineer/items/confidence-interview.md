# confidence-interview (приём)

- **Тип:** справка внутри скилла (`skill/references/confidence-interview.md`, 5 КБ)
- **Источник:** https://github.com/MadurangaDev/requirement-engineer/blob/b728406/skill/references/confidence-interview.md
- **Дата разбора:** 2026-11-03
- **Вердикт:** **адаптировать две части** → `boost:interview-me`; механику вопросов не брать (наша сильнее)

## Что делает

Режим «опрашивай меня, пока не будешь уверен». После каждого ответа
переоценивает уверенность (0–100%) **отдельно по 8 измерениям**: цель,
границы scope, роли и сценарии, скрытые требования, нефункциональные
ограничения, архитектурно дорогие решения, приоритеты, риски. Следующий
вопрос — по самому слабому измерению, а не по чек-листу. Время от времени
вслух: «около 70%, держат два момента: …». Порог по умолчанию «98%» = «могу
написать спецификацию и защитить каждый раздел»; накручивать вопросы ради
цифры запрещено.

Отдельный раздел — охота за разрывом «хочу» и «думаю, что надо хотеть»:

- лозунг на автомате («масштабируемо на миллионы» для инструмента на троих)
  → «что, если сделаем на 50 и окажемся неправы?»;
- осторожные формулировки («наверное, хотелось бы») → «если этого не будет,
  это заблокирует или просто будет неполно?»;
- «как у Stripe» → «какое именно свойство этого вам нужно?»;
- общее заявление против конкретной детали («безопасность критична» +
  «пароли пока храним открыто») → назвать прямо: «что из этого правда для
  проекта?»;
- если проект оказался меньше, чем звучал, — сказать это.

## Сравнение с `boost:interview-me`

| | Этот приём | `interview-me` |
|---|---|---|
| Вопросов за ход | «один или небольшая группа» | строго один (проверено A/B) |
| Догадка | нет | обязательна |
| Уверенность | по 8 измерениям | одна цифра |
| Критерий остановки | порог % или договорились | «предскажу 3 следующих ответа» |
| Итог | сводка по измерениям с метками предположений | пересказ с Out of scope + явное «да» + стоп |
| «Надо хотеть» | 4 сигнала + «схлопнуть scope» | одна проба «если бы не надо было обосновывать» |

## Как перенести

1. **Измерения.** В шаге 1 гипотезы и в шаге 4 остановки — 5 измерений
   вместо одной цифры (цель / scope и Out of scope / роли и сценарии /
   сбои и права / ограничения; для Odoo: стандарт vs доработка). Следующий
   вопрос — по самому слабому. Тест «предскажу 3 ответа» применять к нему.
2. **Сигналы «надо хотеть»** — в шаг 3 одной строкой каждый, подробности и
   примеры в `references/should-want.md`.

Не брать: группы вопросов, порог 98%, итог без пересказа и явного «да».

## Риск

Таблица измерений может толкнуть модель выводить её каждый ход. В тексте
скилла: «измерения — для выбора вопроса; вслух только самое слабое».
