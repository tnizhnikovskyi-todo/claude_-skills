## Что делает

Превращает Claude в «бизнес-аналитика, а не стенографиста»: 16 этапов
инженерии требований (контекст → стейкхолдеры → проблема → видение → scope →
выявление → классификация → анализ → моделирование → приоритизация →
спецификация → валидация → трассировка → изменения → финальный обзор →
документы), 15 шаблонов западного BA-набора (BRD, SRS по ISO/IEC/IEEE 29148,
FRD, PRD, user story, use case, AC, реестры) и три режима, ради которых его
стоит читать: **интервью до уверенности** с оценкой по 8 измерениям,
**разбор рассказа о процессе** на скрытые требования по 5 сигналам и
формулировки требований в **EARS** (`WHEN … THEN система SHALL …`) с
шаблонами граничных случаев.

## Гипотеза «активный инженер требований, который сам задаёт вопросы»

**Подтверждается наполовину.** Позиция активная: не принимать решение за
требование, не выдумывать, называть конфликты, требовать измеримости. Но
дисциплина вопросов слабее нашей:

- «один вопрос **или небольшая сгруппированная пачка**», а при разборе
  рассказа прямо советует «один сгруппированный вопрос лучше пяти» —
  наш A/B показал обратное (`interview-me`, +1.00 именно за один вопрос);
- нет догадки к вопросу, нет пересказа с Out of scope, нет явного «да» и
  стопа после него;
- по умолчанию скилл **выдаёт документ даже при неполном контексте**
  (помечая это), а не останавливается;
- активный опрос включается только по явной просьбе «interview me
  until confident»; в обычном режиме это генератор документов.

## Какую слабость Claude закрывает

- Принимает первое названное решение («нужен AI») за требование.
- Сливает неуверенность в одну цифру: «понятно на 80%», хотя по сбоям и
  правам понятно на 30%.
- Пропускает требования, которые в рассказе прозвучали мимоходом:
  «потом уходит на склад», «если больше 500 — кто-то согласует», «ну и
  потом как-то проводится».
- Пишет расплывчатые требования («быстро», «удобно») и только счастливый путь.

## Сравнение с нашим

| Что | requirement-engineer | `boost:interview-me` | `session-transcript-analyzer` |
|---|---|---|---|
| Один вопрос за ход | «один или небольшая пачка» | **строго один** (A/B +1.00) | — (не опрашивает) |
| Догадка к вопросу | нет | **да** | — |
| Уверенность | **по 8 измерениям**, вопрос по самому слабому | одна цифра в начале | — |
| «Хочу» vs «надо хотеть» | **лозунги, «наверное хотелось бы», «как у Stripe», противоречие общего и частного** | только проба «если бы не надо было обосновывать» | — |
| Пересказ + Out of scope + явное «да» | нет (итог по измерениям) | **да** | — |
| Скрытые требования в рассказе | **5 сигналов** | нет | нет: берёт только сказанное (D/X/C/T/Q/A) |
| Противоречия | **назвать оба, влияние, спросить, записать открытым** | нет | частично (отмена X-N), конфликт с D-N не описан |
| Состояния знания | Hypothesized / Observed / Verified / Rejected / Superseded | нет | `[інтерпретація]`, «не вигадуй», Q-N vs D-N |
| Формат требований | EARS + граничные случаи | — | — (у нас Given/When/Then в `tr-usecases-acceptance`) |
| Документы | BRD/SRS/IEEE, западный набор | не пишет документы | журнал дискавері, наши ID |
| Odoo / наш процесс | нет | банк вопросов Odoo 19, связь с `tr-*` | весь цикл дискавери |

Вывод: **дублирует** нашу цепочку документов (у нас ТР и протоколы,
свои шаблоны и ID), **хуже** нашего `interview-me` в самой механике
вопросов, но **даёт три приёма, которых у нас нет**: уверенность по
измерениям, сигналы «надо хотеть» и разбор рассказа на скрытые требования.

## Что и куда перенести

| # | Приём | Куда | Как | Приоритет |
|---|---|---|---|---|
| 1 | 5 сигналов скрытых требований + правило противоречий | `session-transcript-analyzer` (плагин `odoo19-discovery-sessions`; правка через `proposals/`) | Шаг 3б «Скан прихованих вимог»: актор мимоходом, точка решения, передача между людьми/системами, данные упомянуты один раз, «скачок» в рассказе → кандидаты `Q-N` с меткой `[інтерпретація]`, **никогда** не `D-N`. Противоречие с существующим `D-N`/`X-N` → `Q-N` «конфлікт: D-3 vs сесія N», старое не переписывать | **высокий** — транскрипты у нас каждую неделю, и это ровно то место, где скилл сейчас молчит |
| 2 | Уверенность по измерениям | `boost:interview-me`, шаги 1 и 4 | Вместо одной цифры — 4–5 измерений (цель, scope/Out of scope, роли и сценарии, сбои и права, ограничения); следующий вопрос — по самому слабому; в остановке «предскажу 3 ответа» — по каждому | средний |
| 3 | Сигналы «надо хотеть» + «схлопнуть scope» | `boost:interview-me`, шаг 3 и `references/` | Добавить к пробе: «наверное хотелось бы» → «если этого не будет, это заблокирует или просто будет неполно?»; «как в X» → «какое именно свойство X нужно?»; общее против частного → назвать; честно сказать, если задача меньше, чем звучала | средний |
| 4 | Граничные шаблоны EARS + список расплывчатых слов | `tr-usecases-acceptance` / `tr-review` (плагин `odoo19-tr-authoring`, не наш) | В чек-лист «нещасливих шляхів» добавить: одновременный доступ, значение ровно на пороге; «швидко/зручно/масштабовано» → требовать число | низкий |

**Не брать:** 16 этапов, BRD/SRS/IEEE-шаблоны, широкий триггер, режим
«выдать документ при неполном контексте», «небольшую пачку вопросов».

## Проверка

A/B не проводился (по правилам нужно разрешение пользователя). Предложение:

| Задача | Без | С приёмом | Что меряем |
|---|---|---|---|
| Транскрипт сессии с 4 скрытыми требованиями (передача «склад», порог согласования, «потом как-то проводится», лог причин возврата) → `session-transcript-analyzer` | текущий текст | + шаг 3б | сколько из 4 стали `Q-N`; ложные `D-N` (должно быть 0) |
| Транскрипт, противоречащий `D-2` журнала | текущий | + правило противоречий | конфликт назван и стал `Q-N`, `D-2` не переписан |
| «Interview me»: закупки, ответы-лозунги и «как в SAP» | `interview-me` | + измерения и сигналы | вопрос по слабому измерению; лозунг пойман; один «?» сохранён |

## Оценка

| Критерий | Балл (0–3) | Комментарий |
|---|---|---|
| Прирост | 1 | Механика вопросов слабее нашей; новое — 3 приёма, прирост не измерен |
| Частота | 2 | Целиком (BRD/SRS) — редко; приёмы для транскриптов и интервью — каждую неделю |
| Надёжность | 1 | Триггер на 143 слова перехватывает 5 наших скиллов; разрешает пачку вопросов; ссылка на `ask_user_input_v0` (инструмент claude.ai, в Claude Code нет); README ссылается на отсутствующий `CHANGELOG.md` |
| Стоимость контекста | 2 | ~3 тыс. токенов `SKILL.md` при срабатывании, справки по требованию; но широкий триггер = частые лишние загрузки |
| Безопасность | 3 | Только markdown, без скриптов, сети, хуков; прочитано всё. Релизный `.skill` не проверен |

## Риски и заметки

- Если поставить как есть, на фразах «разбери транскрипт» и «напиши AC»
  он конкурирует с нашими профильными скиллами и выдаст BRD/SRS вместо
  журнала и ТР.
- «Небольшая пачка вопросов» и «один сгруппированный вопрос лучше пяти»
  противоречат проверенному у нас правилу. При переносе приёмов не тащить.
