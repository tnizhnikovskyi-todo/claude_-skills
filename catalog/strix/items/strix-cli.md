# Strix CLI (движок)

- **Тип:** CLI-инструмент (Python), запускает Docker-песочницу и дерево LLM-агентов
- **Источник:** https://github.com/usestrix/strix (`pip/pipx install strix-agent`)
- **Версия / коммит:** v1.7.0, `6b7ae2e`
- **Дата разбора:** 2026-11-02
- **Вердикт:** отложить; допустим только разовый запуск против своего стенда с явного разрешения

## Что делает

`strix -n -t <цель> --scan-mode quick|standard|deep --max-budget <USD>`.
Цели: локальная папка, git-URL, URL/домен/IP, OpenAPI/Postman. Можно
комбинировать код + живой стенд (лучшее покрытие). Режим `--scope-mode diff`
для PR. Вывод в `strix_runs/<run>/`: отчёт, по файлу на находку с PoC и
патчем, JSON/CSV, SARIF, `run.json` (статус, стоимость). Есть TUI и
локальный веб-вьюер (`strix view`), резюме прогона (`--resume`).

## Архитектура (кратко)

- `strix/agents` — фабрика агентов, `system_prompt.jinja`, `scope.jinja`.
- `strix/core` — runner, сессии, хуки, исполнение.
- `strix/llm` — компакция, бюджет контекста, лог запросов (LiteLLM +
  `openai-agents`).
- `strix/runtime` — Docker-клиент, Caido bootstrap.
- `strix/tools` — инструменты агентов (см. README карточки).
- `strix/report` — состояние отчёта, SARIF, PDF.
- `containers/Dockerfile` — Kali + Go-инструменты ProjectDiscovery и др.
- `strix/interface` — CLI, TUI (Go + Python-бэкенд), веб-вьюер (React), cloud-клиент.

## Плюсы

- Доказывает уязвимости динамически (PoC, HTTP-обмены через прокси с id).
- Хорошо сделан для CI: exit-коды, `--fail-on`, SARIF, бюджет.
- Любая модель через LiteLLM, включая Claude.
- Бенчмарк XBEN 100/104 (самооценка, v0.4.0, black-box CTF).

## Минусы для нас

- Нет знаний Odoo; для `td.*` модулей нужен поднятый Odoo со
  стендовыми данными, плюс `--instruction` с моделью ролей/компаний.
- Прогоны `standard` ~30 мин, `deep` часы; стоимость токенов значимая
  (в примерах бюджеты $10–30 на прогон).
- Безопасность исполнения: Kali-контейнер, `pentester` с NOPASSWD sudo,
  `NET_ADMIN`/`NET_RAW`, иногда `SYS_ADMIN` + `apparmor:unconfined`;
  локальная цель монтируется на запись; установщик `curl | bash`; образ
  не закреплён (`kali-rolling:latest`, `go install @latest`).
- Телеметрия PostHog + Scarf включена по умолчанию (`STRIX_TELEMETRY=0`).
- Системный промпт снимает отказ: «все разрешения получены», «никогда не
  спрашивай», «REFUSAL AVOIDANCE». Контроль скоупа целиком на операторе.

## Если всё-таки пробовать

Только на своём стенде (`odoo` в docker-compose со стендовыми данными),
чистый клон модуля, `STRIX_TELEMETRY=0`, `--scan-mode quick`,
`--max-budget 5`, без `web_search`-ключей, сеть контейнера ограничена
стендом. Сравнить с выводом нашего `security-review` на том же модуле.
