# Strix

- **Тип:** CLI-инструмент (мультиагентный AI-пентестер) + 9 скиллов для coding-агентов + ~70 внутренних «knowledge packs» (markdown)
- **Источник:** https://github.com/usestrix/strix
- **Версия / коммит:** v1.7.0, `6b7ae2e` (2026-10-29)
- **Дата разбора:** 2026-11-02
- **Вердикт:** **адаптировать** (методологию), инструмент как есть **пока не ставить**

## Что делает

Strix — open-source (Apache-2.0) автономный AI-пентестер. Получает цель
(локальный код, git-репозиторий, URL, домен, IP, OpenAPI/Postman-спеку),
поднимает Docker-песочницу на базе Kali Linux с набором инструментов
(nmap, nuclei, sqlmap, ffuf, semgrep, ast-grep, gitleaks, trivy, Caido-прокси,
headless-браузер) и запускает дерево LLM-агентов: корневой агент только
оркестрирует, дочерние делают разведку, тестирование одного класса уязвимостей
в одном компоненте, валидацию PoC и отчёт с патчем. Результат: отчёт в
Markdown/JSON/CSV/SARIF, каждая находка с PoC, CVSS, контраргументами и
предложенным фиксом. Коммерческая надстройка: Strix Cloud (app.strix.ai).

## Какую слабость Claude закрывает

1. **Нет динамической проверки.** Наш `security-review` (встроенный и
   `odoo19-mvp-build:security-review`) читает diff и рассуждает статически.
   Strix доказывает находку живым эксплойтом против запущенного приложения.
2. **Небрежное закрытие кандидатов.** Модель склонна «тихо» отбрасывать
   сомнительные места. У Strix жёсткая дисциплина: каждый кандидат
   заканчивается в `confirmed` / `ruled_out` (с названным контролем
   и местом) / `open_proof_gap`.
3. **Завышение severity.** Отдельный рубрикатор с чек-листом для high/critical.
4. **Непроверенные фиксы.** Пять упорядоченных «ворот» проверки патча.

## Как устроен

- **Python 3.12, `openai-agents` + LiteLLM.** Любая модель через LiteLLM
  (`STRIX_LLM`, `LLM_API_KEY`), включая Anthropic; есть вход через подписку
  ChatGPT/Codex (OAuth). Компакция контекста, бюджет (`--max-budget` в $),
  лимит ходов (`--max-turns`, по умолчанию 500).
- **Промпт.** Один большой `system_prompt.jinja` (~540 строк) + подгрузка
  скиллов в промпт (`<specialized_knowledge>`) или по требованию (`load_skill`).
  Агенту разрешено 1–5 скиллов, «без агентов-универсалов».
- **Схема агентов.** Корень = только оркестрация. Для каждой находки цепочка
  Discovery → Validation → Reporting (в white-box отчёт включает патч
  `fix_before/fix_after` + `fix_pr_body`). Дедупликация отчётов через LLM.
- **Инструменты агентов:** shell в песочнице, Caido proxy (HTTPQL),
  agent-browser, python, web_search (Perplexity или Exa), notes, todo,
  threat_model, coverage, reporting, apply_patch, MCP-клиент.
- **Режимы:** `quick` / `standard` / `deep` (по умолчанию deep, часы);
  `--scope-mode diff --diff-base origin/main` для PR; headless `-n` с
  exit-кодами (0 / 1 / 2) и `--fail-on` для CI; SARIF для code scanning.
- **Окружение:** нужен Docker; образ Kali, пользователь `pentester` с
  `NOPASSWD sudo`, контейнеру добавляются `NET_ADMIN`/`NET_RAW`, иногда
  `SYS_ADMIN` + `apparmor:unconfined`. Локальная цель монтируется **на запись**.

## Риски и заметки

- **Промпт снимает тормоза.** Разделы `AUTHORIZATION STATUS` и
  `REFUSAL AVOIDANCE`: «все разрешения получены, никогда не спрашивай»,
  «не классифицируй как вредное». Контроль скоупа только на совести
  оператора (в OSS нет проверки владения доменом, в Cloud есть DNS-верификация).
  Запускать только против своих стендов.
- **Код цели монтируется на запись**, агенты могут его менять: только чистый
  клон.
- Телеметрия включена по умолчанию: ставить `STRIX_TELEMETRY=0`.
- Нет знаний Odoo: из фреймворков только Django/FastAPI/NestJS/Next.js.
- README и consumer-скиллы активно ведут в платный Strix Cloud.
- Supply chain: проект сам отмечает инцидент с отравленным `litellm 1.107.0`
  (2026-10-21) и держит 5-дневный cooldown в `uv`; образ собирается из
  `kali-rolling:latest` и `go install ...@latest` (не закреплено).
