# Детектор `aislop`

- **Тип:** CLI/библиотека на Node ≥18, без зависимостей
- **Источник:** https://github.com/git-voitenko/anti-ai-slop-writing, `detector/`
- **Версия / коммит:** 3.0.0, `6f706e9`
- **Дата разбора:** 2026-11-03
- **Вердикт:** адаптировать (узкий список и уроки в `check-humizer.py`), код не брать

## Что считает

| Группа | Правило | Порог / severity |
|---|---|---|
| Лексика (`banned.md`) | `banned-word`, `banned-phrase`, `banned-opener` | high — голая запись; medium — есть замена «→» или узкая форма; low — условие, которое не проверить («як філер», «переносне»). Зачины — только в начале предложения |
| Структура | `uniform-sentence-length` | 3+ предложения подряд ±2 слова |
| | `flat-rhythm` | σ/среднее < 0,4 при ≥60 словах и ≥6 предложениях |
| | `parataxis` | 4+ предложения подряд ≤8 слов |
| | `rule-of-three` | «A, B і/та/й C» в одном предложении, придаточные исключены |
| | `role-opener` | «Як [роль], я…» — high |
| | `verbal-noun-chain` | два соседних -ання/-ення (uk), -ание/-ение (ru) — medium |
| Пунктуация | `em-dash` (en) / `rhetorical-dash` (ru/uk) | >1 на 500 слов; в ru/uk грамматическое тире исключено эвристикой (≤4 слов до тире или после него «це/это/значить») |
| | `not-just-construction` | «X — це не просто Y» — high |
| | `exclamation`, `ellipsis` | >1 на 1000 слов; >1 многоточия |
| Форматирование | `emoji-bullet`, `bullet-run` (>7), `hashtag-stack` (>2), `thread-opener` | high/medium |

Маска до проверки: frontmatter, код (блоки и инлайн), HTML-комментарии,
адреса ссылок, URL, цитаты `>`; для правил ритма ещё заголовки, маркеры
списков и строки таблиц. Смещения сохраняются (замена пробелами).

## Надёжность на деловом тексте

Детектор не запускали; мерили своим портом на Python (сверен по числу
записей: uk 158, ru 132, и по их фикстурам). Подробно — `../notes.md`.

- **Ложные high:** любой диапазон «від 320 до 480 годин» / «от 0 до 3»
  (запись «Від X до Y (зачин-діапазон)» не привязана к началу предложения);
  в ru — «понимает» (фраза «Важно отметить / понимать» режется по «/»).
- **Ложные medium:** «з'являється» (апостроф не считается частью слова),
  «шлях», «функціонал», «розуміли» (стемминг по длине).
- **Шум low:** «правило трёх» ~4 на 1000 слов на обычных перечислениях.
- На их собственных фикстурах всё чисто — но human-фикстуры там бытовые
  абзацы по ~115 слов, деловых документов нет.

Вывод: как блокирующий гейт для клиентских документов не годится; как
подсказка редактору — терпимо при `--severity high`, но high как раз и
шумит на оценках и КП.

## Безопасность

Прочитан весь `detector/` и `package.json`: `readFileSync`/`readdirSync`,
без сети, `child_process`, `eval`; `postinstall` нет; регэкспы с ограничением
ленивых слотов (защита от ReDoS на «вредной» записи списка). Риск только в
способе установки: `npx github:…` и `npm install git-voitenko/…` тянут main
без пина.

## Что из этого переложить в `check-humizer.py`

1. **Блокирующий класс «бот-хвосты»**: «Сподіваюся, це допоможе», «не
   соромтеся звертатися», «Чудове запитання», «Як ШІ/мовна модель».
   0 срабатываний на 63 тыс. слов нашего текста.
2. **Класс-предупреждение «кальки й канцелярит»**: точные формы без
   стемминга (список — в README карточки, п. 1, 3, 4). Вывод отдельной
   секцией `⚠`, код возврата не меняет.
3. **Технические правила:** граница слова `(?<![\w'ʼ’])…(?![\w'ʼ’])`;
   никакого стемминга по длине; фразы с «/» не резать; диапазоны не трогать.
4. **Фикстуры «должно быть чисто»**: 3–5 настоящих анонимизированных
   документов регистра 3 (оценка, КП, follow-up) — скрипт обязан молчать.
