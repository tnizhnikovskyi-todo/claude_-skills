# Итог: addyosmani/agent-skills

- **Что это:** плагин Addy Osmani: 24 скилла-методички «как работает senior»
  на весь цикл (spec → plan → build → test → review → ship), 9 команд,
  4 агента. MIT, очень активно поддерживается (v0.6.15, ~200 коммитов в
  октябре 2026), есть свой эвал-контур.
- **Безопасность:** скиллы являются чистым markdown, оба скрипта безопасны. Хуки
  плагином не подключаются. `simplify-ignore` (переписывает файлы на диске) и
  `sdd-cache` (подменяет WebFetch кэшем) не ставить.
- **Вердикт:** плагин целиком **не ставить**. Дублирует встроенные
  `code-review`/`simplify`/`security-review` и наш `odoo19-mvp-build`,
  конфликтует по `/review`, широкие триггеры, ~3–4 тыс. токенов description
  в каждой сессии.
- **Лучшие находки:**
  1. `doubt-driven-development` (◐): враждебная проверка решения субагентом со
     свежим контекстом, без своих выводов, максимум 3 цикла. Закрывает
     самоподтверждение. Адаптировать сжато, подвязать к `tr-review` и
     security-review.
  2. `interview-me` (★): по одному вопросу с догадкой, пересказ с «Out of
     scope», явное «да». Сразу полезен для дискавери и ТР.
  3. `source-driven-development` (◐): версии → официальная документация →
     цитаты, «UNVERIFIED». Сделать «odoo19-source-check».
  4. «Пол» из `constraint-driven-development` (◐): запрет новых `noqa`/skip,
     удалённых тестов, ослабления порогов. Положить в CLAUDE.md шаблон и `pr-review`.
- **Приёмы для своих чек-листов:** мутационная проверка тестов при ревью,
  Prove-It (сначала падающий тест на баг), разделение старых дефектов и
  регрессий, одна зависимость на апгрейд.
- **Дальше:** проверить `doubt-driven` и `interview-me` на реальной задаче
  с ними и без них.
