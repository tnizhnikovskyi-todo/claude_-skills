# code-review-and-quality (+ code-simplification, security-and-hardening)

- **Тип:** скиллы + команды `/review`, `/code-simplify` + агенты
  `code-reviewer`, `security-auditor`
- **Источник:** https://github.com/addyosmani/agent-skills/tree/main/skills/code-review-and-quality
- **Версия / коммит:** 0.6.15 / `301b02b`
- **Дата разбора:** 2026-11-02
- **Вердикт:** **отклонить как замену встроенных**, взять 4 приёма в свои
  чек-листы

## Что делает

Ревью по пяти осям: корректность, читаемость, архитектура, безопасность,
производительность. Метки серьёзности: Critical / без префикса / Optional /
Nit / FYI. Ориентиры по размеру изменения (~100 / ~300 / ~1000 строк).
«Структурные средства»: предлагать конкретную реструктуризацию, а не просто
«сложно». Дисциплина зависимостей. Чек-лист в конце. `code-simplification`:
пять принципов (сохранять поведение, «забор Честертона», ясность важнее
хитрости, ограничиваться изменённым). `security-and-hardening`: OWASP,
секреты, supply chain, GDPR.

## Сравнение со встроенными

| | Встроенный `code-review` / `simplify` / `security-review` | agent-skills |
|---|---|---|
| Форма | Исполняемый процесс: уровни усилия, субагенты, проверка находок, `--fix`, `--comment` в PR | Методичка: оси и чек-листы, исполнение на усмотрение модели |
| Проверка находок | Есть отдельный этап верификации | Только «сверь с вызывающими и тестами перед репортом» |
| Охват | Баги (code-review), упрощение (simplify), безопасность (security-review) | Всё в одном плюс стиль, размер изменения и процесс |
| Наша специфика | Есть Odoo-обёртка `anthropic-skills:security-review` | Нет |

Встроенные сильнее как инструмент. Если поставить оба, описания будут
конкурировать за «review this diff» / «simplify», а `/review` конфликтует по
имени.

## Что стоит забрать (идеи, а не скилл)

1. **Мутационная проверка тестов при ревью:** инвертировать одно условие из
   изменения, прогнать тесты, вернуть файл. Если тесты остались зелёными, это
   находка. Во встроенных этого нет.
2. **Дисциплина обновления зависимостей:** читать changelog, одна зависимость
   на изменение, смотреть дифф lock-файла.
3. **«Рефакторинг переносит сложность или уменьшает?»:** считать, сколько
   понятий нужно держать в голове читателю.
4. **Отделять уже существующие дефекты в базовой ветке от регрессий этого
   изменения.**
