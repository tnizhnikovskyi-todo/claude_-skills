# doubt-driven-development

- **Тип:** скилл (часть плагина `agent-skills`)
- **Источник:** https://github.com/addyosmani/agent-skills/tree/main/skills/doubt-driven-development
- **Версия / коммит:** 0.6.15 / `301b02b`
- **Дата разбора:** 2026-11-02
- **Вердикт:** **адаптировать** (лучшая находка репозитория)

## Что делает

Перед тем как принять нетривиальное решение (ветвление, граница модулей,
необратимая операция, утверждение вида «это безопасно / масштабируется /
соответствует спеке»), Claude формулирует CLAIM, выделяет минимальный
ARTIFACT и CONTRACT и **без своих рассуждений и без CLAIM** отдаёт их субагенту
со свежим контекстом. Промпт субагента враждебный: «найди, что не так, не
подтверждай». Находки разбираются по порядку (контракт непонятен → правка →
осознанный компромисс → шум). Не больше 3 циклов, потом вопрос пользователю.
Опционально предлагается второе мнение от другой модели (Gemini/Codex CLI),
только с явного согласия пользователя.

## Какую слабость Claude закрывает

- Самоподтверждение: в длинной сессии допущения тихо превращаются в «факты»,
  и проверка своего же кода чаще подтверждает, чем опровергает.
- Встроенный `code-review` работает с готовым диффом. Этот скилл ловит
  неверное направление раньше, на уровне решения или плана.
- Против «doubt theater» есть проверяемый сигнал: 2+ цикла с существенными
  находками и ни одной принятой значит, что Claude не сомневается, а
  оправдывается.

## Как устроен

Один `SKILL.md`, 245 строк, около 16,7 КБ. Скриптов нет. Использует штатный
запуск субагента (Agent). Внешние CLI только после явного «да» пользователя,
через stdin, в режимах `--sandbox read-only` / `--approval-mode plan`. Сеть
не нужна. Ссылается на `references/orchestration-patterns.md` (при установке
одного скилла этого файла не будет).

## Как адаптировать

- Сжать до ~80 строк: CLAIM → ARTIFACT+CONTRACT → враждебный субагент →
  классификация → стоп после 3 циклов.
- Убрать обязательный вопрос про cross-model. Оставить одной строкой «по
  запросу пользователя».
- Сузить триггер: «проверь решение», «stress-test», перед утверждением ТР,
  перед необратимыми действиями в Odoo (миграции, удаления, права).
- Связать с нашими `tr-review` и `anthropic-skills:security-review`: их
  результат может быть ARTIFACT для враждебного прохода.

## Риски и заметки

- Субагент без контекста даёт шум. Скилл это учитывает (класс «noise» и вопрос
  «что добавить в контракт»).
- Внутри субагента скилл не работает (вложенный запуск запрещён), это прямо
  написано.
