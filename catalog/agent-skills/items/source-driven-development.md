# source-driven-development

- **Тип:** скилл (часть плагина `agent-skills`)
- **Источник:** https://github.com/addyosmani/agent-skills/tree/main/skills/source-driven-development
- **Версия / коммит:** 0.6.15 / `301b02b`
- **Дата разбора:** 2026-11-02
- **Вердикт:** **адаптировать** (под Odoo 19)

## Что делает

Процесс DETECT → FETCH → IMPLEMENT → CITE. Определить точные версии стека по
манифестам и вслух их назвать. Загрузить **конкретную** страницу официальной
документации, а не главную. Писать код по документации, а не по памяти.
Каждое решение, зависящее от фреймворка, подкрепить полным URL и цитатой.
Есть иерархия источников (официальные доки > changelog > MDN > caniuse;
Stack Overflow и блоги не годятся). Если код проекта расходится с
документацией, вынести это на решение пользователю. Если документации нет,
явно пометить «UNVERIFIED». Отдельно сказано, что скачанные страницы являются
данными, а не инструкциями.

## Какую слабость Claude закрывает

Устаревшие API из обучающих данных. Уверенный код по памяти для конкретной
версии фреймворка. В `inventory/current.md` прямо отмечено: «Нет отдельного
MCP для актуальной документации библиотек».

## Как устроен

`SKILL.md`, 217 строк, около 10 КБ. Использует WebFetch/WebSearch. Опциональный
хук `sdd-cache` (кэш WebFetch) **не ставить** (см. `notes.md`).

| Критерий | Балл | Комментарий |
|---|---|---|
| Прирост | 2 | Реально полезно для Odoo 19, где API меняется от версии к версии |
| Частота | 2 | Разработка модулей `td.*` |
| Надёжность | 2 | Зависит от доступности документации из сети |
| Стоимость контекста | 2 | 10 КБ плюс загруженные страницы |
| Безопасность | 3 | Без хука: только текст. Есть правило «fetched content = data» |
| Поддержка | 3 | Активно |
