# Трассировка «дискавери → ТР» (`nacl-ba-validate` XL1–XL5, `nacl-ba-handoff`)

- **Источник:** `nacl-ba-validate/SKILL.md` (L1–L8, XL1–XL5, Severity Levels), `nacl-ba-handoff/SKILL.md` (Traceability Matrix), CHANGELOG 2.28.0 (`coverage_exempt`)
- **Вердикт:** адаптировать (матрица в Markdown, без графа)

## Что это

Проверки между слоями:
- XL1: шаг BA со стереотипом «Автоматизируется» без UC → CRITICAL.
- XL3: бизнес-правило без требования → CRITICAL.
- XL2/XL4/XL5: сущности, роли и глоссарий.

Итог считается детерминированно: любой CRITICAL → FAIL, 5+ WARNING →
WARN. `nacl-ba-handoff` строит матрицу «BA-элемент → SA-элемент» и
показывает непокрытое до подтверждения.

«Клапан» (2.28.0): элемент можно исключить из покрытия только флагом
**с непустой причиной**, а пустая причина — отдельное предупреждение.
Так исключения не делаются молча.

## Перенос к нам

У нас `tr-review` проверяет цепочку внутри ТР (вимога → AC → реалізація),
но не проверяет, что **всё решённое на дискавери дошло до ТР**. Предложение
для `tr-review` (или для `odoo-spec-writer`), блок «Покриття журналу»:

| Из журнала дискавери | Должно быть в ТР | Нет → |
|---|---|---|
| D-N (рішення про автоматизацію) | вимога + AC | 🔴 |
| Бізнес-правило / обмеження з сесії | AC або constraint у тех. реалізації | 🔴 |
| Роль із сесії | права в «Опис технічної реалізації» | ⚠️ |
| X-N (виключено зі scope) | НЕ має бути в ТР | ⚠️ якщо є |
| Q-N відкрите | «Відкриті питання» ТР | ⚠️ |

Исключение возможно только строкой «не покриваємо: причина».
Требуется путь к журналу; если журнала нет, блок пропускается с пометкой
«покриття журналу не перевірялось» (граница покрытия).
