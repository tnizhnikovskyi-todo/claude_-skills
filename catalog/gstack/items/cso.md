# cso (аудит безопасности)

- **Тип:** скилл + нативный лаунчер `gstack-cso-launcher` + Docker
- **Источник:** `cso/SKILL.md@7caca33`, `cso/ACKNOWLEDGEMENTS.md@7caca33`, `cso/sections/audit-phases.md`
- **Лицензия:** MIT
- **Вердикт:** отклонить рантайм; 2–3 идеи — в наш Odoo-`security-review`

## Что делает

v3: «сначала доказательство, потом заверение». Модель приложения (акторы,
активы, входы, границы тенантов, инварианты), перепись поверхности атаки,
фазы по OWASP Top 10:2025 / API 2023 / ASVS 5.0 / LLM и Agentic Top 10
2026 / MCP security. В отчёт попадают только «supported findings»:
вход под контролем атакующего + пересечение границы + показанный ущерб в
скоупе + проверенные защитные меры. Остальное — помеченные гипотезы.
Независимый скептический ревьюер без вывода автора. Полный режим
воспроизводит эксплойт и чинит в Docker через доверенный лаунчер.

## Почему не рантайм

Нужен собранный нативный лаунчер и локальный Docker; без них скилл
честно пишет «not assessed». В облачной сессии этого нет. Стек
поддержки воспроизведения: Node, Bun, Python, Rails — не Odoo.

## Сравнение

Наш `odoo19-mvp-build:security-review` (`proposals/…/security-review`)
уже взял из Strix counterevidence, калибровку severity, ворота фикса,
скоуп диффа и Odoo-чек-лист. С `cso` почти совпадает. Новое:

- «UUID — не авторизация»; переменные окружения могут прийти из
  недоверенного workflow; отсутствие hardening без сценария отказа — не
  находка.
- «Неизвестная достижимость — это unknown, не unreachable».
- Severity по **худшему соседу**: найденный паттерн грепается по всем
  входам (то же есть в `review` как «Sideways sweep»).
- Отчёт начинается со статуса complete / partial / not assessed; пустой
  результат без прогона ≠ «чисто».
