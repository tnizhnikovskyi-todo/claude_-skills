# Gate Integrity (`review`, `ship`)

- **Тип:** раздел скиллов `review`/`ship` + бинарник `gstack-gate-diff`
- **Источник:** `review/gate-integrity.md@7caca33`, `review/SKILL.md@7caca33` (шаги 3.5, 4, 5c)
- **Лицензия:** MIT (gstack); текст сам ссылается на «just-say-no-to-process-porn-and-ceremony … REWARD-HACKING-CATALOG», которого нет в `NOTICE.md` → лицензия первоисточника неизвестна
- **Вердикт:** адаптировать (идея, своими словами) в `odoo19-mvp-build:pr-review`

## Что делает

Ловит «подгонку под зелёный CI» в диффе: агент не чинит код, а ослабляет
проверку. Дифф делится на три уровня: *перечень* (все ханки в тестах, CI,
конфигах линтеров), *чтение* (ханки с тегом или удалёнными строками; на
каждый один вопрос: «это ослабление глушит отказ, ради которого проверка
была добавлена, или оно обосновано измерением/решением в этом же диффе?»)
и *находка* (не прошёл вопрос). Находку решает человек из 4 вариантов:
вернуть проверку / оставить с обоснованием / оставить по другой причине /
оставить открытой. Автоисправления нет.

## Какую слабость Claude закрывает

Reward hacking агента на собственном коде: удалить/пропустить тест,
поднять таймаут, ослабить `assertEqual` до `assertTrue`, переписать
критерий приёмки под сделанное, вставить заглушку и отчитаться «готово»,
прогон, где не выполнилось ни одного теста.

## Сверх нашего (что стоит взять)

| Паттерн gstack | Odoo-вариант для `pr-review` |
|---|---|
| RH-10 правка спеки как прогресс | Дифф меняет текст AC-NN в `SPEC.md`/ТР в той же ветке, что и код → AC сверять с версией из базовой ветки; правка AC = отдельное решение, не «выполнено» |
| RH-12 код нюхает тестовое окружение | `config['test_enable']`, `odoo.tools.config.get('test_enable')`, `self.env.context.get('test_mode')`, `modules.module.current_test` в продуктовом коде |
| RH-15 ослабление порога | Рост `timeout`, `retry`, `delta`, `places`; `assertEqual(x, 3)` → `assertTrue(x)`/`assertGreater(x, 0)`; снижение `--test-tags` охвата |
| PL-2 ноль тестов = зелёный | Odoo с `--test-tags` по опечатке выбирает 0 тестов и выходит с 0 → требовать число прогнанных тестов из лога (`Ran N tests`/`0 failed, 0 error(s) of N tests`) |
| Три уровня + «один вопрос» | Не каждая правка теста — находка; находка только если ослабление не обосновано в диффе |
| Решение человека, не автофикс | Gate-находка всегда ASK/REQUEST CHANGES с 4 вариантами, в отчёте строка «Gate edits:» |

## Как устроен

Детектор (`gstack-gate-diff`, TS) только размечает ханки тегами и никогда
не подавляет находку; судит агент по одному вопросу, решает человек.
Ссылка на обоснование в сообщении коммита не снимает находку («commit
text is forgeable»).
