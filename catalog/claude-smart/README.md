## Что делает

Хуки пишут каждый промпт, каждый вызов инструмента (вход и вывод до
4096 символов) и ответ в JSONL-буфер. На `Stop` буфер уходит в локальный
бэкенд reflexio (`localhost:8071`), который через `claude -p` (по
умолчанию `sonnet`) решает, есть ли в сессии поправка или неочевидный
путь к успеху, и извлекает правила `{trigger, content, rationale}` в
три коллекции: предпочтения проекта, скиллы проекта, общие скиллы.
На следующий промпт и перед каждым Edit/Write/Bash ищет похожие правила
и подмешивает их индекс (до 8000 символов); полный текст правила модель
грузит командой. Дашборд на `localhost:3001`.

## Какую слабость Claude закрывает

Поправки пользователя теряются между сессиями: Claude повторяет ту же
ошибку. У нас это закрыто явным путём: `skill-feedback` (поправка к
скиллу → `observations/` → еженедельное ревью → правка с A/B) и
`cloud-memory` (решения/баги/находки проекта в `memory/` в git).
claude-smart делает то же автоматически и без участия человека.

## Как устроен

- **Захват.** 7 событий хуков (`plugin/hooks/hooks.json`):
  `Setup` (установщик, 300 с), `SessionStart` (4 команды: корень плагина,
  сессия, старт бэкенда, старт дашборда), `UserPromptSubmit` (буфер +
  поиск), `PreToolUse` на `Edit|Write|NotebookEdit|Bash` (поиск),
  `PostToolUse` на `*` (запись входа и вывода любого инструмента, включая
  MCP), `Stop` (публикация), `SessionEnd` (публикация, остановка служб).
- **Распознавание поправки.** На сервере, LLM-гейтом
  (`playbook_should_generate`), а не регэкспом. Плюс явная
  `/claude-smart:learn [заметка]`.
- **Хранение.** `~/.reflexio/` (SQLite, гибридный поиск, локальные
  эмбеддинги onnxruntime), `~/.claude-smart/` (буферы, `.env`, логи).
  «Скилл» — запись в базе, а не `SKILL.md`.
- **Правило → скилл.** Экстрактор пишет запись; дальше
  дедупликация, консолидация, «оптимизатор» переписывает формулировку,
  статусы `CURRENT → ARCHIVED`; общие скиллы собираются из проектных.
  Человек может смотреть и удалять в дашборде, но одобрения не требуется.
- **Сеть.** Установщик: `astral.sh` (uv, `curl`→`sh`), `nodejs.org`
  (Node), PyPI (`reflexio-ai`, `litellm`, ...), npm (дашборд). В работе:
  localhost; LLM — через `claude -p` (Anthropic на подписке пользователя).
  Managed-режим: всё на `https://www.reflexio.ai` по API-ключу. Явной
  телеметрии в коде плагина не нашли.

## Сравнение с нашим

| Что | claude-smart | у нас |
|---|---|---|
| Ловля поправки | автоматически, все сессии | явно: `skill-feedback` по поправке/просьбе |
| Куда | SQLite в `~/.reflexio` | `observations/` и `memory/` в git (переживает контейнер) |
| Секреты | маскировка `KEY=value` | жёсткий запрет в тексте скилла, тег `<private>`, обобщение |
| Правило → скилл | автоматическая запись в базу, подмешивание | наблюдение → ревью человеком → правка в ветке → A/B |
| Повтор правила | консолидация в одну формулировку | `repeat_of` → барьер (хук/линт/кейс) |
| Облако | не поддерживается | работает (git) |
| Цена | хуки на каждое действие + фоновый LLM | только по вызову; хук `cloud-memory` ~10 мс |

Сверх нашего: качественная методика «что считать поправкой и как писать
триггер», success-path recipe, дедуп подмешивания по сессии.
Хуже нашего: нет барьеров и A/B, нет человека в контуре, утечка
секретов, не работает в облаке. Дублирует: `cloud-memory` (память
проекта) и `skill-feedback` (поправки), а также claude-mem.

## Риски и заметки

- В облачной сессии не работает (README: «Not supported … claude.ai/code
  web»); если поставить локально — полная запись промптов и вывода
  MCP-коннекторов с клиентскими данными в `~/.reflexio`.
- Опасна автоматическая «самонастройка» правил без гейта: `catalog/skillopt/`
  показал падение 0.554 → 0.026 без гейта. У claude-smart гейта
  «правка принимается только при росте на отложенных кейсах» нет.
- Бенчмарк сделан автором, на синтетике и заглушках.
