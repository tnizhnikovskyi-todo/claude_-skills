# reflexio: промпты извлечения правил

- **Тип:** методика (тексты промптов LLM-экстрактора)
- **Источник:** `ReflexioAI/reflexio@49659eb`,
  `reflexio/server/prompt/prompt_bank/`:
  `playbook_should_generate/v3.0.0.prompt.md` (гейт),
  `playbook_extraction_context/v4.6.1.prompt.md` (основной экстрактор, активный),
  `playbook_extraction_context_expert/v3.5.0.prompt.md`
- **Лицензия:** Apache-2.0 (`LICENSE`, `pyproject.toml`; `NOTICE` нет)
- **Вердикт:** адаптировать (пересказ в `skill-feedback` и `cloud-memory`)

## Что ценно

**1. Гейт «есть ли чему учиться»** (`playbook_should_generate`).
Две дорожки: (а) поправка/трение — критика, перенаправление,
недовольство, неиспользованный доступный инструмент, плохие параметры;
(б) путь успеха — ≥3 значимых действия, результат получен и есть хотя бы
один неочевидный элемент (решение с причиной, не первая попытка, найденный
факт, восстановление после ошибки). Рутинное выполнение не проходит.
Петли инфраструктурных ошибок без прогресса отбрасываются.

**2. Сигналы поправки** (`playbook_extraction_context`, Valid Correction
Signals) — шире, чем «пользователь сказал нет»:
избежимый уточняющий вопрос (ответ должен был это включать), частичная
поставка («ты пропустил X»), застой при уже данном разрешении
(«продолжай»), непроверенное утверждение (просят доказать), пропущенная
параллельная поверхность (второй конфиг/док/фронт), повторный вопрос,
на который уже ответили, повтор невыполненного, дублирование работы.

**3. Качество триггера.**
- Триггер — *предшествующая ситуация*, а не реакция: самый ранний
  наблюдаемый момент, когда агент мог поступить иначе («правишь один из
  двух деплой-доков» вместо «синхронизируешь два дока»).
- Тест точки решения: триггер проверяем только тем, что видно в этот
  момент; факты, всплывшие позже, не могут быть условием.
- Правило AND/OR: случайные детали сессии нельзя добавлять через «и»;
  поздние симптомы — только через «или», для расширения.
- Не «пользователь поправил агента» и не «агент ошибся» как триггер.
- Тест тавтологии: «просят X → делай X» — не правило.

**4. Заземление.** Каждое утверждение правила подтверждается сессией;
не изобретать процедуры; не писать превентивных запретов на ошибку,
которой не было; запрет начинается с «Не/Никогда» и в обосновании
называет наблюдённый провал; ссылки на минимальный набор доказательств.
Если пользователь сказал «есть особый порядок», но не назвал его —
не додумывать, а задать вопрос (`ask_human`).

**5. Долговечность предпочтения.** «На будущее / всегда / мне всегда»
делает правило долговечным; выбор в рамках одной задачи — нет. Текст от
внутренних источников (инструмент памяти, генератор) не считается словами
пользователя, даже если роль `User`.

**6. Формат «пути успеха».** Применимо когда / Делать (кратчайший путь) /
Ограничения / Избегать (только реально случившиеся тупики) / Проверка
(узкая проверка, доказавшая результат); точные команды и значения —
только из финального проверенного состояния.

## Риски

- Тексты длинные (37 КБ основной промпт) — переносить 5–10 строк, а не
  разделы целиком (правило плагина: `SKILL.md` ≤ ~150 строк).
- Эффект не доказан на наших задачах: перед слиянием A/B на eval-кейсах
  `skill-feedback` (качество поля «Предложение» и `rule`).
