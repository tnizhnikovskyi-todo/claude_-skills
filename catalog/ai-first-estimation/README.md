## Что делает

Оценивает проект, в котором весь код пишут ИИ-агенты, и считает только
«чистое время человека»: постановку задачи, выдачу доступов, продуктовые
решения, смоук-тесты на проде, приёмку и надзор за агентом. Принцип: часы
человека растут не с объёмом кода, а с числом **точек касания с реальным
миром** (живые деньги, доступы, ревьюеры магазинов, необратимые действия,
решения). Выход: таблица `Модуль | Часы человека | Роль человека`, диапазон,
отдельно «несжимаемое ядро», урезанный вариант под открытые вопросы,
исключения и обязательные условия оценки. Подробно:
[`items/ai-first-estimation.md`](items/ai-first-estimation.md).

## Какую слабость Claude закрывает

Без указаний модель оценивает AI-сборку по привычкам «до ИИ»: часы на
написание кода, лишние задачи «по best practice», запас на воображаемую
сложность. Скилл переводит оценку на один вопрос: «что здесь делает
человек?». Это проблема и для нас: сборку MVP ведёт Claude
(`odoo19-mvp-build`), а таблица «Обсяг робіт» в наших ТР всё ещё по этапам
разработки (см. ниже).

**`preliminary-estimate` (пресейл).** Намного строже ai-first: нижняя граница =
часы по разрывам `G-N` + **исторические аналоги из фактических таймшитов Odoo**
(с годом, «чем похож / чем нет», пометкой «аналог по смежной отрасли»);
верхняя = нижняя × коэффициент полноты данных от `data-completeness-scorer`;
обязательная строка покрытия «оценено N из M разрывов»; неоцениваемое остаётся
пустым и уходит в «белые пятна» `Q-N`; аккуратная работа со ставками. Понятия
AI-сборки нет. **Главный вывод:** аналоги из таймшитов — это часы до ИИ;
когда сборку делает Claude, нижняя граница по аналогам систематически
завышена, а коэффициента «доля работы, которую забирает агент» нет.

**`tr-effort-instruction` (по форме выхода):** таблица «Обсяг робіт»
`Етап | План люд./год. | Коментар`, этапы *Технічне рішення / Архітектура /
Розробка / Тестування / Інструкція*, значения вилкой; при открытых вопросах
клиенту скилл может отказаться от оценки.

| Тема | ai-first-estimation | Наше | Итог |
|---|---|---|---|

## Риски и заметки

- Перед правкой `tr-effort-instruction` **прочитать его оригинал** (приватный
  репо): часть пунктов «у нас нет» может уже быть в тексте (принцип №28).
- Без данных о факте часов любые коэффициенты останутся догадкой. Полезнее
  сначала собрать факт по 5–10 ТР, собранным через `odoo19-mvp-build`:
  сколько человек реально тратил на постановку, ревью, UAT.
- Переход на «часы человека» меняет коммерческую модель (что продаём
  клиенту) — это решение руководства, а не правка скилла.
