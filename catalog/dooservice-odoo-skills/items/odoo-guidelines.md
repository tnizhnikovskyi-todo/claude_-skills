# odoo-guidelines (19.0) + version.md

- **Тип:** скилл (Markdown, 29 файлов, 256 КБ)
- **Источник:** `odoo/19.0/odoo-guidelines/` в dooservice/odoo-skills@f154564; основа:
  `odoo/odoo@20.0:skills/odoo-guidelines` (Odoo S.A., LGPL-3)
- **Вердикт:** адаптировать (таблицу фактов 19.0 и правило «одна версия»)

## Что делает

Правила кода аддона (без `static/`) по доменам: структура модуля, манифест, модели,
поля, computes/api, ORM, производительность, вью, actions, права, контроллеры,
внешний API, mail, мульти-компания, отчёты, миграции, переводы, тесты, `odoo-bin`.
`SKILL.md` — это карта «задача → файл», а каждый файл открывается списком главных
имён 19.0 и разделов. `version.md` — таблица «что есть в 19.0» по группам: ORM,
вью, права, роуты/тесты, веб, бизнес-записи, плюс «если не уверен — grep по
установленному исходнику».

## Ценное

- **Описание уже несёт самые изменчивые имена версии**: `<list>`,
  `models.Constraint`, `Domain`, `_read_group(..., ['__count'])`, `group_ids`,
  `privilege_id`, `type='jsonrpc'|'json2'`, тег `at_install`. Даже если тело не
  загрузилось, нужные имена уже в контексте. Сильный приём, переносим в наши описания.
- Таблица `version.md` сверена с исходниками (у нас 20/20 совпадений, см. `../notes.md`).
- «Когда не уверен»: grep в `odoo.__file__` установленной версии вместо памяти.

## Чего у нас нет

У наших `odoo19-*` нет единой таблицы фактов 19.0 с источником. Есть
`source-check` (метод «версия → источник → цитата»), но без готовой базы.
