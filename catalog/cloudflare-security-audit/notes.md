## Ключевые наблюдения

1. Их «независимая проверка» — не самопроверка. Это **опровергающий верификатор
   на каждого кандидата** со свежим контекстом (получает только кандидата, без
   выводов других верификаторов), плюс **второй** верификатор на финальную
   запись, плюс третий при существенной замене. Отличия от нашего
   `independent-check` (Δ=0): (а) работает по ширине — десятки кандидатов на
   весь репозиторий, задача фильтровать ложные срабатывания; (б) может
   **запускать** проверку в песочнице, то есть приносит новые факты, а не
   перечитывает. В нашем облаке их же правила песочницы не выполнимы
   (нет OS-изоляции с лимитами и без сети) → у нас верификатор будет только
   перечитывать код → ожидаем тот же Δ≈0 при цене ×N.
2. Больше пользы в **критике покрытия**: свежий агент смотрит не находки, а
   ledger, и ищет непокрытые входы/пути. README: «один прогон нашёл примерно
   половину того, что нашли повторные». Это про полноту, а не про перепроверку.
   У нас это можно сделать без агента: барьер «каждая строка диффа с
   `@http.route` / `sudo()` / `cr.execute` / новой моделью / правкой
   `ir.model.access.csv` / `ir.rule` есть в таблице покрытия».
3. Калибровка severity близка к нашей (Strix), но есть удачный различитель
   high/medium: «результат **полностью** снимает явный контроль для действия с
   реальными последствиями или только ослабляет?» и явные якоря уровней.
4. `needs_validation` без severity — у нас противоположное правило
   (`open_proof_gap` на BLOCK-поверхности → REQUEST CHANGES). Для ворот перед
   деплоем наше правило правильнее; берём у них только разделение плана
   проверки на «локально» и «у владельца инстанса».
5. Механика изоляции записи (11-шаговая «promotion procedure» с fstat и
   no-follow, повторённая дословно в 3 местах), бюджет агентов,
   percent-encoding `coverage_id` — для нас лишнее и дорого.

## Оценка стоимости (оценка, не замер)

- `SKILL.md` ≈ 22 КБ ≈ 5.5k токенов грузится на любой вопрос о безопасности
  (широкий `description`). Полный прогон: родитель читает ещё ~90 КБ, каждый
  охотник получает `architecture.md` + блоки + схему (~8–10k), минимум 4
  разведчика + 2 критика + охотник на единицу + 1–2 верификатора на кандидата.
  Для модуля `td.*` на ~10 единиц покрытия — порядка 20–25 запусков агентов,
  против одного (88k токенов) у нашего `security-review`. Порядок ×15–20.
