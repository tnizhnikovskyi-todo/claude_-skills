# Цикл `/plan-analysis` → `/start-coding` → `/testing` (+ `CommandingSystem`, `odoo_mcp`)

- **Тип:** 5 команд, скилл-оркестратор (225 строк + workflow-файлы 416/476/714 строк), MCP-сервер
- **Вердикт:** отклонить как продукт; дублирует `odoo19-mvp-build` и `odoo-connector`

## Что делает

- `/plan-analysis <v> <module>`: вопросы, обнаружение моделей через MCP, поиск
  в документации, выбор «персоны», PRD (`docs/requirements.md`, `design.md`,
  `tasks.md`), excalidraw-диаграмма.
- `/start-coding`: по задачам `tasks.md`, тест после каждой задачи через
  `sandboxctl` / `manage_modules.sh`; без `tasks.md` уводит в `/plan-analysis`.
- `/testing`: фронтенд-тесты, скриншоты, документация модуля.
- `/fleet`: по Docker-песочнице на модуль. `/rules-check-drift`: аудит правил.
- `odoo_mcp`: 7 инструментов чтения метаданных моделей (XML-RPC / JSON-2).

## Почему не нам

- Жёстко завязано на их окружение: `~/odoo-workspaces/<v>_workspace`, порты
  8765–8768, `manage_modules.sh`, Docker Sandbox microVM. В облачной сессии Claude
  Code этого нет.
- Дублирует `odoo19-mvp-build` (спека → код → тесты → ревью) и `odoo-connector`
  (живые поля и данные, уже подключён).
- Объём: workflow-файлы по 400–700 строк, `Agent-browser-skill` 1117 строк.
- В `plan_analysis_workflow.md` ссылка на несуществующий `copilot_odoo_agent.py`.

## Одна идея, которую стоит отметить

Ворота между шагами как хук, а не как текст: `/start-coding` физически не
стартует без `docs/tasks.md`, Stop не даёт закончить без записанного результата
тестов («Record only what the tests showed»). Если в `odoo19-mvp-build` модель
пропускает шаги — это готовый образец барьера. Пока нет свидетельств, что у нас
такая проблема есть; не переносим без наблюдения (`observations/`).
