# `OdooRequirementGapAnalysis`

- **Тип:** скилл + 3 скрипта (`audit_document.py`, `verify_modules.py`, `catalog_match.py`)
- **Источник:** `plugin/skills/OdooRequirementGapAnalysis/` (SKILL.md 323 строки + `references/`)
- **Вердикт:** адаптировать идеи (для владельцев `odoo19-tr-authoring` / `odoo19-sales-*`), не ставить

## Что делает

ТЗ клиента → fit-gap анализ Odoo: входной контроль документа (11 проверок:
читаемость, ссылки на несуществующие разделы, противоречивые приоритеты,
редакция и хостинг, системы учёта, конфиденциальность), атомизация требований
(`R-001`), сопоставление с модулями и **проверка имён модулей по исходникам**
(`verify_modules.py` по `__manifest__.py` Community/Enterprise), таблица
доказательств (возможность / файл / вывод), Fit/Partial/Gap, работы `CM-01`,
оценка в трёх сценариях с редактируемыми коэффициентами, «плейбук изменения
требований», выход DOCX + XLSX + заготовки PRD.

## Сильное

- «Never map a requirement to a feature you could not find. Say "not found in 19.0"» —
  то же, что наш `source-check`, но в предметной области пресейла.
- Скрипт проверки технических имён модулей — детерминированный барьер против
  выдуманных модулей.
- Входной контроль документа и «плейбук изменения требований» — полезны для пресейла.

## Слабое

- Коэффициенты ускорения (0.50–0.80) — допущения автора, сам скилл это признаёт.
- Завязан на их lifecycle (`/plan-analysis`, `sandboxctl`, `/fleet`).
- Пересекается с `sales-handover-analyzer`, `tr-*`, `odoo-spec-writer` по назначению.
