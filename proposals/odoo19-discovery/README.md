# Предложения для `odoo19-discovery-*` (задача 3.4)

Перенос метода `interview-me` (вопрос с догадкой, по одному, пересказ с «Out of scope», только
явное «да») в скиллы подготовки вопросов к живой встрече с клиентом:

- `odoo19-discovery-sessions:session-question-builder`
- `odoo19-discovery-initiation:kickoff-question-builder`

Плагины живут вне этого репозитория, поэтому здесь готовые к применению вставки для владельца.
Результаты проверки и открытые вопросы — в [`reports/discovery-interview.md`](../../reports/discovery-interview.md).

**Важно:** текущие тексты обоих скиллов в окружении не найдены. Вставки написаны как
самостоятельные блоки с метками «куда вставить» по названиям шагов; проверка делалась на
заменителях (`standin/`), восстановленных по соседним скиллам. Перед применением сверить места
вставки с реальным текстом.

## Что меняется по смыслу

Скиллы готовят вопросы для встречи, а не интервьюируют пользователя в чате, поэтому метод
адаптирован:

| `interview-me` | В подготовке встречи |
|---|---|
| Гипотеза задачи с % уверенности | «Гипотеза подготовки»: что клиент должен получить от встречи, % и чего не хватает |
| Вопрос + догадка | Каждый вопрос + «Наша гіпотеза» с источником (`бриф §N`, `журнал Q-N`); строки внутренние, клиенту не уходят |
| Один вопрос за раз | Одно предложение = один «?»; ≤ 7 вопросов на тему |
| Порядок кто → зачем → ограничения | Самый рискованный первым: блок «Головне» из 3–5 вопросов с высоким риском до тем |
| «Могу предсказать 3 ответа — стоп» | «Могу предсказать ответ по брифу/журналу — вопрос лишний» → убрать или «Підтвердити: факт» |
| Пересказ с Out of scope | «Out of scope цієї зустрічі» + кандидаты в X-N; «Підсумок для підтвердження», который БА зачитывает в конце |
| Только явное «да» | «Як вважаєте» / молчание — не согласие: в журнал как Q-N/C-N, не D-N/X-N |

## Что внутри

```
proposed/INSERT.md                     блоки A–D для вставки (с местами >>>) — основной артефакт
proposed/references/question-method.md довод, оценка риска, тест «предскажу ответ», примеры
proposed/references/ATTRIBUTION.md     атрибуция addyosmani/agent-skills (MIT) — обязательна
standin/*-question-builder.md          ЗАМЕНИТЕЛИ текущих текстов (оригиналов нет) — только для проверок
standin/*+INSERT.test.md               заменитель + вставка — только для проверок
standin/{session,kickoff}.diff         diff заменителя и собранного текста (показывает объём вставки)
tests/fixtures/                        3 фикстуры: K1, K2 (бриф → kickoff), S1 (план+журнал → сессия 3)
tests/keys/KEYS.md                     ключи оценки (не давать проверяемому агенту)
tests/results/                         ответы «текущий (A) / предлагаемый (B)» и оценка SCORES.md
```

## Как применить

1. В репозитории плагина открыть `skills/session-question-builder/SKILL.md` и
   `skills/kickoff-question-builder/SKILL.md`.
2. Вставить блоки из `proposed/INSERT.md`:
   - **A** (правила метода) — в начало шага, где собираются вопросы;
   - **B** (формат вопроса, «Гіпотеза підготовки», «Головне») — заменить формат вопроса в шаблоне
     опросника; добавить вариант для своего скилла (сессия: C-N/Q-N с ID, не переоткрывать D-N/X-N;
     kickoff: обещания продаж ⚠️ первыми, факты брифа не переспрашивать);
   - **C** (Out of scope встречи) и **D** (итог для подтверждения + правило «как вважаєте ≠ згода»)
     — в конец шаблона.
   - Лимит «8–15 / 5–10 вопросов» заменить на «≤ 7 на тему».
3. Скопировать `proposed/references/question-method.md` и `ATTRIBUTION.md` в
   `skills/<скилл>/references/` обоих скиллов.
4. Соседям по циклу (правило `siblings_checked`, задача 3.5):
   - `session-client-prep-builder` (письмо клиенту) — не переносить строки «Наша гіпотеза»,
     «Головне» можно дать как повестку;
   - `session-transcript-analyzer` / `kickoff-transcript-analyzer` — понимают новые поля
     опросника: «Підтвердити: …» с ответом «так» → факт, «Підсумок…» → D-N / X-N только при явном
     «так», иначе Q-N.
5. `claude plugin validate <путь к плагину>`; прогнать фикстуры из `tests/` (ниже).

Объём: ~+30 строк в SKILL.md (+~3,8 КБ) и ~85 строк в `references/` (+ ATTRIBUTION). На заменителях это ×2, потому
что заменители короткие (~60 строк); на реальном тексте типичного размера (150–250 строк, как
`session-transcript-analyzer`) — ориентировочно +20–35 %.

### `odoo19-sales-prep:brief-prep-pack` (по желанию, не проверялось)

Текст скилла тоже не найден. Если в нём есть раздел вопросов к клиенту / «Відкриті питання»,
достаточно вставить из блока A пункты 2, 3 и 5 (гипотеза к вопросу, фильтр «уже знаем», рискованное
первым) — без «Підсумку» и Out of scope, потому что это пакет подготовки, а не встреча.

## Как повторить проверку

Для каждой фикстуры и каждого плеча — отдельный каталог: файлы фикстуры + `skill/SKILL.md`
(A — заменитель, B — заменитель + вставка, плюс `skill/references/question-method.md`). Субагенту
(sonnet): «работай только в каталоге, прочитай skill/SKILL.md, следуй ему, уточнений не будет».
Оценка по `tests/keys/KEYS.md`. Цифры — в отчёте.
