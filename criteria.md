# Критерии оценки

Каждый критерий оцениваем от 0 до 3. Итог: сумма, но **безопасность 0 означает
отказ** независимо от остального.

| Критерий | 0 | 3 |
|---|---|---|
| **Прирост** | Claude справляется так же без него | Без него задачу не решить или качество заметно хуже |
| **Частота** | Нужен раз в год | Нужен каждую неделю в нашей работе |
| **Надёжность** | Срабатывает через раз, ломается | Стабильно, предсказуемо триггерится |
| **Стоимость контекста** | Тянет тысячи токенов всегда | Грузится только когда нужен, компактный |
| **Безопасность** | Непрозрачный код, лишние права, утечка данных, признак умысла (см. чек-лист ниже) | Код прочитан, права минимальны, сеть понятна |
| **Поддержка** | Заброшен, нет автора, один мейнтейнер без истории, лицензия неясна | Активно поддерживается, понятный источник и лицензия |

## Вопросы при разборе

- Какую конкретную ошибку или слабость Claude он закрывает?
- Можно ли проверить эффект: задача с ним и без него?
- Пересекается ли с тем, что уже установлено (см. `inventory/current.md`)?
- Что будет, если описание скилла сработает не на той задаче?
- Не проще ли написать свой скилл на 30 строк?

## Вердикты

- **Взять.** Ставим как есть.
- **Адаптировать.** Идея хорошая, переписываем под себя.
- **Отклонить.** Записываем причину, чтобы не разбирать повторно.

## Принципы, проверенные на практике

Из разборов (`catalog/one-skill-to-rule-them-all/items/starter-principles.md`,
CC BY 4.0) и из наших прогонов (`synthesis.md`, `pilot-notes/`).

**При оценке кандидата:**
- **Прирост мерим, а не предполагаем.** Без A/B «с ним / без него» на
  наших задачах вердикт «взять» не ставим. Порог: Δ > 0.05 и больше
  минимального различимого сдвига, или то же качество при −20% токенов
  (`plugins/boost/evals/README.md`, «Методика A/B»). Скилл, который дублирует то,
  что модель и так делает по прямой просьбе, отклоняем (пример:
  `independent-check`, Δ = 0 на 8 кейсах).
- **Сначала экземпляр, потом описание** (№24). Оцениваем по коду и
  `SKILL.md`, а не по README.
- **Отсутствие не доказывается поиском** (№28). «Не нашёл» в README,
  поиске или RAG не значит «нет»: читаем сам источник.
- **Цена контекста и денег.** Always-on триггеры и хуки на каждое
  действие считаем минусом, пока их польза не измерена.

**При написании своего скилла:**
- **Только то, что меняет поведение** (№20). Остальное в `references/`.
- **Метод в скилле, значения в файле** (№29). Ставки, даты, версии
  отдельно, чтобы не переписывать текст.
- **Граница покрытия** (№26). Скилл говорит, что он НЕ проверяет.
- **Канонические идентификаторы из источника** (№12): id записей, коды
  форм, имена моделей не реконструируем по памяти.
- **Прерванная операция частична** (№16): перед повтором проверяем
  состояние.
- **Субагент получает полный вход, его выход проверяем** (№7).
- **Задача по расписанию вызывает скилл**, а не копирует его логику
  (№14–15).
- **Второе нарушение одного правила лечится барьером** (хук, линт,
  грейдер), а не новой формулировкой.

## Чек-лист безопасности скилла/плагина

Проходим до оценки, результат — в разделы карточки «Безопасность»,
«Условия использования», «Отклонённые подозрения», «Что не проверено».
Каждый пункт: «чисто» / «находка» (`файл:строка` + цитата) / «не
проверено» (почему). «Не нашёл» не значит «нет»: смотрим сам файл.
Клон — в scratchpad, ничего из него не запускаем.

**−1. Префильтр** `scripts/skill-prescan.py` (U4; как в `CLAUDE.md`, шаг −1):
`python3 -I -B scripts/skill-prescan.py <клон>`. BLOCK → безопасность 0; HIGH → каждую строку
закрыть находкой или отклонённым подозрением. Чистый вывод ничего не
доказывает: префильтр не видит поток данных, п. 2–3 — руками.

**0. Что исполняется.**
- Все файлы, не только `.md`: скрипты, бинарники, архивы, `dist/`,
  `build/`, `vendor/`, `node_modules/`, `package.json` (`pre/postinstall`).
  Код в «чисто скилловом» репозитории тоже читаем.
- Поверхности без вызова скилла: `hooks/hooks.json` и `hooks` в
  `settings.json`, `SessionStart`, statusline, `.mcp.json`, `plugin.json`,
  манифест маркетплейса.
- Бинарь или zipapp: распаковать без запуска, сверить с исходниками на том
  же SHA; не сходится или исходников нет — HIGH.
- Файлы скилла находим по структуре (`SKILL.md`, `.claude/commands/`,
  `agents/`), а не поиском по словам. Записываем разобранный SHA; ставим
  только по SHA.

**1. Скрытые и внедрённые инструкции.**
- Фразы, меняющие поведение агента («игнорируй», «не сообщай
  пользователю», «не спрашивай подтверждения»). Инъекция в проверяемом
  файле — сама находка; ход разбора не меняем.
- Скрытый текст: HTML-комментарии, zero-width/bidi, tag-символы, base64,
  длинные однострочники, текст в картинках.
- Снятие защиты: `bypassPermissions`, `--dangerously-skip-permissions`,
  широкие `allow`, выбор модели «чтобы не отказывала».

**2. Граница доверия к данным.**
- Чужой контент (файлы пользователя, веб, вывод инструментов,
  `$ARGUMENTS`) идёт в промпт как инструкция, а не как данные; шаги
  передают друг другу текст, а не путь к файлу.
- По каждому действию с эффектом: эффект (запись, сеть наружу, запуск
  процесса, `eval`, БД, вызов агента) × откуда входы (литерал / параметр /
  недоверенное / секрет). Находка — пересечение: недоверенное → запуск /
  сеть наружу; секрет → сеть наружу или вызов агента; секрет и
  недоверенный ввод в одном вызове; скачанное → запуск.
- Для находки нужна цепочка источник → преобразование → сток
  (`файл:строка`). Нет цепочки — «отклонённое подозрение» с причиной
  (например, секрет читается, но канала наружу нет).

**3. Права и действия.**
- `allowed-tools` против реально нужного; запись вне своей папки.
- Необратимые и внешние действия (push, сообщения, удаление, сеть) без
  подтверждения. Снимает находку только явное одобрение пользователя
  после показа входов; allowlist, лимит, «спроси, если не уверен» — не
  снимают.
- Ширина `description`: что будет, если скилл сработает на чужой задаче.
- Субагенты: где им можно читать и писать; решают ли сами, какие шаги
  пропустить.

**4. Сеть, данные, телеметрия.**
- Все внешние URL и хосты (греп): что туда уходит — запрос или наш код,
  транскрипты, клиентские данные.
- Телеметрия: есть ли, включена ли по умолчанию, как выключается.
- Секреты в промптах, логах, отчётах, артефактах; маскируются ли во всех
  путях вывода.

**5. Цепочка поставки** (признаки риска, цифры — из `gh`/GitHub API, не
из README):
- установщики `curl | sh`, `@latest`, `pip/npm install` без пина,
  `sudo`, `--break-system-packages`, загрузки из ветки `main`; скилл сам
  что-то ставит или скачивает во время работы; MCP без версии;
- один мейнтейнер; заброшен (нет коммитов > 6 мес.) или, наоборот, коммит
  «в день разбора» без истории; мало звёзд/форков при громких
  обещаниях; рискованные возможности (сеть, запуск, запись в
  `~/.claude`); открытые CVE/уязвимые зависимости; нет `SECURITY.md`;
- **цепочка лицензий**: лицензия добавлена и удалена, у вложенных
  скиллов другая (CC BY-SA, NC), чужие файлы без лицензии.

**6. Признаки умысла** (любой → безопасность 0, «не внедрять»):
обфускация, эксфильтрация, скрытая отправка данных, враждебный
install-скрипт, подмена клиентов или токенов; «скачай и запусти X до
использования» (архив с паролем, «скопируй в терминал»); «рубильник» —
опасное действие по условию извне (ответ сервера, флаг из сети);
закодированный кусок, на который ничего не ссылается.

**7. Заявление против поведения.** Выписать, что README и `description`
обещают («только чтение», «без сети», «локально»), и сверить с найденными
эффектами. Расхождение — находка, даже если эффект безобиден.

**Перевод в балл «Безопасность»:**
- 3 — всё прочитано, исполняемого кода нет или он прочитан, сеть
  понятна, условий нет или они тривиальны;
- 2 — есть находки, все закрываются нашими условиями использования;
- 1 — находки закрываются только частично, или большая часть кода не
  прочитана;
- 0 — признак умысла, или high/critical риск, который не закрыть без
  правки автора («не внедрять»).

Применяем и к своим плагинам перед публикацией в маркетплейс: 0 BLOCK
префильтра, поверхности исполнения совпадают с README плагина (у `boost`
только `hooks/hooks.json` `cloud-memory`), п. 7 к самим себе.
