# Пилот: плагин boost и шаблон CLAUDE.md на проекте Odoo 19

Дата: 2026-11-02. Проект: `pilot/` (сервисная мастерская, 3 модуля, ~600
строк). Ключ заложенных проблем: `KEYS.md` (в прогоны не попадал).

## Как проводили

- Копия `pilot/` в отдельном git-репозитории в scratchpad, чтобы правила
  хаба из корневого `CLAUDE.md` не попали в контекст. В обоих плечах
  действует `pilot/CLAUDE.md` (шаблон 0.3 без блока Context7).
- `claude -p`, модель сессии по умолчанию, по одному прогону на плечо.
  «С плагином» = `--plugin-dir plugins/boost`; «без» = тот же запрос без
  плагина. Инструменты ограничены (`Read Grep Glob`, плюс `WebFetch` для
  проверки фактов, `Write Edit` для записи памяти).
- Оценка ручная по ключу (главная сессия).

Всего на пилот ≈ $3.3.

## Выводы

1. **Шаблон `CLAUDE.md` (0.3) работает и даёт дисциплину обоим плечам.**
   В каждом ответе есть `UNVERIFIED` там, где не проверено, финальная
   строка `Не проверено / риск`, ссылка на правило про `except: pass` и
   `sudo()` без комментария. Это самая дешёвая часть с заметным эффектом.
2. **На реалистичном проекте находки плагина ≈ находкам базовой модели.**
   Скиллы добавляют форму: 4-частные находки с группами важности,
   ссылки и цитаты из источников, структурированные записи памяти. Цена
   выше на 5–50%. Это совпадает с выводами eval (см. `synthesis.md`).
3. **Обе ветки упёрлись в одно и то же: факты Odoo 19 без сети.** Без
   `WebFetch` аудит пометил K9 как `UNVERIFIED`; с `WebFetch` обе ветки
   подтвердили его по исходникам. Context7 сделает это без открытия
   GitHub и дословно.
4. **Скрипт `odoo_map.py` полезен сам по себе:** бесплатная карта и
   модели без прав за доли секунды.
5. **Ни один прогон не нашёл K12 целиком** (нет правила мультикомпании
   у строк заказа). Кандидат на пункт чек-листа `repo-audit` и
   `security-review`: «у дочерней модели есть свои `ir.rule`?».
