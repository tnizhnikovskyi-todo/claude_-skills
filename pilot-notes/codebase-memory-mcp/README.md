## Вердикт

**Не брать сейчас, ни рядом с `odoo-model-map`, ни вместо него.**

1. Правильность уже на потолке без MCP на обоих масштабах (600 строк
   пилота и 5 аддонов ядра, 229 МБ). Выиграть можно только центы и
   секунды на вопрос.
2. Самые важные для Odoo связи (строковый `_inherit`, XML-вью, права) по
   устройству графа ему не видны; их даёт `odoo_map.py` бесплатно и за
   доли секунды. «Вместо» исключено.
3. «Рядом» стоит 331 МБ стороннего бинарника, переиндексация на каждом
   старте облачной сессии и ≈5,7k токенов схем при неотложенной загрузке.
   Для этого нужен измеримый выигрыш, а его здесь нет.
4. Остаётся непроверенным один сценарий, где MCP мог бы окупиться:
   большой рабочий репозиторий, где grep-плечо начинает тонуть (сотни
   совпадений, многошаговые цепочки вызовов). Вернуться к нему, если такие
   вопросы появятся, и прогнать `run_mcp_arm.sh` уже с разрешением.

## Как довести MCP-плечо

Нужно разрешение на запуск бинарника для классификатора, которое эта сессия
поставить себе не может (разрешение из главной сессии сюда не доходит).
После этого: скачать архив по `notes.md` §1, сверить SHA-256 и подпись,
затем `S=… CBM_BIN=… CBM_HOME=… run_mcp_arm.sh` (индексация + время +
размер индекса), затем `run_ab.sh mcp <вопрос> <цель> <out>` для 6 вопросов.
Ожидаемая стоимость ≈ $0.6–1.
