## Стенд

`build_stand.sh <репо> <dest>`: копия `pilot/` в отдельном `git init` в
scratchpad (корневой `CLAUDE.md` хаба не попадает), 28 коммитов и ловушки:

| Ловушка | Где | Что rtk может потерять (по разбору кода) |
|---|---|---|
| L1 | указание миграции и тикет WS-4471 только в **теле** коммита | `git log` → хэш/автор/тема, тело отбрасывается |
| L2 | незакоммиченный дифф ~800 строк, `DEFAULT_DISCOUNT 0.0 → 0.35` в самом конце | `git diff`: ханк ≤100 строк, весь дифф ≤500 |
| L3 | `.github/workflows/report_template.xml` и gitignored `data/local/override_demo.xml` | `rtk find` уважает `.gitignore` и скрытые каталоги (если `^find` не исключён) |
| L4 | `legacy_hooks.py` с `SyntaxError` в строке 1 | — (проверка, что код выхода/ошибка не теряются) |
| L5 | 1200 строк вывода, одна `ERROR` в строке 637 | дедупликация/лимиты лог-фильтров |
| L6 | 361 строка `TODO`, нужная (`mod_27.py:13`, про `sudo()`) в хвосте | `grep`: лимит на файл и всего, `+N more` |

Задачи — `tasks.json` (T1–T8: `git log`, `git diff`, `git status`,
`grep -rn`, `find`, `py_compile`, `odoo_map.py`, длинный вывод). Ключи
правильности — подстроки финального ответа.

Запуск: `claude -p`, только `Bash` (`Read/Grep/Glob/Edit/Write/Web*`
запрещены, чтобы всё шло через Bash), `--model claude-sonnet-5-5` (бюджет),
`--output-format stream-json --verbose`, свежая копия стенда на каждую
задачу. Плечо rtk отличается только `--settings settings-rtk.json`
(хук `rtk hook claude`) и `PATH` с бинарником. Оценка — `score.py`.

## Что уже видно без плеча rtk

1. **Потолок экономии маленький.** Весь вывод Bash за 8 задач — ~18.5k
   токенов из 684k входных (**≈2.7%**). Остальное — системный промпт и
   инструменты (~35k токенов на ход), которые rtk не трогает. Даже если rtk
   сожмёт вывод на 90%, это −2.4% входа. Под правила rtk попадают только
   `git diff`, `git log`, `git status`, `grep` (≈45 КБ ≈ 11k токенов,
   ≈1.6% входа). Переписывает ли он `python3 скрипт.py` и составные
   команды с `|` / `>`, не проверено (по разбору: правил для своих
   скриптов нет, «непрозрачные» конструкции лексер не трогает).
2. **Claude (Sonnet) и так пишет экономные команды** (`--grep`,
   `--porcelain`, фильтры `find`, вывод в файл + `grep -v`). Там, где
   выигрыш rtk был бы большим (T8, 78 КБ), Claude сжал вывод сам.
3. **Риск тот же, что в разборе:** 3 из 6 ловушек (L1 тело коммита, L2
   хвост диффа, L6 хвост grep) лежат ровно в зоне урезания rtk. В базе
   все найдены; цена ошибки (пропустить миграцию или `sudo()`-обход) выше
   выигрыша в 1–2% токенов.

## Вердикт (предварительный, до плеча rtk)

**Не брать в окружения по умолчанию.** Ожидаемая экономия на наших
задачах 1–3% входных токенов при ненулевом риске тихих потерь в `git log`,
`git diff`, `grep`. Пересмотреть, если появятся сессии с тяжёлыми
шумными командами (большие тестовые прогоны `pytest`/Odoo-тесты с сотнями
строк лога, сборки, `npm install`) — там доля вывода Bash выше; это и
стоит мерить, а не `git`/`grep`.

Окончательный вердикт — после плеча rtk (см. «Как досчитать»).
`templates/rtk/` не создан: вердикт не «взять». Рецепт установки на случай
пересмотра — в `catalog/rtk/README.md`.

## Как досчитать плечо rtk

Нужно, чтобы пользователь разрешил запуск бинарника в этой сессии: прямым
сообщением в этот чат или правилом разрешения Bash. Потом:

```bash
SCR=<scratchpad>                      # там stand/, bin/rtk, xdg/
./run_ab.sh rtk "$SCR/out/rtk"        # 8 задач, ~$0.3–0.7 на Sonnet
python3 -I score.py "$SCR/out/rtk" --cmds
```

Для чистоты сравнения прогнать базу ещё раз сразу после
(`./run_ab.sh base "$SCR/out/base2"`), чтобы кэш был одинаковым.
