### Формат памяти (в рабочем репозитории)

```
memory/
  INDEX.md                  по строке на запись, новые сверху; подмешивается хуком
  HANDOFF.md                последнее состояние незаконченной работы; подмешивается хуком
  YYYY-MM-DD-<slug>.md      frontmatter: type (decision|bugfix|discovery), date, tags, status
                            (active|open|superseded|obsolete), summary; тело до ~15 строк
```

## Проверка

### `claude plugin validate plugins/boost`

`√ Validation passed`. Каталожная проверка предупреждает, что нет LICENSE
(ни в плагине, ни в корне репозитория) и нет иконки (см. «Правки общих

### Ручная проверка хука: две последовательные сессии в облачном контейнере

1. Сессия 1 (`claude -p --plugin-dir plugins/boost` во временном git-репо):
   «Запомни: деплой только по вторникам 14:00…, коммитить не надо».
   Создала `memory/2026-11-02-deploy-window.md` (type: decision, причина и
   источник на месте) и `memory/INDEX.md`. Коммит не сделала и
   предупредила, что без коммита запись пропадёт. Стоимость $0.20.
2. Имитация нового контейнера: коммит `memory/`, затем `git clone` в новый
   каталог. Сессия 2 запущена там со **всеми инструментами чтения
   выключенными** (`--disallowedTools "Read Bash Grep Glob Skill Agent"`).
   В stream-json виден блок `<cloud-memory>` от хука. Ответ: «деплоить
   только во вторник в 14:00, решение от 2026-11-02, взял из индекса
   памяти». Это критерий задачи из roadmap: вторая сессия отвечает о
   прошлом решении без пересказа пользователем.
3. Контроль: тот же вопрос в репо без `memory/`. Хук молчит, ответ «не
   знаю, правил деплоя не вижу».
4. Находка: без чтения файла сессия 2 **додумала** причину («чтобы был
   свежий бэкап для отката») вместо настоящей («клиент закрывает смену»).
   Исправлено: в выводе хука и в скилле теперь сказано, что строка индекса
   передаёт только суть, а на вопрос «почему» нужно сначала прочитать
   запись. В скилл добавлен запрет дописывать свои причины в запись (eval
   поймал и такое: «вторничное окно оставляет запас времени…»).

Хук срабатывает и внутри `claude plugin eval`: это видно в трейсе
(`SessionStart:startup`, `exit_code 0`) и по пробному кейсу, где модель
процитировала первую строку блока `<cloud-memory>`.

Стоимость итогового прогона $1.80. Всего на eval за задачу около $5.6:
четыре полных прогона (первые два отсеяли ошибки грейдеров) и два пробных
по одному кейсу. Плюс ручная проверка ~$0.5.

**Вывод.** Скилл даёт положительную разницу там, где важен формат и
правила: запись, handoff, отказ хранить секрет при сохранении полезного
факта. На лишних задачах не срабатывает. На `recall-why` качество
одинаковое: если `memory/` уже лежит в репозитории, базовый Claude тоже
находит его grep'ом. Плагин отвечает за 2 хода вместо 3.7 и дешевле на
~15%, потому что индекс уже в контексте.

**Как честно читать Δ.** Без плагина Claude пытается писать во
встроенную авто-память `~/.claude/projects/<проект>/memory/`. В песочнице
eval запись туда запрещена, поэтому базовая рука отчасти проваливается
из-за окружения. В настоящей облачной сессии запись туда прошла бы, но
этот каталог лежит в домашней папке эфемерного контейнера и **пропадает
вместе с ним**. Ровно эту проблему и решает задача. Значит, для облака
вывод «без плагина память не переживает сессию» верен, но размер Δ в
таблице частично объясняется песочницей. Отдельно: базовая рука ни разу
не сохранила пароль. Отказ хранить секреты у модели есть и без скилла,
скилл добавляет к нему сохранение безопасной части.

## Что не получилось / ограничения

- **Грейдер «пароль не записан ни в один файл»** работает через LLM-судью
  по трейсу (`focus: trace`). Трейс весит ~110 КБ, и судья, судя по
  evidence, видит его начало. Этот грейдер надёжен меньше остальных. Жёсткая
  regex-проверка есть только для `memory/INDEX.md`, потому что имя файла
  записи заранее неизвестно. По той же причине из `remember-decision` убран
  судья по трейсу: он давал ложные FAIL.
- **Stop-хук в облаке дублирует платформу.** В облачном контейнере уже
  есть глобальный Stop-хук (`~/.claude/stop-hook-git-check.sh`). Он
  заставляет агента закоммитить и запушить любые изменения, `memory/` тоже.
  Наш хук нужен в основном для локальной работы. В облаке он только
  показывает пользователю строку, что изменилась именно память. Скилл
  разрешает коммит, когда «правила сессии уже требуют коммитить», поэтому
  конфликта нет. Если дубль мешает, `Stop` можно убрать из `hooks.json`.
- Маскировка `<private>` в хуке работает только для однострочных блоков.
  Это страховка: главное правило в скилле не записывать такое содержимое.
- Хук берёт корень из `CLAUDE_PROJECT_DIR` (или `$PWD`). Если сессия
  запущена в подпапке монорепо, где `memory/` лежит в корне git, хук
  промолчит. Сознательно не стал вызывать `git rev-parse`: так хук быстрее
  и не зависит от git.
- Плагин-ориентированных грейдеров по реальному второму запуску внутри eval
  нет: одна eval-сессия это один запуск. Перенос памяти между сессиями
  проверен вручную (выше).

   (видна команде, проходит ревью) или в отдельной ветке? Сейчас скилл

## Нужные правки общих файлов (для главной сессии)

1. `plugins/boost/README.md`, таблица «Состав»: строка
   `| cloud-memory | Память проекта в git (memory/): индекс и handoff на старте сессии, запись решений/багов/находок без секретов | готов, A/B 5/5 vs 1/5 | 2.1 |`.
   В разделе правил добавить, что у плагина есть хуки `SessionStart` и
   `Stop` (оба молчат, если нет `memory/`).
2. **LICENSE.** `claude plugin validate` (профиль directory) требует LICENSE
   в корне репозитория или `license` в `plugin.json`. Предлагаю
   `"license": "MIT"` (или другую, на выбор владельца) в
   `plugins/boost/.claude-plugin/plugin.json`.
3. `plugins/boost/evals/README.md`, что выяснилось про `claude plugin eval`:
   - `scaffold_script` должен лежать **внутри** папки кейса (`../`
     запрещено), запускается в рабочем каталоге кейса, только с `--scaffold`.
   - `--case 'скилл/*'` сравнивается с полем `name` в `case.yaml`, поэтому
     имена кейсов нужно писать с префиксом: `name: cloud-memory/handoff`.
   - В regex-грейдерах не работает `(?i)` (регэкспы JS), нужно `flags: i`.
   - У `llm`-грейдера есть `focus: last_message | trace | files |
     {source: file, path}`. С `trace` судья видит только начало большого
     трейса, поэтому лучше целиться в файл.
   - `file_exists` поддерживает `exists: false`, а regex поддерживает
     `match: not_contains`.
   - Для `--allow-tools Bash` нужна песочница: `apt-get install bubblewrap
     socat`. В облачном образе их нет, без них прогон отказывается
     стартовать. Возможно, стоит добавить их в setup-скрипт окружения.
   - Без `--model` eval гоняет `claude-sonnet-5-5`, судья haiku.
4. `roadmap.md`, статус 2.1: «готово, ждёт слияния».
