# Отчёт: review-upgrades (задачи 3.1, 3.2)

Ветка `build/review-upgrades`. Все артефакты лежат в `proposals/odoo19-mvp-build/`, инструкция по
применению — в её `README.md`.

## Что сделано

| Задача | Результат | Где |
|---|---|---|
| 3.1 `security-review` | Полный новый текст + diff + 3 файла `references/` + атрибуция Strix | `proposals/odoo19-mvp-build/security-review/` |
| 3.2 `pr-review` | Блоки для вставки с указанием места + `references/review-discipline.md` | `proposals/odoo19-mvp-build/pr-review/proposed/` |
| Проверка | 5 фикстурных PR, ключи, 10 прогонов, оценка | `proposals/odoo19-mvp-build/tests/` |

**3.1 по сути:**
- три состояния закрытия кандидата и список того, что НЕ доказывает безопасность, с примерами для
  Odoo: UI-домены и `groups=` во view, OR правил разных групп через `implied_ids`, публичный метод
  вызывается по RPC, `SQL(f"…")`, `Markup`, проверка после `sudo().read()`;
- калибровка VULN по чек-листу, правило «понижай, не удаляй»;
- 5 ворот для предлагаемого фикса и право фикс не давать;
- скоуп диффа (новая достижимость старого синка, ослабленный общий контроль, удалённый контроль);
- описание PR считается недоверенным вводом;
- в выводе появились формат находки (trace / counterevidence / severity change / gates), таблица
  покрытия, «Open proof gaps» и «Noted, not blocking»;
- новое правило вердикта: `open_proof_gap` на BLOCK-поверхности не даёт APPROVE.

**3.2 по сути:**
- формат находки из 4 частей с правилом «нет конкретного кейса — нет находки»;
- метки regression / newly reached / pre-existing; новые строки, повторяющие старый дефект, считаются
  regression (правило добавлено после проверки P2);
- «пол» качества: `noqa`, skip, ослабленные или удалённые тесты, пороги, `except: pass`, `sudo()`
  ради зелёного теста;
- мутационная проверка (1–3 мутации, при отсутствии Odoo — на бумаге);
- Prove-It для багфиксов;
- новые разделы вывода.

## Где искал текущие тексты

- `security-review`: найден в
  `/root/.claude/skills/synced/<org>_<id>/security-review/SKILL.md` (это скилл организации
  `anthropic-skills:security-review`, его описание совпадает с `odoo19-mvp-build:security-review`).
  Снимок лежит в `security-review/current/SKILL.md`.
- `pr-review`: **не найден**. Где искал:
  - `~/.claude/plugins/synced/*/` (пусто), `~/.claude/plugins/store/`;
  - `/root/.claude/skills/synced/*/` (21 скилл, `pr-review` нет), `find / -name SKILL.md`;
  - `gh api search/code` по `"odoo19-mvp-build"` и `"pr-review" "track-convergence"` — 0 результатов;
  - `list_repos` (odoo, plugin) — репозитория плагинов нет.
  Поэтому 3.2 оформлена как вставка. Для проверки написан явный заменитель `BASELINE-STANDIN.md`
  (реконструкция по описанию соседнего скилла), применять его не нужно.

## Результат проверки (с текущим текстом / с предложенным)

Подробности в `tests/results/SCORES.md`, ответы агентов в `tests/results/`.

| Скилл | Фикстуры | Текущий (A) | Предложенный (B) | Стоимость B к A |
|---|---|---|---|---|
| security-review | S1 IDOR + «безопасный сосед» + инъекция в описании PR; S2 OR правил + SQLi «только cron» + старый `sudo()`; S3 обходимый блэклист-фикс + калибровка | 13.5/15 | 15/15 | +~15 % токенов, ~×1.8 по времени |
| pr-review | P1 «пол» + Prove-It; P2 мутации + старый дефект | 8/10 (заменитель) | 10/10 | +~5 % токенов |

Ни один вариант не дал APPROVE и не завысил severity у `color`/`manager_note`.

Вывод:
- Базовый `security-review` уже находит заложенные дыры.
- Прирост B не в числе найденного, а в дисциплине: таблица покрытия с названными контролями,
  открытые пробелы вместо молчания, старые дефекты отделены от новых, у фикса проверены ворота,
  меньше раздувания (в S2 у A было 4 VULN, у B — 2 точных).
- pr-review: в P1 «пол» нашли оба варианта, но только B показал, что существующий тест прошёл бы
  и на base. В P2 только B провёл мутационный анализ (3 выжившие мутации) и вынес старый дефект
  из вердикта.

Ограничения:
- n = 1, оценивал автор предложения;
- полноценный A/B через `claude plugin eval` не делался, потому что плагин не наш;
- для pr-review вариант A — заменитель.

## Что не получилось / отклонения

- **Объём `security-review`:** +52 % по символам (192 → 284 строки) при ориентире ~40 %. Детали
  вынесены в `references/` (~250 строк). Резать дальше значит убирать то, что нужно в каждом прогоне:
  состояния, формат находки, таблицу покрытия, правило вердикта. Если владелец хочет ≤40 %, следующим
  кандидатом на вынос идёт блок «Concrete fixes — 5 gates» (останется одна строка со ссылкой).
- Текст `pr-review` недоступен, поэтому полного нового текста и настоящего diff для него нет.
- В `references/closure-and-severity.md` упомянут `check_access(...)` (v18+). Это стоит сверить с
  документацией Odoo 19 через Context7. В тексте есть пометка «verify with official docs».
