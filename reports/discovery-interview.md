Плагины `odoo19-discovery-*` живут вне репозитория, поэтому результат — предложения в
`proposals/odoo19-discovery/` (как применить: `README.md` там же).

| Файл | Что |
|---|---|
| `proposed/INSERT.md` | Блоки A–D с местами вставки для `session-question-builder` и `kickoff-question-builder` |
| `proposed/references/question-method.md` | Довод, оценка риска, тест «предскажу ответ», примеры плохо/хорошо, лозунги, явное «так» |
| `proposed/references/ATTRIBUTION.md` | addyosmani/agent-skills `301b02b`, MIT, через наш `interview-me` |
| `standin/` | Заменители текущих текстов, собранные тестовые версии, диффы |
| `tests/` | 3 фикстуры (выдуманные компании), ключи, ответы A/B, слепые оценки, `results/SCORES.md` |

Как адаптирован метод `interview-me` (скиллы готовят вопросы к живой встрече, а не опрашивают
пользователя):
- «Гіпотеза підготовки» с % уверенности в начале опросника;
- к каждому вопросу «Наша гіпотеза» с источником (`бриф §N`, `журнал Q-N`); строки внутренние для
  БА, в письмо клиенту и протокол не переносятся;
- тест «могу предсказать ответ по брифу/журналу — вопрос лишний» → убрать или «Підтвердити: факт»;
- одно предложение = один «?» (с примерами типичных склеек);
- блок «Головне»: 3–5 вопросов с высоким риском до тем; метка `ризик:`; ≤ 7 вопросов на тему,
  остальное в «Якщо лишиться час»;
- «Out of scope цієї зустрічі» + кандидаты в X-N; «Підсумок для підтвердження», который БА
  зачитывает в конце; «як вважаєте» / молчание не согласие → Q-N/C-N, а не D-N/X-N;
- вариант для сессии: C-N/Q-N всегда и с ID, D-N/X-N не переоткрывать (только «Підтвердити»);
  вариант для kickoff: обещания продаж ⚠️ первыми, факты брифа не переспрашивать.

`brief-prep-pack`: текст не найден; в README предложена короткая версия (пункты 2, 3, 5 блока A)
без проверки.

Что известно из соседей и легло в заменители: `session-question-builder` читает план и журнал
(D/X/C/T/Q/A), пишет `питання_сесії-[N]_[компанія].md` с полями «Відповідь:» и тегами, создаёт

`sales-handover-analyzer` (`бриф_[компанія].md`) → вопросы → установочная встреча →
`kickoff-transcript-analyzer`. Заменители помечены как «не оригинал», как в 3.2.

## Проверка

3 фикстуры: K1 «БудМаркет Захід» и K2 «АвтоДеталь Схід» (бриф → kickoff), S1 «Смачна Пекарня»
(план + журнал → сессия 3). Каждое плечо — отдельный каталог, субагент sonnet: «прочитай
skill/SKILL.md и следуй ему, уточнений не будет». Оценка — отдельный субагент sonnet вслепую по
`tests/keys/KEYS.md`. Полная таблица — `proposals/odoo19-discovery/tests/results/SCORES.md`.

| Критерий | A (текущий) | B (раунд 2, итоговый текст) |
|---|---|---|
| Доля вопросов с гипотезой | 0 % / 0 % / 0 % | 87 % / 89 % / 100 % |
| Анкетные вопросы (ответ уже в брифе/журнале) | 4 / 2 / 1 | 0 / 2 (спорные) / 0 |
| Рискованные среди первых 5 (≥ 3 из ключа) | нет / нет / нет | да (5/5) / да (5/5) / да (4/5) |
| Out of scope | нет / нет / нет | да / да / да |
| Склеенные вопросы | ~38 / ~40 / ~31 | 3 / 0 / 0 |
| Всего вопросов | 49 / 55 / 35 | 30 / 27 / 21 |

Порядок: K1 / K2 / S1. В S1 обязательные пункты журнала (C-1, C-2, Q-3, Q-4, T-1) покрыты в обоих
плечах, но в A они разбросаны (C-1 — 14-й вопрос), в B — в «Головне» с ID. Переоткрытых D-N/X-N
нет в обоих плечах.

Раунд 1 B уже давал гипотезы, риск первым и Out of scope, но оставалось 4–6 склеенных вопросов
(«чи змінюється … і хто приймає рішення?»). Правило 4 дополнено примерами типичных склеек и
советом «вторую часть — в гипотезу»; в раунде 2 склеек 3 / 0 / 0.

**Стоимость:** 9 прогонов исполнителя (~70–75 тыс. токенов каждый) + 2 прогона оценщика
(~250 тыс.), всё на sonnet; оценка по токенам ≈ $2–2,5, в пределах бюджета ~$3. Точной цифры
нет: подсчёт стоимости субагентов в сессии не выводится.

## Что не получилось / ограничения

- **Оригиналы не найдены.** Проверка на заменителях (~50 строк). Реальные скиллы, вероятно,
  длиннее и уже содержат свои правила: эффект может быть меньше, а места вставки нужно сверить.
- **Объём.** Вставка ≈ +30 строк (+3,8 КБ): на заменителе это ×2, на реальном тексте типичного
  размера (150–250 строк) — ориентировочно +20–35 %. Детали вынесены в `references/` (85 строк).
- **Один прогон на ячейку**, оценщик — модель, не человек. Разрыв A/B большой (0 % → ~90 %
  гипотез), поэтому вывод устойчив, но цифры 87/89/100 % шумные.
- Не проверено: как `session-client-prep-builder` обращается с полями «Наша гіпотеза» (риск утечки
  к клиенту) и как `session-transcript-analyzer` читает «Підтвердити:» и «Підсумок…».
- `claude plugin validate` не применим: в нашем репозитории нет собранного плагина с этими скиллами.
