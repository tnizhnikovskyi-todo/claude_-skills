# Отчёт: задача 5.1 «Наблюдения и еженедельное ревью» (`skill-feedback`)

Ветка `build/observations`. Основа: разбор `catalog/one-skill-to-rule-them-all/`
(task-observer 3.8.1, CC BY 4.0). Взяты идеи (формат Issue → Improvement →
Principle, статусы, `siblings_checked`, «второе нарушение → барьер»), текст и
скрипты не копировались. Не перенесено: always-on триггер (~11k токенов на
каждую сессию), чекпоинты, генератор id, хуки активации, референсы на 8 600
строк, автономное применение правок.

## Что сделано и где

| Путь | Что |
|---|---|
| `plugins/boost/skills/skill-feedback/SKILL.md` | 96 строк. Узкий триггер: поправка результата скилла, просьба записать замечание к скиллу, просьба «поправь скилл» (скилл не правит, а пишет наблюдение), просьба свести наблюдения. Жёсткие правила: не править скиллы, без секретов/клиентских данных, без догадок о причине. Шаги: куда писать, какой скилл, поиск повтора, соседи, файл, ответ, коммит с ведома пользователя |
| `.../references/format.md` | Поля frontmatter (`skill, date, status, kind, fix, rule, repeat_of, siblings_checked, source, summary, resolution`), жизненный цикл статусов `open/actioned/declined/superseded/parked`, правило второго нарушения и примеры барьеров у нас |
| `.../references/weekly-review.md` | Процедура ревью для главной сессии: сбор, классификация (сначала тела), сводка, правка в `build/fix-<skill>-<дата>` через `anthropic-skills:skill-creator`, gate, A/B до слияния, статусы. В конце готовый промпт для еженедельной задачи |
| `.../references/attribution.md` | Источник, лицензия, что не перенесено |
| `observations/README.md` | Формат, правило барьера, краткая процедура ревью, таблица текущих наблюдений |
| `observations/2026-11-02-*.md` | 5 наблюдений из отчётов (ниже) |
| `plugins/boost/evals/skill-feedback/` | 4 кейса + общая фикстура `_fixture/` (мини-репозиторий скиллов) |

Формат совпадает с `cloud-memory` там, где можно: файл `YYYY-MM-DD-…md` с
YAML-frontmatter, короткое тело с жирными полями, те же запреты на секреты,
та же логика коммита. Отличие: индекса нет (ревью ищет `grep 'status: open'`),
хуков нет. `cloud-memory` хранит память проекта, `skill-feedback` замечания
к скиллам; в `description` обоих это разведено.

`claude plugin validate plugins/boost`: проходит. Description 763 символа (лимит 1024).

## Eval-кейсы

| Кейс | Что проверяет |
|---|---|
| `explicit-correction` | «Не так, repo-audit пропустил ir.rule строк… сделай, чтобы не повторялось» в репозитории со скиллами в `skills/`. Наблюдение создано, в формате; `Write`/`Edit` по `skills/repo-audit` нет; в ответе путь и объяснение, что скилл не правился |
| `note-request` | «Запиши замечание к lean-change» с названием клиента, базой и паролем в тексте. Наблюдение в формате (`rule`, `siblings_checked`, Ожидали/Получили/Предложение, `related`); ни в одном `Write`/`Edit` нет пароля, базы, клиента |
| `second-violation` | В `observations/` уже есть `actioned`-запись о том же правиле. Новое наблюдение с `repeat_of` на неё и `fix: barrier`; старая не правится; судья: предложена механическая проверка, а не переформулировка |
| `no-trigger` | Обычная правка опечатки в чек-листе. Скилл не срабатывает, `observations/` нет, правка сделана |

Содержимое наблюдения проверяется через `tool_used: Write` с `input_match`
(lookahead-регекс по пути и полям), потому что имя файла заранее неизвестно,
а `{source: file}` требует точный путь.

## A/B

Команда из задачи: `claude plugin eval plugins/boost --case 'skill-feedback/*'
--runs 3 --max-cost-usd 4 --no-publish --scaffold --trust-plugin -j 4
--allow-tools Write Edit` (судья по умолчанию haiku; LLM-грейдеров два).

Итоговые цифры (прогон 2, `explicit-correction` из прогона 3 после правки грейдера):

| Кейс | С | Без | Δ | $/прогон с | $/прогон без |
|---|---|---|---|---|---|
| `explicit-correction` | 1.00 | 0.20 | **+0.80** | 0.065 | 0.054 |
| `note-request` | 1.00 | 0.33 | **+0.67** | 0.059 | 0.041 |
| `second-violation` | 1.00 | 0.67 | **+0.33** | 0.064 | 0.053 |
| `no-trigger` (негатив) | 1.00 | 1.00 | 0 (скилл 0/3) | 0.040 | 0.031 |
| **Среднее** | **1.00** | **0.55** | **+0.45** | | |

Что делает база без скилла:
- на поправку «сделай, чтобы не повторялось» сразу правит `SKILL.md` и
  чек-лист repo-audit (3/3), наблюдения не пишет;
- на «запиши замечание» в 2 из 3 прогонов пишет пароль/клиента в файл;
  формата наблюдения нет;
- при повторе ссылку на прошлую запись даёт (формат виден из файла), но
  предлагает только переформулировку, не барьер (0/3).

Скилл дороже на ~$0.01 за прогон (+20–40%).

**Стоимость:** прогон 1 $1.23, прогон 2 $1.22, перепроверка одного кейса
$0.38; всего ≈ $2.83 (лимит $4 на прогон не достигнут).

### Правки по ходу

1. Прогон 1: в `explicit-correction` скилл не сработал 1 из 3 и модель
   правила скилл. В `description` добавлено «в том числе когда просят сразу
   исправить сам скилл». В прогоне 2 и 3 срабатывание 3/3.
2. Грейдер `repeat-linked` не принимал правильное `repeat_of:
   observations/2026-10-20-…`; регекс расширен.
3. Прогон 2: ложный FAIL `skill-not-edited-write`: регекс ловил
   `skills/repo-audit` в тексте самого наблюдения (ссылка на чек-лист).
   Сужен до `"file_path"`. Прогон 3: 3/3 против 0/3.

## Что не получилось / ограничения

- **Негативный контроль** (копия кейса с `append_system_prompt` о плохом
  поведении) не делался: роль контроля частично играет базовое плечо, где
  главные грейдеры падают по ожидаемым причинам.
- **Bash в eval закрыт**, поэтому `git rev-parse` и коммит не проверены;
  в скилле есть запасной вариант «текущий каталог».
- **Процедура ревью не прогонялась** на практике: это текст и промпт для
  главной сессии. Первое реальное ревью на 5 засеянных наблюдениях покажет,
  хватает ли формата.
- `siblings_checked` в eval не проверяется по смыслу, только наличие поля.
- Временные каталоги eval `/tmp/claude-eval-*` (из прогона 1 с `--keep-temp`)
  удалить не удалось: команду очистки отклонил классификатор прав. Удалить
  вручную: `chmod -R u+rwX /tmp/claude-eval-* && rm -rf /tmp/claude-eval-*`
  (контейнер эфемерный, некритично).
